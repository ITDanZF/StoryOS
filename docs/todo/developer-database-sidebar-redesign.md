# 开发者页面：数据库侧边栏重新设计

- 日期：2026-09-07
- 状态：设计已确认，树形侧栏已实现并通过交互验证。
- 本文替代原设计中数据库下拉选择器及单库表列表的导航方案。

## 1. 设计目标

**所有已发现的数据库统一显示在左侧边栏，每个数据库下面展示它的数据表。用户直接点击任意数据库下的表，即可查看和操作数据。**

取消“先打开下拉框选数据库，再查看这个库的表”的两步导航。全局库、项目库、书籍库、检查点库都在同一棵树中呈现。

“全部显示”指所有数据库节点都进入同一侧栏列表，不通过选择器切换可见数据库；数量较多时在侧栏内纵向滚动。首次进入默认展开所有数据库，用户可以独立收起其中的表列表。

本次调整导航组织与布局，沿用已经实现的动态 CRUD、结构检查、编辑会话和备份机制。

## 3. 左侧树的组织方式

### 两层结构

| 层级 | 内容 | 呈现方式 |
| --- | --- | --- |
| 数据库 | 接口返回的全部数据库，包括检查点库 | 同级根节点：展开箭头、数据库图标、名称、表数量或加载状态 |
| 数据表 | 该数据库中的普通表、视图及已支持浏览的虚拟表 | 缩进子节点：对象图标、真实表名、当前选中样式 |

不再添加“项目”“书籍”等需要先展开才能找到数据库的外层分类。项目数据库与其检查点库保持相邻，但都是直接可见的根节点。

沿用数据库发现接口的顺序。节点身份使用数据库 ID，同名数据库不会合并；同名表也不会跨数据库合并。

### 名称显示

- 数据库名称使用 `DatabaseInfo.name`，实际路径使用 `DatabaseInfo.path`，不从显示名称推断业务归属或解析数据库类型。
- 数据库名称最多显示两行；超出部分省略，悬停或键盘聚焦时可查看完整名称和路径。
- 表名使用真实名称、等宽字体、单行展示。超长名称省略，完整名称通过提示及主区域标题查看。
- 同名数据库在节点下方补充路径说明，区分具体文件。主区域始终显示完整数据库路径，可选中复制。
- 书籍库继续使用当前接口提供的名称；本次不增加读取业务表获取书名的依赖。
- 数量指表或视图数量，不查询记录总数；尚未加载时不显示误导性的 `0`。

### 默认展开

首次进入时，所有数据库节点立即出现，默认展开并分别加载其表列表。数据库列表不会等到所有表加载完成才显示。

数据库可独立展开或收起，展开一个库不会自动关闭其他库。收起当前表所在数据库时，主区域保留当前数据，父节点继续显示“当前”标记。

## 4. 尺寸与视觉规范

| 项目 | 规则 |
| --- | --- |
| 侧栏默认宽度 | 300 px，比现有单库列表更适合数据库长名称 |
| 宽度调整 | 宽窗口支持拖动分隔线，范围 240–420 px，同时为主区域至少保留 320 px |
| 窄窗口 | 窗口不足 600 px 时侧栏固定 180 px，不替换成下拉框或隐藏抽屉；中间宽度使用 240 px |
| 侧栏滚动 | 标题、搜索框、底部状态固定；数据库树单独纵向滚动 |
| 主区域滚动 | 数据表和结构内容自行滚动，不撑宽整个页面 |
| 数据库节点 | 最小 40 px；名称换行时自然增高，字体略重于表节点 |
| 表节点 | 最小 32 px；相比父节点缩进 20 px |
| 当前表 | 浅底色、左侧短色条、加深表名；只有一个当前表 |
| 当前数据库 | 名称强调及小型“当前”标记，与表选中样式区分 |
| 图标与颜色 | 复用 Lucide 和现有中性色主题，加载、错误状态使用文字与图标共同表达 |

分隔线可通过键盘调整宽度。树使用规范的 tree/treeitem 语义，支持上下键移动、左右键展开收起、Enter 选择表，焦点样式可见。

## 5. 点击与跨库切换

| 操作 | 行为 |
| --- | --- |
| 点击数据库行或展开箭头 | 展开或收起该库的表；不清空右侧当前内容 |
| 点击任意库下的数据表 | 一次操作选中对应数据库和表，加载结构与第一页数据 |
| 点击当前已选中的表 | 保持当前分页、筛选和排序，不额外刷新 |
| 切换到另一个库的同名表 | 视为不同表，重新加载，不复用原库数据 |
| 记录编辑器打开时切换 | 沿用编辑器关闭及未保存草稿确认规则，不在后台切换数据目标 |
| 正在保存或切换编辑会话 | 禁止发起表选择等冲突操作；允许无副作用的树滚动 |

前端当前选择统一为 `{ databaseId, tableName }`。请求直接携带这两个值，不依赖“先更新数据库状态，再从旧状态读取数据库”的调用顺序。

开始切换表时清除上一张表的行内容并展示加载状态，避免新标题配上旧库数据。使用请求序号识别当前选择，较早请求的晚到结果不得覆盖新选择。

选中表后主区域显示所属数据库、真实表名和文件路径。切换表会重置到第一页，并清空原表的筛选及排序。

## 6. 搜索

侧栏使用一个搜索框：**搜索数据库或表名**。搜索范围覆盖所有已发现数据库，不限于当前库。

- 不区分大小写，按字面包含匹配数据库名称和表名。
- 命中数据库名称：展示这个数据库及其全部表。
- 仅命中表名：展示命中表，同时保留其数据库父节点。
- 搜索结果自动展开对应数据库；清空搜索后恢复搜索前的展开状态。
- 搜索不会切换或清空右侧当前表，即使当前表不在搜索结果中。
- 尚有元数据请求未完成时，显示“仍在加载部分数据库”，不能提前宣称完整范围内无结果。
- 某库读取失败时保留该库的错误节点，明确说明此库未参与完整表名匹配；其余结果可用。
- 完成加载且没有匹配项时显示“没有匹配的数据库或表”，并提供清除搜索操作。

搜索只读取名称与表元数据，不扫描记录内容。

## 7. 加载、刷新及错误处理

### 加载组织

数据库列表由 `listDatabases` 获取，各库表列表由 `listTables(databaseId)` 获取。

前端按库维护独立状态：未加载、加载中、已加载、失败。首次加载使用最多 4 个并发请求，避免大量数据库同时打开连接；每个库完成后立即显示，不等其他库。

只为当前选中表调用 `describeTable`、`queryRows`。展开整棵树不会读取每张表的数据、完整结构或记录总数。

### 刷新结构

点击现有“刷新结构”后：

1. 重新获取数据库列表，以接口返回的 ID 集合为准更新树。
2. 重新获取各库表列表，并保留仍存在节点的展开状态；新发现数据库默认展开。
3. 当前表仍存在时，重新加载结构和第一页数据，清空旧筛选及排序。
4. 当前库或表消失时清空当前选择，明确提示重新选择，不自动跳到其他库的同名表。
5. 尽量保留树的滚动位置，不强制将用户带回顶部。

有未保存草稿时，必须先处理草稿再执行刷新；已有结构版本检查继续生效。

### 状态反馈

| 情况 | 侧栏反馈 |
| --- | --- |
| 尚未发现数据库 | “没有发现本地数据库”，提供刷新 |
| 某库正在加载 | 保留数据库名称，子区域显示加载状态 |
| 某库没有表 | 子区域显示“暂无数据表” |
| 某库打开失败或文件失效 | 子区域显示错误及“重试”；其他数据库照常显示 |
| 搜索没有结果 | 独立搜索空态，不显示为“没有数据库” |
| 当前表读取失败 | 当前表保持选中，主区域显示错误，不显示旧表内容 |

重试由用户点击发起，不静默重复请求。库加载失败不能降级为成功返回空表列表。

数据库与表的基础信息沿用现有共享契约。此次不需要更改 SQL CRUD 引擎、数据库迁移、业务表结构、备份策略或编辑权限。

树的缓存只保存当前页面会话内的元数据和界面状态，不另建持久化数据库。后续新增数据库和表仍从元数据自动呈现，不维护业务表名名单。

## 9. 验收标准

1. 页面中不再出现数据库选择下拉框；全部数据库根节点在左侧同一滚动列表中。
2. 首次进入各数据库默认展开，显示各自表列表；可同时展开多个库。
3. 从任意库下直接点击表，即可进入对应数据；右侧明确显示所属数据库及路径。
4. 两个库包含同名表时，切换、查询、修改和删除始终作用于选定数据库。
5. 某个数据库加载失败，不阻塞其他库浏览，也不被误显示为空库。
6. 搜索可找到其他数据库中的表，并保留所属数据库信息；部分加载或失败状态明确可见。
7. 数据库或表动态新增、删除、重命名后，刷新正确同步树与当前选择。
8. 快速连续选择不同表时，最后一次选择生效，不出现跨库数据串用。
9. 当前库收起或搜索隐藏当前表时，右侧内容保留且归属清晰。
10. 窄窗口下仍使用左侧树，长名称和宽表格不会撑出页面；按钮文字不竖排挤压。
11. 未保存编辑、业务访问暂停、备份和恢复流程继续有效。
