# StoryOS 设置面板改版设计

状态：已确认，已按本方案实施。  
日期：2026-09-07

后续更新：模型配置已支持免重启切换，新任务立即使用新配置，运行中任务保持原配置。下文涉及模型重启的内容为首期设计记录，现以[模型免重启切换设计](./model-hot-switch-design.md)为准；工作区路径仍需重启生效。

## 1. 需求与范围

本次调整围绕已有设置页展开：

- 设置页占满应用标题栏下方的全部可用区域，隐藏工作区左侧栏。
- 重整设置页的信息层级、表单、状态反馈和保存操作。
- 允许用户修改模型服务商、模型名称、接口地址和 API Key。
- 展示 StoryOS 应用版本号。已确认这里指应用版本，不是小说项目版本；版本号只读。

截图用于说明改版前页面。本文记录已确认的布局、交互和生效方式。

## 2. 当前问题

- 设置页仍嵌套在工作区侧边栏旁，且带有外层边距和圆角，独立设置页面的感觉不明显。
- 已初始化后只显示模型状态卡，用户无法再次编辑配置。
- 前端提交逻辑和后端 `configure()` 都阻止修改已有模型连接，仅调整界面不足以解决问题。
- 设置页缺少应用版本；现有关于页的版本号直接写为 `1.0.0`。
- 当前状态能够表示“已初始化”，不能证明远程模型接口实际连接成功，需要准确区分这些状态。

## 4. 模型设置

### 字段与编辑规则

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 模型服务 | 下拉选择 | 首期沿用现有 DeepSeek、OpenAI、通义千问三种服务商 |
| 模型名称 | 文本输入 | 必填，允许输入服务商支持的具体模型 ID，不限制为固定列表 |
| 接口地址 | URL 输入 | 必填，接受 HTTP/HTTPS 地址，支持修改为兼容接口地址 |
| API Key | 密码输入 | 初次配置必填；相同服务商、相同地址下可留空复用已保存密钥 |
| 工作区路径 | 高级设置中的文本输入 | 沿用已有可选字段；默认折叠，说明用于工作区路径设置 |

切换服务商时填入该服务商的默认模型名称与接口地址，清空新输入的密钥。更换服务商或接口地址后必须提供密钥，避免将其他连接的密钥沿用到新地址。默认值仅为填写起点，不表示账户一定具有对应模型权限。

服务商、模型名称、地址和工作区路径从已保存配置回填。已保存的 API Key 不回传前端，不使用真实密钥或假星号作为表单值；输入框用占位文案提示保留规则。

本方案按现有架构维护一套应用级模型连接，允许更换服务商和模型。多套配置命名保存、同时为不同任务分配模型，属于后续扩展，不在首期方案中。

### 保存与撤销

- 未修改时，保存与撤销按钮禁用；表单有变化后启用。
- “撤销修改”恢复最近一次保存的字段，并清空新输入的密钥。
- 保存前执行必填与 URL 校验，错误显示在对应字段下方。
- 保存中禁用表单及重复提交，按钮显示“正在保存…”。
- 保存成功后保留在设置页，清空新输入密钥，显示结果提示。
- 写入失败时保留用户输入，展示可读错误，并允许重试。
- 返回工作区时，若有未保存内容，提示用户选择继续编辑或放弃修改。
- 返回时优先回到进入设置前的工作区页面；直接访问设置时返回对话首页。

### 配置生效方式

建议首期采用“保存后，下次启动生效”，沿用现有运行时生命周期，避免设置保存中途切换正在执行的任务。

| 状态 | 页面表现 |
| --- | --- |
| 首次进入，未配置 | 展示完整表单；保存按钮为“保存并开始使用” |
| 已初始化，无修改 | 展示当前配置；状态为“已配置” |
| 有未保存编辑 | 显示“未保存”，启用保存及撤销 |
| 已保存，与当前运行配置不同 | 显示“待重启生效”；说明当前会话继续使用原配置 |
| 重启后读取新配置 | 恢复“已配置”状态 |
| 保存失败 | 保留输入并显示错误，不显示成功状态 |

首次配置成功并完成本地服务初始化后，可以返回工作区。首次配置尚未完成时继续保留现有返回限制，并明确解释原因。

待重启状态应由后端对比“当前运行配置”和“已保存配置”得出；重新打开设置后仍能看到。保存回当前运行配置时，应清除待重启标记。判断需覆盖模型名称、地址、密钥、服务商和工作区路径。

本期不自动重启应用。保存后使用文案：“配置已保存，退出并重新打开 StoryOS 后生效。”

“已配置”仅表示配置已保存且本地服务完成初始化。未执行真实接口请求时，不显示“连接成功”。本期不增加远程连接测试按钮。

## 5. 应用信息

- 展示 StoryOS 名称、简短说明和只读版本号。
- 版本号来自项目统一版本信息，避免在设置页单独写死。

## 6. 实现边界与文件影响

以下为本次实施涉及的主要文件。

| 位置 | 预计调整 |
| --- | --- |
| `src/renderer/layouts/workspace/WorkspaceLayout.tsx` | 设置路由隐藏工作区侧栏，保存返回目标 |
| `src/renderer/pages/settings/SettingsPage.tsx` | 全页外壳、页头、模型区域与应用信息区域 |
| `src/renderer/pages/settings/components/ConfigurationDialog.tsx` | 复用或提取配置表单，开放已有配置编辑与反馈 |
| `src/renderer/features/agent/hooks/useAgentWorkspace.ts` | 更新配置状态，避免保存设置时无谓重载会话 |
| `src/main/agent/StoryAgentService.ts` | 接受配置修改，处理密钥保留，返回待重启状态 |
| `src/main/agent/config/index.ts` | 分离配置持久化与运行环境更新，保证待重启配置不会提前影响当前任务 |
| `src/renderer/features/agent/api/previewAgentApi.ts` | 同步预览模式的保存和状态反馈 |
| 应用版本公共模块、关于页 | 提供统一版本来源 |

沿用现有配置文件及 IPC 链路，不新增数据库或组件库。表单按独立职责拆分即可，避免为少量字段引入复杂的设置框架。

保存中的错误或并发调用不能破坏已有配置；读取设置状态不能将尚待重启的配置写入当前进程环境。密钥始终只在主进程保存和复用。

## 7. 验收标准

- 打开设置后，桌面端和窄屏均不显示工作区侧栏，页面没有残留侧栏占位。
- 页头保持可见，内容可纵向滚动；桌面与窄屏均无横向溢出。
- 已完成初始化的用户可以修改和保存模型连接。
- 必填、非法 URL、密钥保留与更换地址后的密钥要求均有效。
- 保存成功、保存失败、未保存编辑、撤销、待重启状态均有准确反馈。
- 修改配置不会打断当前运行任务；重启后真实读取新配置。
- 已保存的密钥不会通过状态接口回传到前端。
- 版本与项目版本一致，设置页和关于页展示一致。
- 验证首次配置、已有配置修改、返回工作区和刷新设置页流程。
