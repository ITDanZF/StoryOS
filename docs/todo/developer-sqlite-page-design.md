# StoryOS 开发者页面：动态 SQLite CRUD 设计

- 日期：2026-09-07
- 工作区：`E:\workspace\StoryOS`
- 状态：通用 CRUD 与左侧数据库树均已实现，并完成针对性验证。
- 已确认流程：先审设计，再实现。

## 1. 已确认的核心需求

开发者页面直接管理已有 SQLite 数据表中的记录，支持查询、新增、修改、删除。

**页面由数据库元数据驱动。新增数据表、增加或删除字段、修改字段类型、调整主键后，刷新即可重新生成表格和编辑器，不需要继续修改开发者页面。**

取消上一版按 StoryOS 业务表逐个适配的方案：不为 `threads`、`chapters` 等表编写专用表单，不维护按业务表名划分的可写名单，也不为每张新表增加接口。

工具面向开发阶段的数据调试，直接处理数据库记录。

## 2. 自动适配范围

| 数据库变化 | 自动适配行为 |
| --- | --- |
| 新增普通数据表 | 刷新后出现在表列表，可查询和执行支持的记录操作 |
| 删除或重命名数据表 | 重新读取表列表；旧选择失效时明确提示 |
| 新增、删除、重命名字段 | 表格列和表单字段自动更新 |
| 修改类型、默认值、非空约束 | 重新生成字段说明、初始填写方式和基础校验 |
| 调整单列或复合主键 | 重新计算记录定位方式 |
| 增加外键、索引或触发器 | 结构页自动展示；实际写入遵循 SQLite 约束与触发器 |
| 增加生成列 | 展示计算结果，自动识别为不可直接写入 |
| SQLite 支持的新结构特性 | 未覆盖能力明确显示为不支持，不猜测如何写入 |

“不随业务表变化改代码”适用于已支持的 SQLite 结构能力，不承诺任意数据库对象都能写入。视图、虚拟表、SQLite 内部表，以及无法可靠定位单条记录的表，应显示明确能力限制。这些判断同样来自数据库结构，不依赖业务表名。

- 从设置页进入，独立全页显示，隐藏创作工作区侧栏。

- 主区域展示分页表格和结构信息，表格内部横向滚动。
- 新增、编辑使用同一套动态记录编辑器；窄屏时编辑器占满内容区域。

- 沿用现有 Tailwind 主题、Lucide 图标和表单风格。

## 4. 元数据读取

主进程读取 SQLite schema、表字段、主键、外键和索引信息，统一转换为页面使用的结构。

元数据至少包含：

- 数据库及表标识、对象类别、结构版本。
- 列名、声明类型、类型亲和性、非空、默认表达式。
- 主键列及其顺序、生成列和隐藏列信息。
- 是否为 WITHOUT ROWID 表、是否为 STRICT 表。
- 外键、索引、触发器的结构说明。
- 此表及各字段的可查询、可插入、可更新、可删除能力与限制原因。

表名和字段名必须来自当前数据库元数据。读取不存在的表或字段时返回结构变化错误，不能把错误显示成空表。

浏览现有数据库不触发迁移，不自动创建缺失文件。

## 5. 通用数据读写

### 查询

- 分页查询，默认每页 50 条，可选择 20、50、100 条。
- 支持按字段排序及结构化条件：等于、不等于、包含、大于、小于、为空、不为空。
- 表格中的 NULL、空字符串、数字零、BLOB 分别展示。
- 长文本可展开查看，不一次性加载全部记录或大型二进制内容。
- 有可靠记录标识时使用稳定排序；无可靠标识的只读表不承诺并发变更中的稳定分页。

### 新增

- 自动根据可插入列生成字段。
- 每个字段区分“填写值”“设为 NULL”“使用数据库默认值”三种状态。
- 使用默认值时从 INSERT 列表中省略该列，让 SQLite 执行默认表达式；不在前端解析或模拟表达式。
- 可自动生成的整数主键允许不填写；其他主键按数据库结构填写。
- 生成列及隐藏内部列不出现在可写列集合中。

### 编辑

- 从当前记录值生成表单，保留原始 SQLite 值类型。
- 只提交变更字段；字段改成 NULL 与不修改字段必须明确区分。
- 主键字段如允许更新，定位仍使用编辑前的记录标识，成功后重新获取新标识。
- 提交时验证结构仍有效，并检测记录自打开后是否发生变化；冲突时保留草稿并要求重新加载。

### 删除

- 首期支持单条删除，确认框显示数据库、表和记录标识。
- 删除依据可靠行标识执行，不按当前页行号或单元格展示文字删除。
- SQLite 的外键级联与触发器正常生效。确认框说明此类关联影响，不能把“直接删除一行”描述为“总共只影响一行”。
- 主进程在事务中校验直接命中的目标记录；数量不符则回滚。

### 记录定位

优先使用能够唯一定位的主键，支持复合主键。普通 rowid 表在没有可用主键时，可使用未被用户字段遮蔽的 SQLite 行标识。

必须正确处理 SQLite 普通表中允许 NULL 的主键声明、WITHOUT ROWID 表，以及用户字段与 `rowid` 别名重名的情况。不能仅看到 PRIMARY KEY 就假定所有记录都能唯一定位。

没有可靠单行定位方式时，禁止更新和删除，并展示原因；查询仍可使用。

## 6. 类型与字段控件

| 值类型或结构特征 | 通用呈现方式 |
| --- | --- |
| TEXT | 文本输入；长文本使用多行编辑器 |
| INTEGER | 整数输入；超出 JavaScript 安全范围时用带类型的十进制字符串传输 |
| REAL | 数值输入，拒绝无法表示为有效 SQLite 数值的输入 |
| NULL | 显式空值选项，受 NOT NULL 约束限制 |
| BLOB | 展示长度，按需查看；通过文件导入或十六进制输入替换 |
| 生成列 | 只读展示，由 SQLite 计算 |
| 默认表达式 | 展示原始表达式，新增时可选择让 SQLite 计算 |

SQLite 普通表的声明类型不是严格类型保证。查询必须返回实际存储类型；遇到历史数据类型与列亲和性不一致时，不静默转换或丢失内容。

不根据列名猜测字段业务意义，不把任意 TEXT 当 JSON，也不按 `status` 等名字硬编码下拉选项。CHECK、UNIQUE、外键和触发器等约束交由 SQLite 最终校验，失败时返回明确原因。

## 7. 表结构变化时的处理

1. 打开数据库、切换表或点击“刷新结构”时，重新读取元数据。
2. 查询和编辑请求携带结构版本；主进程在执行时核对。
3. 结构已变化时拒绝旧请求，提示刷新，不把旧表单强行映射到新字段。
4. 用户草稿不静默丢弃；刷新前明确说明字段可能已变更。
5. 元数据缓存按数据库结构版本失效，不要求重新编译或重启开发者页面。

表结构变化在这里指外部迁移或其他数据库工具已经完成的变化；本页面本期负责数据 CRUD，不提供建表、删表或 ALTER TABLE 编辑器。

## 8. 通用 CRUD 与业务状态

本工具遵守数据库约束，不理解应用业务。直接修改章节正文不会自动计算业务哈希，修改状态也不会自动执行对应业务流程；这些派生规则如果没有数据库触发器，不由通用页面推断。

因此取消上一版的业务适配器和业务表名单，改为以下统一机制：

- 默认进入浏览状态，打开编辑会话后才允许写入。
- StoryOS 自身数据库进入编辑会话前，完成编辑器保存，并暂停业务侧数据库访问。
- 存在运行中任务、导入导出或未完成写入时，不强制中断，提示等待完成后重试进入。
- 编辑会话期间关闭相关运行时连接并阻止新业务请求，避免缓存覆盖手工修改。
- 退出编辑会话后重新加载应用状态；若修改造成业务层无法加载，应保留明确错误及数据管理入口以便修正。
- 编辑会话前通过 SQLite 备份能力生成一致性备份，不能简单复制 WAL 模式下的主数据库文件。

这些规则针对整个数据库访问生命周期，不需要在新增业务表后继续添加页面逻辑。跨数据库的业务一致性仍由开发者负责，通用 CRUD 不承诺跨库业务事务。

## 9. 数据访问与 IPC

主进程提供统一数据库服务，前端通过有限 IPC 调用。现有 `better-sqlite3` 驱动继续复用。

| 接口提案 | 职责 |
| --- | --- |
| `listDatabases` | 获取已发现的数据库及可用状态 |
| `listTables` | 获取实际表列表 |
| `describeTable` | 返回结构、记录定位方式及操作能力 |
| `queryRows` | 通用分页、排序、筛选 |
| `insertRow` | 根据元数据构造参数化 INSERT |
| `updateRow` | 根据旧行标识及并发校验构造 UPDATE |
| `deleteRow` | 根据可靠行标识删除单条记录 |
| `beginEditSession` / `endEditSession` | 统一协调备份、业务访问暂停和恢复 |

SQL 标识符只能来自已核验元数据，并正确引用；数据值全部参数绑定。页面不传任意 SQL，不使用字符串拼接用户值。

每次写入在事务中执行，保持外键约束。数据库锁定、结构变化、唯一键冲突、外键失败均明确展示，不关闭约束、不自动重试非幂等写入。

## 10. 数据库范围与入口

表级 CRUD 的实现与数据库文件发现分离。

当前优先覆盖已有 StoryOS 全局库、项目库、书籍库和检查点库。新表在已有数据库内自动发现；如果将来增加一种新的数据库存储位置，只需调整数据库发现方式，不需要修改表格、表单或 CRUD 引擎。

本期按设计中的优先范围接入 StoryOS 已有数据库。暂未添加任意 SQLite 文件选择器；如后续增加，也复用统一引擎，不增加按文件名适配的逻辑。

仅在开发构建中开放页面路由和设置入口，主进程也拒绝打包版本的开发者 IPC 请求。

## 12. 验收重点

核心验收不是只让当前几张表能编辑，而是证明对未来结构变化也能适配。

测试在临时 SQLite 数据库中完成：

- 页面启动后新增一张未知表，刷新后立即完成 CRUD。
- 增加、删除、重命名字段，刷新后表格和表单与新结构一致。
- 测试默认表达式、NOT NULL、UNIQUE、CHECK、外键、生成列和触发器。
- 测试单列主键、复合主键、可空主键、rowid、WITHOUT ROWID 及行标识重名。
- 测试 NULL、空字符串、大整数、混合存储类型、长文本和 BLOB 往返无损。
- 表单打开后修改表结构，旧提交被拒绝且不误写其他字段。
- 表单打开后从其他连接修改记录，旧提交识别冲突。
- 测试记录删除的外键级联与触发器影响，不误报实际行为。
- 浏览不产生写入；编辑会话阻止业务并发访问，退出后重新读取数据库。
- 全过程不新增任何按测试表名判断的代码。

方案已修订为通用、元数据驱动的 SQLite CRUD 工具，符合“表变化后不用持续改页面”的目标。

## 14. 通用 CRUD 首版实现与验证记录

本节记录通用 CRUD 的首版实现。后续已完成的树形侧栏及其验证记录另见 [数据库侧边栏重新设计](developer-database-sidebar-redesign.md)。

用户确认继续完成后，已实现上述通用页面与主进程引擎。

- 入口：设置 → 开发者工具 → 打开数据管理，独立 `/developer` 路由，不挂载业务工作区侧栏和数据加载 Hook。
- 实际模块：`src/main/developer/`、`src/shared/developerDatabase.ts`、独立 IPC / preload、`src/renderer/pages/developer/`。
- 统一写入接口 `mutate` 根据 operation 执行新增、更新、删除；无业务表专用判断。
- 数据网格仅加载有界预览；打开记录时读取完整值。单条完整记录编辑上限为 8 MiB，超限明确提示。BLOB 采用十六进制查看和编辑。
- 使用原始存储类型传输数据，64 位整数以十进制字符串传输；覆盖空 BLOB、含 NUL 的文本。
- 结构或记录冲突时保留编辑器及草稿，显示错误；不自动重试写入。刷新结构前需关闭编辑器，未保存修改会确认。
- 暂停通过统一 IPC 业务访问门禁、进行中请求计数与 AI 运行状态检查实现。关闭运行时连接后备份；恢复重新创建运行时并重新加载业务页面。
- 进入设置或开发者页面前等待章节编辑器保存完成，失败时留在原页显示保存错误。
- 每次编辑会话对已发现数据库使用 SQLite backup 创建一致性备份，路径在页面可查看。会话中新发现的数据库须结束并重新开启会话，完成备份后才可写入。
- 注册库读取错误会显示发现警告，同时保留已发现数据库入口供修正；恢复业务失败时页面仍可重新开启编辑会话。

已验证：类型检查、相关文件 ESLint、38 项针对性自动化测试；临时数据目录下的 Electron 真实 IPC 与页面 CRUD、动态结构刷新、未保存草稿保护、业务暂停与恢复、窄窗口布局。测试未操作用户现有项目数据。

本期不包含建表/删表/ALTER TABLE 编辑器、任意 SQL 控制台、任意文件连接器或自动推断业务派生规则。
