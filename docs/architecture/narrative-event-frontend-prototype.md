# 叙事事件前端原型

> v0.1 · 2026-09-23 · 原型设计，不含实现  
> 依据：`docs/architecture/narrative-event-model.md`，以及 STORYWRITER、DOC、GraphStory、CFPG 中已采纳的交互机制。  
> 字段、patch 和检查规则以 `docs/todo/outline-module-design-analysis.md` 第 6、8、10 节为准。本文只规定屏幕、状态和组件边界。

## 1. 原型要完成的事

作者在现有书籍工作区里规划事件，再按当前叶子写章节。原型要让这四件事在界面上可操作：

- 事件树可展开、可排序，叶子能映射到已有章节。
- AI 提案和作者原稿可区分，逐项接受后才写入。
- 伏笔承诺按状态可见，未触发的承诺不出现在写作确认里。
- 按大纲写作前先读取事件图主线。没有结果时让用户决定：先生成事件图，或放弃主线后继续写作。生成后能看到叶子是否被写到。

原型不包含自由画布、多分支版本树、角色社会模拟和自动把承诺标成已兑现。

## 2. 放在哪里

路由保持 `#/projects/:projectId/book`。大纲是这本书工作区里的一种模式，不新开路由，也不放进宽度只有 216–360px 的目录面板。

```text
src/renderer/pages/book/BookWorkspacePage.tsx
  只转交 feature，不增加大纲逻辑

src/renderer/features/book-workspace/
  BookWorkspacePage.tsx          增加模式：manuscript | outline
  components/BookWorkspaceHeader.tsx
                                 书名后增加「正文 / 大纲」切换

src/renderer/features/narrative-outline/
  NarrativeOutlineWorkspace.tsx  三栏编排
  useNarrativeOutline.ts         快照、选中节点、候选、保存
  model/outlineView.ts           树、时间线、筛选的纯派生
  components/OutlineTree.tsx
  components/OutlineTimeline.tsx
  components/NodeInspector.tsx
  components/OutlineCandidateDialog.tsx
  components/ChapterMappingMenu.tsx
  components/PromiseList.tsx
  components/OutlineCheckList.tsx
  components/WritingContextSheet.tsx
```

`pages/` 不引用大纲组件。`components/ui` 与 `components/layout` 不引用本 feature。弹窗用 `AnimatedDialog`，列表出现用 `motion-reveal` / `motion-stagger`。工作区进入动画仍由 `WorkspaceLayout` 负责，大纲模式切换不再包一层 `AnimatedPage`。

正文模式继续使用 `BookCatalogPanel` 和 `ChapterEditorPanel`。切到大纲时这两块卸下，助手栏保持可用。书籍尚未创建时，「大纲」按钮禁用，沿用现有「请先设置书名」。

## 3. 工作区骨架

顶栏在现有项目名和书名之后插入模式切换。当前模式使用 `aria-pressed`。

```text
项目 / 《书名》 / [正文] [大纲]          目录  助手
```

大纲模式，宽度不小于 1280px：

```text
┌────────────┬──────────────────────────────┬──────────────┐
│ 事件树      │ 时间线或结构卡片               │ 节点详情      │
│            │ [结构|时间线] [检查] [AI]      │              │
│ 全书        │                              │ 摘要          │
│ ├ 故事弧    │  01 激励 → 02 上升 → 03 高潮   │ 角色 / 地点   │
│ │ ├ 情节    │  章标签、告警、来源色          │ 目标冲突结果  │
│ │ └ 事件    │                              │ 关系 / 承诺   │
│ └ 未映射    │                              │              │
└────────────┴──────────────────────────────┴──────────────┘
```

宽度规则：

| 宽度 | 布局 |
|---|---|
| ≥ 1280px | 三栏同时显示。左栏 280px，右栏 360px，都可拖拽，宽度记入 `storyos:outline-tree-width` 与 `storyos:outline-inspector-width` |
| 900–1279px | 左树 + 主区。详情用右侧抽屉，打开时不卸载主区选中态 |
| < 900px | 主区单栏。树和详情都是抽屉。顶栏模式切换保留 |

主区工具条固定四项：结构 / 时间线、检查、从简介生成、展开一层。筛选（角色、地点、结构角色、未映射、有告警）放在工具条第二行，默认收起。

## 4. 屏幕

### 4.1 空大纲

还没有大纲时，主区是空状态，不显示假节点。

```text
这本书还没有叙事大纲
目录只记录卷和章。大纲记录事件、因果和承诺。

[手动建立]  [按简介生成]
```

手动建立打开详情抽屉，必填只有大纲标题。前提、主题、核心冲突、高潮、结局可空。保存后出现一个根节点「全书」，其下无子节点。

按简介生成使用 `AnimatedDialog`，阶段依次是 `brief`、`running`、`candidates`、`applying`。`running` 启动 `event-graph` Agent，并显示它调用的大纲工具；这一步不把工具暴露给书籍对话本身。Agent 返回的是候选 patch，不是已经落库的大纲。

`brief` 收集：

- 主题、核心冲突、叙述视角、结局偏好。结局可空。
- 规划方式：顺序，或高潮优先。高潮优先对应 BiT-MCTS 的锚点，只改变候选的生成说明，界面不出现搜索树。
- 期望规模：短篇、中篇、长篇。这只约束候选的故事弧数量，不触发递归展开。

`candidates` 展示 2–3 个顶层方案。每个方案只显示故事弧标题和一句差异，不展示完整事件列表。用户选一个方案，或勾选若干故事弧后合并。合并时重名弧必须改名，不能静默覆盖。

`applying` 显示提交进度。失败时留在 `candidates`，展示主进程返回的错误原文，不清空已选方案。

### 4.2 结构视图

默认视图。按父子关系做缩进卡片，顺序用 `narrativeOrder`。

卡片只显示：

- 顺序号和标题。
- 一行摘要。摘要为空时显示「未写摘要」，不用标题重复填充。
- 结构角色或叙事功能的短标签。
- 章节标签。未映射的叶子显示「未入章」。
- 告警数。
- 状态：草拟、已确认、写作中、待核验、已覆盖、需修订。

卡片上的来源只在候选预览里出现。已提交节点不再保留「AI 色」；来源留在 patch 记录里，日常树上看状态和告警。

交互：

- 单击选中，详情跟随。
- 拖拽改变同级 `narrativeOrder`。拖到另一节点上则改变父级。父级不能是自己的后代。
- 折叠只影响显示，不改变顺序。
- 键盘：上下移动选中，左折叠，右展开，`Enter` 聚焦详情标题。
- 删除先打开确认对话框，列出子节点数、关系数、章节映射数、关联承诺数。确认后节点删除，章节正文保留。

结构角色用固定中文：开端、激励、上升、转折、危机、高潮、下降、结局。自定义角色显示作者填写的名称。

### 4.3 时间线

只排列叶子事件，顺序仍是 `narrativeOrder`。故事弧作为分组标题，不单独占一个事件格。

```text
第一弧
  01 夜袭森林          第 3 章 · 激励 · 已确认
  02 山脊对质          未入章 · 上升 · 草拟 · 1 条告警

第二弧
  03 靴子失踪          第 7 章 · 悬念 · 已铺设承诺
```

筛「未映射」时隐藏已入章叶子。筛某个角色时，只保留该名字出现在参与者里的叶子。时间线不提供第二种排序；故事发生顺序 `storyOrder` 放在详情的高级区，默认与叙述顺序相同。倒叙是把两个数字改成不同值，并允许用户忽略「前置应更早」的告警。

### 4.4 节点详情

详情按折叠组排列。默认打开摘要、本章和目标。其余组收起，避免把卡片变成表单。

| 组 | 内容 | 来源 |
|---|---|---|
| 摘要 | 标题、短摘要、节点种类、状态 | STORYWRITER 事件元组的标题层 |
| 写作约束 | 目标、冲突、结果 | 事件要素 |
| 场面 | 地点文本、时间文本、叙事功能 | DOC 的场景；成书论文的叙事功能 |
| 人物 | 名字、出场角色、事件前状态、事件后变化 | EVOSPARK 的状态代谢，首版是文本 |
| 结构 | 结构角色；高级区里的故事顺序 | BiT-MCTS 的阶段；热奈特的两种顺序 |
| 关系 | 指向其他节点的因果、前置、揭示、伏笔、对照 | 事件图的边，用选择器而不是画布 |
| 承诺 | 以本节点为铺设、触发或兑现的承诺 | CFPG |
| 章节 | 映射到的章节和覆盖状态 | Weaver |

地点首版是文本，不提供地点库。人物首版是名字，不提供角色卡。名字为空不能加入参与者列表。

关系编辑：选择目标节点、关系类型、一句说明。不允许选自己。保存失败时保留表单并显示错误。

状态含义：

| 状态 | 作者看到的含义 |
|---|---|
| 草拟 | 还可大改，写作确认里默认不勾选 |
| 已确认 | 计划采用，可映射、可写入上下文 |
| 写作中 | 已进入某次章节生成的上下文包 |
| 待核验 | 正文已生成，覆盖检查尚未通过 |
| 已覆盖 | 作者确认这一叶子已经写到 |
| 需修订 | 检查或作者判定正文偏离了叶子 |

生成成功不会把节点直接标成已覆盖。

### 4.5 候选预览

展开一层、补充过渡、检查建议，都进同一个候选对话框。这是 GraphStory 的可编辑中间层，用列表代替图。

```text
展开「夜袭森林」 · 只新增一层
基线 revision 14

将新增 3 个事件                         [全部留下] [全部放弃]
┌─────────────────────────────────────────────┐
│ ＋ 雾中设伏          作者可改标题             │
│   目标：活过这一夜                            │
│   [留下] [改一句] [放弃]                      │
├─────────────────────────────────────────────┤
│ ＋ 战友未归                                   │
└─────────────────────────────────────────────┘

不会修改你已有的事件。
[取消]                              [提交留下的项]
```

规则：

- 一次展开只加一层，新增事件默认不超过 8 条。超出时对话框拒绝展示，并要求模型侧重新生成；前端不截断后假装方案完整。
- 已有节点在这次预览里只读。AI 若返回对已有节点的修改，该项单独标成「改动」，默认不勾选。
- 留下、放弃按条操作。提交只发送勾选项。
- 对话框打开期间大纲若被助手改过，提交返回修订冲突。对话框保留勾选，提示刷新后再提交。
- `applying` 阶段按钮进入 `busy`。关闭走 `AnimatedDialog` 的 `close`，不在前端用定时器猜测动画结束。

从简介生成的顶层方案用第 4.1 节的对话框。展开、过渡和检查建议共用本节对话框，标题不同。

### 4.6 映射到章节

在叶子的章节组或时间线卡片上打开菜单。菜单列出当前书的卷和章，数据来自已经载入的书籍工作区快照，不另请求一本目录。

```text
放入章节
  第一卷
    第 3 章 夜袭
    第 4 章 山脊
  [只建映射，不改章节标题]
```

一个叶子只能映射一个章节。若已有映射，菜单显示当前章，并提供「移到其他章」和「解除映射」。解除映射不删除章节。一个章节里的多个叶子用 `sortOrder` 在详情里上下移动，这个顺序只决定本章上下文包里的事件次序，不改写全书 `narrativeOrder`。

未映射叶子和「已确认但没有叶子」的章节出现在检查列表，级别是提示，不是错误。

### 4.7 承诺

主区工具条不单开第四种视图。承诺从详情进入，也可在检查列表里按「承诺」筛选。

一条承诺显示标题、状态、铺设节点、触发节点、兑现节点。状态用作者可点的分段控制：计划、已铺设、可兑现、已兑现、放弃。从「已铺设」到「可兑现」、以及到「已兑现」，都先弹出一句理由。理由写入 notes 的追加记录，不覆盖铺设说明。

AI 可以在候选里建议状态变化，建议行默认不勾选，文案写明「不会自动标成已兑现」。

写作确认里只列出已经是「可兑现」、且触发节点落在当前章或更早章节的承诺。其余承诺显示在折叠组「未纳入本次写作」，并说明原因：仍是计划、尚未触发、已经兑现或已放弃。

### 4.8 检查

检查对话框分「当前弧」和「全书」。先显示确定性结果，语义检查默认关闭，单独按钮触发。

```text
当前弧 · 2 条警告，1 条提示
错误   无
警告   兑现节点「解释靴子」在叙述顺序上早于铺设
       [定位] [忽略]
提示   「山脊对质」尚未放入章节
       [定位]
```

级别沿用大纲设计：错误阻止相关写入，警告和提示可忽略并填写原因。忽略后的条目在同一 `fingerprint` 下不再重复弹出，节点内容变化导致 fingerprint 变化后重新出现。

语义检查的每条结果带「建议」标记，和确定性结果分开，不能显示成结构已损坏。

### 4.9 按大纲写作

入口在章节编辑器工具条，正文模式可用，文案是「按大纲写作」。大纲模式的时间线卡片提供同一入口，点击后切回正文并打开该章。

确认层是编辑器右侧的 `WritingContextSheet`。它先向主进程读取事件图主线，再决定能否启用写作子 Agent。

```text
第 3 章的写作主线
来自事件图 · 大纲 revision 14

将写的叶子
  [x] 01 夜袭森林     已确认
  [ ] 02 山脊对质     草拟，默认不写

只作过渡，不会展开
  下一叶子：山脊对质

人物状态
  老兵 · 事件后：负伤，仍相信战友

纳入的承诺
  无。靴子失踪尚未触发

检索证据
  第 1 章 · 修订 4 · 偏移 120–180
  「战友把地图留在营地。」

主线 1860 / 4000 字
[启用写作 Agent]
```

没有已确认叶子，或这本书还没有事件图时，不直接启用写作，也不自动去生成事件图。确认层换成选择：

```text
这一章还没有事件图主线
事件图 Agent 没有已接受的结果，或你还没有生成事件图。

[先生成事件图]    [仍然写作]
```

「先生成事件图」关闭确认层，委派 `event-graph`，候选按第 4.5 节接受后再回到这里。「仍然写作」才启用 `chapter-writer`，确认层标明「本次没有事件主线」。作者可临时取消某个已有叶子，预算随即重算。证据区若收到索引不存在、不可用或正在重建，整块显示该错误，两个按钮都禁用。空证据显示「没有命中」；只要主线存在，或用户已选择仍然写作，就可以启用。

有主线时启用 `chapter-writer`。编辑器沿用现有章节生成的流式状态。完成后，预览正文按叶子分色标注覆盖情况：写到、疑似合并、未出现、提前写出了下一叶子。作者接受后才保存为新修订。接受后相关叶子变为「待核验」，不变为「已覆盖」。作者在详情里确认后才变为「已覆盖」。用户放弃主线时，没有叶子可标成待核验。

## 5. 组件职责

| 文件 | 职责 |
|---|---|
| `NarrativeOutlineWorkspace` | 读模式、宽度和选中 id，把三栏拼起来。不发 IPC |
| `useNarrativeOutline` | 加载快照、提交 patch、处理修订冲突、持有候选 |
| `outlineView` | 由快照派生树和时间线。筛选是纯函数 |
| `OutlineTree` / `OutlineTimeline` | 展示和拖拽意图，把操作交回 hook |
| `NodeInspector` | 编辑一个节点的本地草稿，失焦或显式保存时提交单节点更新 |
| `OutlineCandidateDialog` | 候选的勾选与提交 |
| `WritingContextSheet` | 先展示事件图主线；没有主线时询问用户，再启用写作或返回事件图 |
| `PromiseList` / `OutlineCheckList` | 承诺与检查的列表 |

拖拽库若需要新增依赖，先复用工作区里已有的列表拖拽。没有现成实现时，原型阶段用上下移动按钮完成排序，不为此引入画布库。

## 6. 前端状态

服务端快照是唯一事实。前端不保存第二份大纲再定时合并。

```text
idle → loading → ready
ready → saving → ready
ready → conflict（预期 revision 不匹配）
ready → candidate（对话框打开，快照仍是 ready）
```

- `loading` 失败时主区显示错误原文和重试，不渲染空大纲按钮，避免把加载失败看成「这本书没有大纲」。
- `conflict` 时详情草稿保留在内存，提示刷新。刷新后用户可再次保存。
- 候选对话框的勾选不写入快照。
- 详情里未保存的字段在切换节点前提示。原型使用浏览器确认框即可，不新做未保存系统。
- 助手与大纲同时改同一本书时，以主进程 revision 为准。

模式本身存在组件状态，刷新后默认回到正文，不写入书籍记录。

## 7. 动效与视觉

- 模式切换只交叉淡化主区，持续时间用 `motion.css` 已有时长。文字面板不做缩放。
- 候选行使用 `motion-stagger`。减少动态效果时列表直接出现。
- 新增候选在预览中使用 `bg-accent` 和前缀「＋」。已有节点保持 `bg-card`。这是预览期的溯源，提交后恢复普通卡片。
- 告警用现有 `destructive` 与 `muted` 语义色区分错误和提示，不新定义一套状态色板。
- 窄窗口下抽屉沿用工作区侧栏的滑入。焦点进入抽屉标题，关闭后回到触发按钮。

## 8. 原型不做

- 无限画布、自动布局、在节点之间拖线。
- 并排比较多条正式剧情分支。
- 把 AI 色永久涂在已提交节点上。
- 在卡片上展示目标、冲突、承诺全文。
- 生成结束后自动把叶子标成已覆盖，或自动把承诺标成已兑现。
- 从正文反向生成一棵新大纲并覆盖当前树。

## 9. 验收场景

1. 无书时不能进入大纲。有书无大纲时只看到手动建立和按简介生成。
2. 顺序规划与高潮优先都能产出可勾选的顶层方案，取消后书库没有节点。
3. 展开一层不会改已有事件；放弃的候选不出现在树里。
4. 叶子映射到第 3 章后，目录里的章节标题不变。解除映射后章节仍在。
5. 删除带承诺的节点前能看见承诺标题。确认删除后章节正文还在。
6. 本章没有事件图时，出现「先生成事件图」和「仍然写作」。前者进入事件图候选，后者才启用写作 Agent，并标明没有主线。有主线时，确认层展示的叶子、人物和承诺来自事件图。
7. 接受正文后节点是待核验。作者确认后才变为已覆盖。
8. 1280px 三栏、1100px 详情改为抽屉、800px 树也改为抽屉，选中节点不丢。
9. 开启减少动态效果后，候选列表和模式切换仍可完成。
