# 叙事事件图前端原型

> v0.2 · 2026-09-23  
> 依据已经落地的大纲契约和 `OutlineDesktopApi`，替换 v0.1。  
> v0.1 把大纲做成书籍工作区里的「正文 / 大纲」模式，并假设了多套方案、单独的「待核验」状态和忽略检查的接口。这些和当前后端不一致，不再沿用。

交互原型在 `prototype/`。正式应用仍不在本文件的实现范围内。

## 1. 放在哪里

事件图是项目里的一项，排在「书籍工作区」上面。它和正文不是同一块工作区里的模式切换。

```text
项目
  myStory
    事件图          ← 本屏
    书籍工作区
```

正式路由与书籍工作区并列：

```text
#/projects/:projectId/book     书籍工作区，保持现状
#/projects/:projectId/events   事件图
```

`pages/` 只把路由转交给 feature。事件图不写进 `BookWorkspacePage`，也不放进目录侧栏。

```text
src/renderer/layouts/workspace/components/ProjectConversationTree.tsx
  项目展开后，先渲染「事件图」，再渲染「书籍工作区」

src/renderer/features/event-graph/
  EventGraphPage.tsx
  useEventGraph.ts
  model/eventGraphView.ts
  components/EventTree.tsx
  components/EventStage.tsx
  components/NodeInspector.tsx
  components/ProposalDialog.tsx
  components/CheckDialog.tsx
  components/ChapterHandoffSheet.tsx
```

书籍尚未创建时，事件图可以打开，但建立、生成和映射都不可用，沿用现有「请先设置书名」。没有大纲时 `getOutlineSnapshot` 返回 `null`，这是空状态，不是错误。

原型里的对应位置：

```text
prototype/index.html
prototype/modules/eventGraph.js
prototype/app.js
prototype/styles.css
```

## 2. 屏幕只调用这些能力

渲染进程走 `OutlineDesktopApi`。书籍对话里的同类请求仍由主 Agent 委派 `event-graph`，不在这个屏幕里再暴露一套工具名。

| 界面动作 | 调用 | 结果 |
|---|---|---|
| 打开事件图 | `getOutlineSnapshot` | 快照，或 `null` |
| 手动建立 | `createOutline` | 修订从 1 开始。标题必填，前提、主题、核心冲突、高潮、结局可空。可选 `rootTitle`，原型固定为「全书」 |
| 修改全书设定 | `updateOutlineProfile` | 带 `expectedRevision` |
| 改一个节点 | `updateOutlineNode` | 内部是单条 `update_node` |
| 生成候选、展开一层 | `proposeOutline` | 只收 `planningMode` 和 `parentNodeId`。返回一份 `draft` patch，或 `repairable` |
| 留下部分候选 | 前端勾选后 `applyOutlinePatch` | 没勾的操作不进入 patch |
| 删除前 | `previewOutlinePatch` | 展示子节点、关系、映射、承诺。确认后才 `applyOutlinePatch` |
| 放入章节 / 解除 | `mapOutlineNodes` / `unmapOutlineNode` | 只映射叶子。已映射到别的章时接口拒绝「叶子重复映射」，界面先解除再放入 |
| 检查 | `runOutlineChecks` | `includeSemantic` 默认 `false`。语义检查单独再请求一次 |
| 本章主线 | `loadEventGraphHandoff` | `ready` / `missing` / `waived` / `too-large` |
| 仍然写作 | `waiveChapterMainline` 或 `startChapterWriting({ decision: "continue" })` | 指令使用放弃主线的固定文本 |
| 先生成事件图 | `startChapterWriting({ decision: "generate-events" })` | 返回候选，不落库。规划方式固定为 `sequential`，父节点为空 |
| 启用写作 | `startChapterWriting` | `mode` 为 `append` 或 `rewrite`。保存章节修订后，叶子变为 `writing` |
| 作者确认写到了 | `updateOutlineNode` 把状态改成 `covered` | 覆盖检查本身不能改状态 |
| 检查覆盖 | `reviewChapterCoverage` | 只追加 `source = "ai"` 的问题 |

请求里不出现 `bookId`。`expectedRevision` 不匹配时展示 `OutlineRevisionConflict` 的原文，草稿留在当前面板。

## 3. 工作区骨架

顶栏面包屑在书名后停在「事件图」，不显示卷和章。助手栏不在这一屏展开；生成、展开和检查是本屏按钮，直接对应事件图子 Agent 的一轮结果，确认后才写入。

宽度不小于 1280px：

```text
┌────────────┬──────────────────────────────┬──────────────┐
│ 事件树      │ 结构或时间线                   │ 节点详情      │
│            │ 主题 / 核心冲突                │              │
│ 全书        │ [结构|时间线] [检查] [生成]    │ 摘要          │
│ ├ 故事弧    │  01 雨夜巷口 → 02 清晨来客     │ 目标冲突结果  │
│ │ └ 事件    │                              │ 关系 / 承诺   │
│ └ 未映射    │                              │ 章节          │
└────────────┴──────────────────────────────┴──────────────┘
```

| 宽度 | 布局 |
|---|---|
| ≥ 1280px | 三栏同时显示。左栏 248px，右栏 320px |
| 900–1279px | 左树 + 主区。详情改为右侧抽屉，打开时不卸载选中 |
| < 900px | 主区单栏。树和详情都是抽屉 |

主区是一幅可平移、可缩放的图。节点是故事弧和叶子事件。边分成五层，可单独开关：层级（包含）、叙述顺序、故事顺序、情节关系（因果、前置、揭示、伏笔、对照）、承诺（铺设—触发—兑现）。概览只画故事弧，事件模式展开叶子。

关系在图上连边，也在详情里修改。两个顺序数字不同的节点标成倒叙；打开故事顺序图层后，和叙述顺序不一致的衔接另画一条边。

## 4. 屏幕

### 4.1 还没有事件图

`getOutlineSnapshot` 为 `null` 时只显示空状态，不放示例节点。

```text
这本书还没有事件图
目录只记录卷和章。事件图记录故事弧、叶子事件、因果关系和承诺。
写作前从这里读取已经确认的主线。

[手动建立]  [按简介生成]
```

手动建立只要求标题，其余设定可空。保存后有一个根节点「全书」：种类 `arc`，状态 `draft`，叙述顺序 1000。这和 `createOutline` 的根节点一致。

按简介生成先选规划方式：`sequential`（顺序）或 `climax-first`（高潮优先）。高潮优先只改变候选的生成说明，界面不出现搜索树。书籍简介已经在书籍资料里，这个对话框不再另收主题、视角或篇幅。

没有大纲时，`proposeOutline` 仍可返回 patch，但 `applyOutlinePatch` 要求大纲已经存在。提交留下的项时，界面先 `createOutline`，再把 patch 的 `outlineId` 和 `expectedRevision` 换成新快照后提交。取消则书库里仍然没有大纲。

### 4.2 结构

原型把这一层画成图：故事弧和叶子是节点，包含关系是边。同级仍按 `narrativeOrder` 从左到右排。字段和下面的卡片信息相同。

卡片显示顺序号、标题、一行摘要、结构角色、章节和告警数。摘要为空时显示「未写摘要」。状态用下面的五个词，不另造「待核验」：

| 状态 | 作者看到的含义 |
|---|---|
| `draft` 草拟 | 还可大改。写作主线不收 |
| `confirmed` 已确认 | 可以映射，也可以进入主线 |
| `writing` 写作中 | 正文修订已经保存，`markNodesPendingVerification` 写成这个状态。还没由作者标成已覆盖 |
| `covered` 已覆盖 | 只有作者更新节点才能变成这样 |
| `needs_revision` 需修订 | 作者或后续判断认为正文偏离了叶子 |

结构角色：开端、激励、上升、转折、危机、高潮、下降、结局、自定义。  
节点种类：故事弧 `arc`、情节点 `beat`、场面 `scene`、事件 `event`。  
叙事功能：动作、对话、说明、世界构建、关系、悬念、过渡、混合。

单击选中，详情跟随。删除先展示 `previewOutlinePatch` 的影响清单。确认后节点、关系和映射删除，承诺上的节点改为空，章节正文保留。

### 4.3 时间线

只排叶子，顺序仍是 `narrativeOrder`。故事弧只作分组标题。

```text
城市之夜
  01 雨夜巷口          第 1 章 · 激励 · 已确认
  02 清晨来客          第 2 章 · 上升 · 已确认

黎明之前
  03 车站回声          未入章 · 危机 · 已确认
```

时间线不提供第二种排序。`storyOrder` 放在详情里，默认与叙述顺序相同。倒叙是把两个数字改成不同值。

### 4.4 节点详情

分组默认展开摘要、写作约束和章节，其余收起。

| 组 | 字段 |
|---|---|
| 摘要 | 标题、摘要、种类、状态 |
| 写作约束 | 目标、冲突、结果 |
| 场面 | 地点、时间、叙事功能 |
| 人物 | 名字、角色、事件前状态、事件后变化。名字为空不能加入 |
| 结构 | 结构角色、故事顺序、叙述顺序 |
| 关系 | 目标节点、类型、一句说明。不能选自己 |
| 承诺 | 以本节点为铺设、触发或兑现的承诺 |
| 章节 | 映射到的章节、覆盖状态、本章主线 |

人物角色：焦点 `focus`、主动 `active`、配角 `supporting`、提及 `mentioned`。  
关系：因果 `causes`、前置 `requires`、揭示 `reveals`、伏笔 `foreshadows`、对照 `contrasts`。  
章节覆盖：计划 `planned`、已起草 `drafted`、已核验 `verified`、已偏离 `deviated`。映射新建时是 `planned`。

只有叶子能放入章节。一个叶子只能映射一个章节。菜单列出当前书已经载入的卷和章，不另请求目录，也不改章节标题。已经映射到别的章时，菜单只提供「解除映射」，并写明要换章必须先解除。同一章里的多个叶子用 `sortOrder` 上下移动，这个顺序不改全书 `narrativeOrder`。

### 4.5 候选

生成候选和展开一层共用一个对话框。后端一次只返回一份 patch，所以这里不是多套方案对比，也没有合并重名弧。

```text
展开「雨夜巷口」 · 只新增一层
基线修订 6

将新增 2 个事件                    [全部留下] [全部放弃]
┌──────────────────────────────────────────┐
│ ☑ ＋ 钟表店的停摆          可改标题        │
│    目标：确认停摆发生在脚步声之前          │
└──────────────────────────────────────────┘

不会修改已有事件。新增子节点后，当前节点不再是叶子。
[取消]                              [提交留下的项]
```

- `parentNodeId` 为空时，候选属于全书下一层。展开一层时，父节点是当前选中节点。
- 新增默认不超过 8 条。超出时对话框拒绝展示，要求重新生成，前端不截断。
- 已有节点的 `update_node` 单独标成「改动」，默认不勾选。
- 提交只发送勾选的操作。
- `repairable` 时列出问题原文，不给提交。
- 打开期间修订变了，提交得到 `OutlineRevisionConflict`，勾选保留。

### 4.6 承诺

一条承诺显示标题、状态、铺设、触发条件、兑现要求，以及铺设、触发、兑现节点。

状态：计划 `planned`、已铺设 `seeded`、可兑现 `eligible`、已兑现 `paid_off`、放弃 `abandoned`。

改成 `eligible` 或 `paid_off` 时必须填写理由。理由写入 `statusReason`。`notes` 仍是单独的备注，不会被理由覆盖。其他状态不要求理由。界面不提供「自动标成已兑现」。

### 4.7 检查

检查对话框先显示确定性结果。语义检查默认关闭，单独按钮才带 `includeSemantic: true` 再请求。

级别和后端规则相同：错误阻止写入，警告和提示随快照返回。文案使用检查函数的原文，例如「已确认叶子未映射」「已铺设承诺没有兑现节点」「地点变化但没有过渡或说明」。

语义结果带「建议」，和确定性结果分开，不能显示成结构已损坏。

当前 IPC 没有把问题标成 `ignored` 的通道。本版只提供「定位」和重新检查。节点内容变化后，旧问题按 `checkedRevision` 显示为已过期。

### 4.8 按事件图写作

写作仍属于某一章，所以确认层从两个地方打开：事件图里已映射叶子的「查看本章主线」，以及书籍工作区章节工具条的「按事件图写作」。后者打开同一张确认层，不把事件图嵌回正文模式。

确认层先 `loadEventGraphHandoff`。

有主线时：

```text
第 1 章的写作主线
来自事件图 · 修订 6

将写的叶子
  [x] 雨夜巷口     已确认

下一叶子只用于过渡，不得展开
人物在更早事件之后的状态
可兑现承诺
检索证据：没有命中，或索引错误原文

主线 320 / 4000 字
写作方式：续写 append · 重写 rewrite
[启用写作]
```

叶子、祖先、相邻事件、本章其他叶子、参与者状态、可兑现承诺和检索证据，对应 `OutlineContextBuilder` 的各节。作者看到分节，也可以展开最终交给 `chapter-writer` 的 `instruction`。

勾选改变的是本次 `selection`。一个都不勾时，界面改走下面的选择，不把空数组交出去：`chosenChapterLeaves` 在 `selection` 为空时会采用全部已确认叶子。

没有主线时不直接写作：

| 交接 | 界面 |
|---|---|
| `missing` / `no-outline` | 这本书还没有事件图。［先生成事件图］［仍然写作］ |
| `missing` / `no-accepted-leaf` | 本章没有已确认且已映射的叶子。同上两个按钮 |
| `too-large` | 硬约束超过 4000 字。两个写作按钮都禁用 |
| 向量索引不存在、不可用或正在重建 | 展示错误原文，写作按钮禁用 |
| `waived` | 使用固定句：「本次没有事件主线。」正文不得声称情节来自事件图 |

「先生成事件图」关闭确认层，打开第 4.5 节的候选。接受之后，作者再回到这一章重新读取主线。「仍然写作」写入放弃记录，大纲修订号变了之后这次放弃失效。

启用写作成功并保存修订后，选中的已确认叶子变为 `writing`。放弃主线时没有叶子可标。`reviewChapterCoverage` 只追加建议，不把节点改成 `covered`。作者在详情里确认后，状态才是 `covered`。

## 5. 原型这次做出的交互

`prototype/` 用本地快照演示上面的屏幕，不调用 IPC，也不假装模型已经运行。

- 《长夜》带有一棵可切换、可检查、可映射的事件图。
- 「星海纪元」和「雾港来信」是空状态，可以手动建立或按简介生成一份候选。
- 候选、检查、删除预览、承诺理由和本章主线都可以打开。
- 「启用写作」停在交接结果，不往章节里写正文，也不提前把叶子改成 `writing`。
- 修订冲突、`too-large` 和向量索引错误只在本节规定正式界面的文案，原型不伪造这些失败。

## 6. 仍然不做

- 多条正式剧情分支、节点版本树，以及把拖动位置写回大纲。
- 把事件图做成书籍工作区里的另一种编辑模式。
- 一次展示多套正式剧情方案。
- 生成结束后自动标成已覆盖，或自动把承诺标成已兑现。
- 忽略检查的按钮。后端还没有这个写入通道。
- 从正文反向生成一棵新图并覆盖当前快照。

## 7. 验收

1. 项目展开后，「事件图」在「书籍工作区」上面。点它进入事件图，点书籍工作区回到正文，两边的选中态不同时亮。
2. 无大纲时只有手动建立和按简介生成。取消生成后仍然没有节点。
3. 顺序和高潮优先都只产出一份可勾选 patch。没勾的项不会出现在树上。
4. 叶子映射到某一章后，目录标题不变。已映射叶子不能直接改到另一章，解除后章节还在。
5. 删除前能看见子节点、关系和承诺。确认后正文还在。
6. 已确认且已映射的叶子能打开主线；草拟叶子或未建事件图时出现「先生成事件图」和「仍然写作」。
7. 检查先给确定性结果。语义结果带「建议」。没有忽略按钮。
8. 把承诺改成可兑现或已兑现时，不写理由就不能保存。
9. 1280px 三栏；更窄时详情和树改为抽屉，选中节点还在。
