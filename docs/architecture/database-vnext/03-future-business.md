# 后续业务边界：不占用本次现有业务重设计主线

> v0.2 · 2026-09-09  
> 本页保存未来接口方向。当前两项主线是现有业务重设计，以及小说 / 专业资料向量库与 Agent RAG。

## 1. 大纲、人物、事实和伏笔

这些模块尚未形成当前可用业务闭环，不在第一部分中提前创建完整表组。它们将来仍属于独立书库，而不是会话或向量库。

| 未来业务 | 建议实体 | 与本次设计的接口 |
|---|---|---|
| 人物、地点、组织、物品 | story_entities、entity_aliases | 稳定身份；确认后作为 novel scope 新来源 |
| 大纲与章节目标 | outline_nodes、chapter_outline_nodes、outline_dependencies | 规划树与稿件目录分开；节点版本映射检索来源 |
| 事件与人物状态 | story_events、story_facts、来源映射 | 区分故事时间与读者知晓顺序；事实具有证据与确认状态 |
| 伏笔埋设与回收 | narrative_promises、原文锚点 | 锚点固定到 chapter revision，目录重排不改变证据身份 |
| 章节和全书摘要 | book_summaries、输入版本清单 | 自动生成结果和作者确认资产分开；来源更新后判断失效 |
| 可长期命名的稿件版本 | manuscript_snapshots、快照章节映射 | 延伸现有短时导出快照；新增 UI 与保留策略后再持久化 |

专业方法论资料不能绕过确认流程直接成为人物设定。RAG 搜到的片段也不能代替叙事资产的权威数据模型。

## 2. 云同步与多人协作

本次保留稳定 ID、不可变修订、版本基线、变更日志、设备来源和明确数据所有权。

| 能力 | 后续需要设计 | 本次字段不能冒充的能力 |
|---|---|---|
| 登录与授权 | 账户、书籍成员、角色和服务端校验 | local_profile_id 和本机绑定不等于云权限 |
| 多端增量同步 | 远端确认、同步操作、墓碑保留和协议版本 | local_sequence 不是跨设备全局版本 |
| 离线冲突解决 | 冲突记录、合并修订、重命名/重排/删除冲突 | updated_at 与 row_version 不能单独决定合并 |
| 实时协作 | 协作操作或 CRDT、会话与快照协议 | 普通 JSON 文档不具备并发文本合并能力 |
| 专业资料共享 | 分享范围、原始资产可用性、成员撤销与版本策略 | 本机资料集绑定不是远端授权 |
| 云端向量托管 | 作用域映射、网络失败、服务认证、同步发布 | 本地向量目录不能直接作为分布式共享写入目录 |

同步应针对业务实体和原始资料资产设计。索引和向量默认按目标设备重建，是否传输派生索引作为加速包另行评估。

## 3. 实施顺序

1. 先以第一部分完成现有业务重设计与回归验证。
2. 然后以第二部分实现专业资料管理、小说向量索引、混合检索和 Agent 上下文追溯。
3. 再按具体产品需求引入本页的新业务实体与云能力。

第一、二部分都属于本次设计范围；这个顺序用于控制实施依赖，不是把已经要求的向量设计再次推迟为可选项。
