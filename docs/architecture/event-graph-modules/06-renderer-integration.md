# 模块 06：单画布前端接入与作者交互

> 本模块接入[模块 01–05](./README.md)的正式接口，不重做当前事件图视觉结构。始终是一张可拖动、从左到右推进的画布，阶段在底部用括号表达，节点详情在右侧 Markdown 面板。总设计见[上级文档](../event-graph-backend-integration-design.md)。

## 1. 当前页面需要改的单章假设

[`EventGraphPage.tsx`](../../../src/renderer/features/event-graph/EventGraphPage.tsx) 目前在顶部用单选 `NativeSelect` 给已确认叶子选一个章节；[`useEventGraphSession.assignChapter`](../../../src/renderer/features/event-graph/useEventGraphSession.ts) 找到该节点现有映射后，会先解绑旧章再绑定新章。其间第二步失败会留下无映射节点。图模型 [`GraphNode.chapterId`](../../../src/renderer/features/event-graph/model/document.ts) 与 `GraphVertex.chapterId` 也只能展示一个章。它们需要改为 `chapterMappings[]` 或根据快照按需查映射；不能只把下拉框改为 `multiple` 而保留旧数据投影。

`ChapterHandoffDialog` 同时被事件图页和书籍工作区调用，适合保留为同一个预览组件，但选择对象从节点 ID 改为映射键；空选择不启动写作。右侧 [`EventGraphMarkdownPanel`](../../../src/renderer/features/event-graph/EventGraphMarkdownPanel.tsx) 的结构段落与自由笔记目前还不是完整原子往返，接 AI 字段规划和正文证据前要确认保存一项不会吞掉其它字段/关系。

## 2. 页面信息架构

| 位置 | 持续显示 | 选中/操作时显示 |
|---|---|---|
| 顶部 | 书名、图修订、全书设定入口；“从已有正文补图”“AI 规划” | 当前节点/阶段的快捷规划或生成入口 |
| 中央画布 | 节点卡、显式语义边、从左到右的讲述推进 | 高亮所选节点、直接边和相关章节；卡片不显示长篇字段 |
| 底部阶段括号 | 阶段名称与跨度 | 点击打开同一右侧面板的阶段摘要，以及“生成本阶段正文” |
| 右侧 Markdown | 节点/阶段详情，作者笔记 | 节点全局意图、关系、跨章片段、证据、AI 完善字段、生成单节点正文 |
| 临时对话框/抽屉 | 不常驻占画布 | 候选审阅、映射编辑、生成计划预览和进度 |

全书/章节聚焦只调整这张图的关注范围，不开第二张图或独立流程视图。页面默认操作不要求作者先选“顺序规划/高潮优先”、填多字段表单；范围来自选中对象，补充要求最多一段可选文本。

## 3. 六条交互流程

### 3.1 已有正文补图

入口展示“已有 N 章正文、其中 M 章尚未充分关联事件”，点击后可缩小到卷/章节。扫描中逐章显示状态；结果按章节分组，每个候选有“新建 / 补充已有 / 只补章节片段 / 待判断”标签及正文证据链接。作者可取消、编辑、接受所选项。接受前展示图 patch 和映射差异；版本变化在原面板提示重新对齐，保留选择。无候选时展示“已扫描哪些修订”，不说“整本书没有事件”。

### 3.2 AI 规划

空选中时规划全书，选中阶段时规划阶段，选中节点时规划该节点，选中边/两节点时规划关系，点字段旁按钮时只规划该字段。都使用同一个候选审阅组件。候选卡明确显示旧值→新值、哪条边的方向变化、是否影响跨章片段。模型输出越界时展示可修复问题，不在画布上偷偷只用一部分候选。

### 3.3 跨章映射

选中可写节点，右侧显示多条章节映射，每条有章节名、当前局部目标、期望变化、覆盖状态和证据入口；支持新增一章、编辑片段、调整章内顺序、只移除某一章。新增默认先显示章节列表与可写的局部描述建议，作者确认后提交；绝不先解绑已有章。节点跨章时卡片可只显示“关联 3 章”，完整清单留在右侧，避免卡片膨胀。

### 3.4 写作交接

从书籍工作区或图中选章都打开同一 `ChapterHandoffDialog`。列表显示“本章片段”，不是节点的全局最终结果。作者明确勾选映射；取消全部后禁用开始写作并提示“请选择本次事件”。版本或指令变动时要求重新预览；无主线放弃入口保持明确，但图上直接生成不走放弃分支。

### 3.5 单节点与阶段正文生成

节点按钮进入所映射章节清单；阶段括号按钮进入阶段后代展开后的章节清单。预览逐章显示节点、片段、`append/rewrite`、已有正文、预计调用次数、跳过的草稿或未映射节点。开始后保持画布和右侧详情可浏览，进度按章展示；可以取消尚未完成步骤。完成后直接打开对应书籍工作区章节。部分成功时分开标明“已保存”“失败”“未开始”，重试前重新预览剩余步骤，不提供会重复续写已保存章的按钮。

### 3.6 写后核对

书籍工作区编辑正文后，图右侧对应映射显示“证据来自旧修订/待复核”。核对建议可定位到证据段，作者选择确认覆盖、修改图的候选、回正文修正或保留有意偏离。一个节点多个映射时先显示每章状态，再给节点整体状态；不能因一章完成把卡片直接改成“已覆盖”。

## 4. 状态、错误与可访问性

- `useEventGraphSession` 继续管理当前书的正式快照和候选；扫描/生成任务可拆独立 hook，但必须按 `projectId` 隔离并在切书时取消订阅，防止上一书异步结果写进当前页面。
- 页面刷新后，从后端取正在运行或已部分完成的任务；进度条仅表示任务状态，不当作正文已保存依据。
- IPC 错误按“模型不可用、候选需修复、版本冲突、章节缺失、超预算、生成部分成功、保存冲突”给出可操作文本，不能一律显示通用失败。
- 按钮/对话框复用 `src/renderer/components/ui` 和 `components/motion`，保持键盘焦点、Esc 关闭、忙碌态与 `prefers-reduced-motion`。阶段括号和边都应有可点击的语义控件与焦点样式。
- 静态 JSON 示例入口明确标演示；正式页面不能把演示节点、章节或候选提交到当前书。

## 5. 预计改动与验收

| 步骤 | 预计文件 | 可验证结果 |
|---|---|---|
| U1. 多章投影 | `model/document.ts`、`buildEventGraph.ts`、`EventGraphPage.tsx` | 同一节点关联两章后重开仍显示两章；章筛选正确 |
| U2. 映射编辑器 | `useEventGraphSession.ts`、右侧 Markdown 面板、映射弹窗 | 编辑某章片段不删除另一章；提交失败不丢原映射 |
| U3. 规划与补图候选 | `EventGraphAgent.tsx`、`EventGraphProposal.tsx`、新候选列表 | 五种范围正确传递；证据和差异可读；拒绝不改图 |
| U4. 同一交接组件 | `ChapterHandoffDialog.tsx`、`ChapterMainlineBar.tsx` | 两入口展示同一映射片段；清空选择不可生成 |
| U5. 图上生成计划 | 节点/阶段操作区、计划预览与进度组件 | 单节点跨章、阶段多节点按章显示；部分成功能定位已保存正文 |
| U6. 写后核对 | `chapterMainline.ts`、详情面板、工作区入口 | 正文修订变化时仅对应章证据过期；整体状态正确 |

组件可按功能拆，但不引入新的全局 store 或多视图框架。视觉样式沿用当前主题与单画布设计；窄窗时右侧面板可改为抽屉，事件图仍是同一张。
