# 事件图后端联动：逐步执行清单

> 2026-10-16。本文把[模块设计](./README.md)拆成可以依次开发、检查和交付的步骤。仅使用新建测试书库；旧测试数据可按已确认路径清理后重建，不实施数据迁移。每一步的“完成”以代码与验证结果为准，不以文档勾选为准。

## 0. 先固定执行边界

| 检查 | 动作 | 产物 |
|---|---|---|
| 工作树 | 记录 `git status --short`；逐块查看目标文件现有 diff | 明确保留的未提交代码 |
| 实现入口 | 找到 `OutlineApplication`、`SqliteOutlineStore`、`ChapterGenerationService`、`OutlineIpcController`、事件图会话与工作区主线条 | 复用路径清单 |
| 测试数据 | 只在实际需要重建书库时定位并核对 StoryOS 测试库绝对路径 | 确认后清理；开发测试优先使用临时数据库 |
| 契约 | 确定 `(nodeId, chapterId)` 为映射键；章节片段为必填写作边界 | shared/IPC/SQL 字段表 |

## 1. 数据与跨章映射（模块 01）

1. 在 `outlineContracts.ts` 增加章节局部片段字段，改 map/unmap 请求键；同步 `desktopApi.ts`、`channels.ts`、`OutlineIpcController.ts`、`DesktopController.ts` 与工具调用点。每个请求由后端验证所属书、叶子状态和图修订。
2. 更新 `outlineSchema.ts` 的新建表定义，去掉 `node_id UNIQUE`，加入片段列及索引；更新 `BookDatabase.ts` 新建库版本配置。更新相关测试从空数据库建书，不写旧库迁移逻辑。
3. 更新 `SqliteOutlineStore` 的映射读写、章内排序；应用层新增、修改、删除**单条 `(nodeId, chapterId)`** 映射，不能先解绑另一章。
4. 调整检查和覆盖规则：同一节点多章合法，单章覆盖只作用于一条映射，节点整体覆盖需所有必需片段有效且最终结果得到证据。
5. 运行存储与应用定向测试、`npm run check:backend`。通过条件：一个节点同时映射两章、重开仍在、删除一条不影响另一条。

## 2. 写作交接（模块 02）

1. 把选中对象改为明确映射键；空选择不可写。`acceptedChapterLeaves` 改为返回本章有效映射与对应节点。
2. 重写 `OutlineContextBuilder`：本章片段为硬约束，节点最终结果是全局方向；前后章节片段和承诺触发按多映射查找。
3. 交接返回目标章修订、行版本、选中映射和摘要。执行前重算并对比；章节或主线叙事内容变化则要求重新预览。
4. 写作成功后只把实际生成的章映射标为待核验；覆盖确认按映射记录和正文证据更新，不因一章完成就把跨章节点整体标已覆盖。
5. 两个入口复用同一交接；运行构造器、应用服务、工作区主线条定向测试。

## 3. 单 Agent 范围规划（模块 03）

1. 固定一条页面到 `event-graph` Skill Agent 的提案路径，避免 Agent 再调用会二次发模型请求的 `proposeOutline` 工具。
2. 定义全书、阶段、节点、关系、字段五种 `PlanningScope`；默认范围来自页面选择，作者仅可选填一句补充要求。
3. 模型返回 `OutlinePatch` 后先做范围校验，再做结构模拟；越界操作整份拒绝。字段规划只接受指定节点的指定字段变更。
4. 更新 Skill 关于叶子、关系、跨章片段与不确定证据的规则；候选先预览后接受。
5. 运行规划、patch、Agent 工具定向测试及 `npm run check:backend`。

## 4. 已有正文反向补图（模块 04）

1. 从书籍存储按卷/章读当前正式修订与纯文本，记录每章 revisionId。长章分段，偏移规则与正文证据定位一致。
2. 用同一个事件图 Agent 提取事件候选并保留证据，再在章内及跨章去重，对齐现有图；输出 `matched/update-suggested/new/uncertain`。
3. 将候选与扫描基线持久化供重开审阅。作者接受前逐项预览节点、关系、映射和证据差异。
4. 在同一图事务中提交 patch、章节映射与证据；章节修订变化或图版本变化则拒绝旧候选。重复接受不能重复创建节点。
5. 运行长章末段、跨章同事件、旧修订、原子失败回滚与重扫幂等测试。

## 5. 图上正文生成（模块 05）

1. 单节点范围展开为所选章节映射；阶段范围展开后按章合并节点，同章只生成一次。预览章节、片段、已有正文与 `append/rewrite`。
2. 持久化计划和步骤状态；每个步骤固定 `stepId`、交接摘要、目标章版本及写作模式。
3. 扩展现有单章生成服务传 `sourceRunId = stepId` 并返回 revisionId；编排服务逐章执行，实时复核交接和目标章版本。
4. 保存成功后只标相应映射待核验；任务中断时通过 sourceRunId 识别已保存修订并补状态，不重复 append。
5. 实现取消、部分成功、剩余步骤重试和同章并发保护；运行单节点跨章、阶段多节点、部分失败与崩溃恢复测试。

## 6. 一张图内接入（模块 06）

1. `GraphNode.chapterId` 单值改为多映射投影；右侧文档展示跨章片段，单选章节控件改成逐条映射管理。
2. 顶部接正文补图与全书规划；节点/关系/字段/阶段在当前位置接局部规划，统一候选预览。
3. 节点和阶段接生成计划预览与进度；结果跳到书籍工作区对应章节。演示 JSON 仍隔离。
4. 书籍工作区主线条同步展示局部片段与覆盖证据；切书、取消、重开时状态不串书。
5. 运行 `npm run lint:frontend`、相关组件/模型测试和必要的 `npm run typecheck`。

## 7. 最终联调（模块 07）

按[联调验收清单](./07-integration-acceptance.md)在新建测试书上分别走“已有正文补图”和“新书阶段生成”两条路径。记录本次运行的命令、结果、书库版本、图修订、章节修订及仍存风险。只有两条链路与异常恢复均实际通过，才把整个目标标为完成。
