# 模块 07：跨模块联调与验收

> 本文把[模块 01–06](./README.md)的验收串成可复现的交付门槛。它是实施时的检查清单，不表示这些测试已经运行。

## 1. 交付顺序与阶段门槛

| 阶段 | 允许进入下一阶段的条件 |
|---|---|
| 数据层 | 清理确认的测试书库后能建立新 schema；同节点两章可持久化；新建书的章节修订与外键完整 |
| 交接层 | 同节点前章/后章有不同局部指令；空选择、缺片段、超预算、版本变化都能拒绝或提示 |
| AI 候选层 | 五种范围后端守卫生效；反向扫描有修订证据；接受候选时图与映射原子写入，拒绝时正式图不变 |
| 正文生成层 | 单节点和阶段范围都逐章保存正式修订；已保存步骤可恢复，不重复 append；部分成功有明确结果 |
| 前端闭环 | 两页面看到同一主线，图上按钮能直接生成并跳到工作区，正文再编辑能触发对应映射待复核 |

## 2. 最小自动化检查矩阵

| 层级 | 关键断言 | 预计测试范围 |
|---|---|---|
| 新书库结构 | 全新库的版本、主键、索引、覆盖字段、章节修订与 `foreign_key_check` 完整 | `SqliteOutlineStore.test.ts`、`BookDatabase` 新库测试 |
| 映射与状态 | 同一节点跨章；仅解绑指定章；删除章节处理证据；单章确认不让节点整体完成 | `OutlineApplication`、`outlineChecks` 测试 |
| 交接 | 片段硬约束、最终结果边界、前后章上下文、承诺不取第一条映射、摘要与版本对比 | `OutlineContextBuilder.test.ts`、`outlineHandoff.test.ts` |
| Agent 提案 | 五种范围允许操作集、模型越界拒绝、临时 ID 解析、旧图版本拒绝、候选不污染正式图 | `outlinePropose.test.ts`、`outlinePatch.test.ts`、Agent 工具测试 |
| 正文反向补图 | 长章末段事件可发现、跨章去重、旧修订证据过期、重复接受幂等、原子提交失败回滚 | 新 backfill 用例与 SQLite 测试 |
| 图上生成 | 单节点跨章、同章多节点只调用一次、阶段排序、取消、部分失败、保存后崩溃恢复、并发编辑冲突 | 新编排测试、`ChapterGenerationService` 测试 |
| Renderer | 多章映射投影、选中对象决定规划范围、清空交接不能写、重开显示任务、切书不串数据 | event-graph/book-workspace 定向组件或模型测试 |

运行命令按改动面选择：主进程/shared 先 `npm run check:backend`；renderer 先 `npm run lint:frontend` 与相关定向测试；跨层或最终集成跑 `npm run check`。涉及 `better-sqlite3` 的 Node 测试遵循项目 `native:node`、Electron 运行遵循 `native:electron`，不手工覆盖原生产物。不要为了文档完成而声称这些检查已通过。

## 3. 桌面端贯通：已有正文的书

在新 schema 下重新创建测试书：至少 2 个卷、7 章；第 3 与第 7 章写有同一身份揭示事件的不同推进片段；第 5 章另有一个独立事件；其中一章创建两个修订，并有一章未保存本地草稿。记录书库版本、图修订、各章当前 revisionId/rowVersion。

1. 打开事件图，发起全书扫描；确认只读当前正式修订，未保存草稿不被当作正式证据，长章末尾事件能被发现。
2. 审阅候选；确认第 3/7 章指向同一节点且映射片段不同，第 5 章为独立节点。拒绝部分候选、接受其余，正文 revisionId 保持原值。
3. 重扫同样的章节：已接受事件不重复创建；编辑第 7 章正文后再打开旧证据，标记来源修订已过期。
4. 在右侧只对该节点的“冲突”发起 AI 完善：候选只变该字段；模拟模型越界修改“结果”时后端拒绝。
5. 预览第 3 章交接，必须只要求“产生怀疑”；第 7 章才要求“确认身份”。书籍工作区主线条与事件图入口的内容一致。
6. 从图上对该节点选中第 7 章生成正文，确认新增正式章节修订，结果可在工作区继续编辑。生成后只第 7 章映射为待核验，节点整体未直接覆盖。
7. 核对第 7 章证据并修改其中一句导致关键结果变动：仅该章覆盖证据过期，系统提出图或正文的可选修订路径，不自动改图。

## 4. 桌面端贯通：新书与阶段生成

1. 创建新书和事件图，AI 规划少量阶段及节点；接受候选，两个节点分配同一章，其中一个节点另跨到下一章。
2. 点底部阶段括号进入计划预览：展示该阶段后代节点、两章任务和章内局部要求；未确认/未映射节点有明确缺口。
3. 启动阶段生成：同一章只执行一次正文生成；第二章接续第一章修订后的上下文。成功修订具有任务来源 ID。
4. 模拟第二章模型失败、窗口关闭、重新打开：第一章保留并显示已保存，恢复时不会再次续写第一章；重试前重新预览第二章。
5. 在第二章生成前由书籍工作区保存修改：图上任务识别版本冲突并暂停，不覆盖这次手工修改。
6. 最后按映射逐章核验；一个跨章节点只有全部必需片段及最终结果证据确认后才显示整体覆盖。

## 5. 异常与恢复检查

| 注入情况 | 期望行为 |
|---|---|
| 伪造外书 `nodeId/chapterId` | IPC/应用层拒绝；不泄露另一书正文 |
| 扫描时正文修订变化 | 候选标过期，接受被拒绝并要求重新对齐 |
| 接受补图时映射 SQL 失败 | 新节点、关系和映射全回滚；正文无变化 |
| 模型返回范围外 patch | 整份候选可修复或拒绝；正式图无变化 |
| 生成后、任务状态落库前中断 | 用 `sourceRunId` 找到已存修订并补状态；不重复生成 |
| 作者取消阶段任务 | 已保存章保留；未开始章不生成；运行章收到取消并明确状态 |
| 切换书籍时旧任务推送事件 | 事件仍归属原书，当前页面不展示或修改原书之外的状态 |

## 6. 交付记录模板

每个实施批次记录：代码提交/工作树范围、模块编号、新建书库版本、确认清理的测试数据范围、运行命令与实际结果、桌面端测试书与章节修订 ID、尚存风险。发现与本目标无关的问题另列，不扩大本轮实现范围。只有自动化与桌面端两条贯通场景均通过，才把“事件图与书籍工作区双向联动”标记为完成。
