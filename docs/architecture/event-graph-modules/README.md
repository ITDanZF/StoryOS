## 跨模块统一约定

1. **一张正式事件图**：正式图的权威数据是 `OutlineSnapshot`；节点卡与右侧 Markdown 都读取它。演示 JSON 不接正式写入。
2. **两种修订**：`outline.revision` 保护图的修改；`chapter.currentRevisionId/rowVersion` 保护正文。覆盖核对另看该映射的验证基线。
3. **候选先于写入**：AI 规划和正文反向抽取只生成可审阅的候选。作者接受后才写图；候选不参与写作交接。
4. **正文只存一处**：章节正文及历史修订留在书籍模块；图上生成是同一写作服务的新入口。
5. **一个节点可跨多章**：每章映射写清局部变化。一个章节亦可包含多个事件；实际关联键是 `(nodeId, chapterId)`。
6. **显式失败**：模型不可用、候选越界、图或章节修订冲突、章节已删除、提示词超预算、写作部分失败，都有明确结果；不默默采用备用默认值。

## 最终闭环

```mermaid
flowchart LR
  A[书籍工作区已有正文] --> B[反向补图候选]
  B --> C[作者接受正式事件图]
  C --> D[AI 局部规划与跨章映射]
  D --> E[按章构造写作交接]
  E --> F[事件图页启动单节点或阶段生成]
  F --> G[章节修订与工作区编辑]
  G --> H[覆盖核对与偏离候选]
  H --> C
```

每个模块文档里的文件路径是**预计修改位置**，不是要求创建同名新抽象。实施时先复用最近的用例和存储接口，只新增无法被现有接口表达的行为。
