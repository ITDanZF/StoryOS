# 单模型多 Agent 必做事项 TODO

## 目标

在保持单一模型连接的前提下，使主 Agent、规划 Agent、执行型子 Agent、Reviewer 和 Synthesizer 能够稳定协作，并达到可测试、可取消、可追踪、资源不泄漏的基础稳定版本。

## 当前范围

- 只支持一个默认模型，所有 Agent 使用 `inherit`。
- 支持主 Agent 委派子任务，以及规划、执行、审核、汇总流程。
- 保留 `ModelGateway` 和 `ModelRouter` 扩展边界，但暂不实现多模型配置。
- 不包含模型 fallback、分布式任务队列、Agent 插件市场和复杂运行界面。

## TODO-01：工作区运行时失败回滚

- [ ] 新运行时未创建成功前，不关闭当前可用运行时。
- [ ] 新运行时完整创建成功后，再原子替换当前运行时。
- [ ] 替换成功后关闭旧运行时资源。
- [ ] 项目不存在、模型初始化失败、Skill 加载失败时保留旧运行时。
- [ ] 为项目切换失败增加行为测试。

验收标准：

- 切换到损坏或无法初始化的项目后，原项目仍然可用。
- 不出现 `current === null` 但旧运行时已经被关闭的中间状态。

## TODO-02：部分初始化资源清理

- [ ] 为运行时构建过程增加统一的失败清理逻辑。
- [ ] SQLite checkpoint 创建后，如果后续初始化失败，必须关闭数据库连接。
- [ ] Agent 订阅创建后，如果后续初始化失败，必须取消订阅。
- [ ] 防止同一资源被重复关闭。
- [ ] 增加初始化失败后的资源释放测试。

验收标准：

- 任意初始化步骤抛错后，不残留 SQLite 句柄、事件订阅或活动运行记录。
- 失败后可以再次初始化同一项目。

## TODO-03：Agent 上下文与 checkpoint 隔离验证

- [ ] 主 Agent 与子 Agent 使用不同的 thread ID。
- [ ] 子 Agent thread ID 可追溯到父 thread、父 run 和 Agent 类型。
- [ ] 同一父任务的不同子 Agent 不共享可变 checkpoint。
- [ ] 子 Agent 只能通过明确输入获得父任务上下文。
- [ ] 增加两个并行子 Agent 的 checkpoint 隔离测试。

验收标准：

- 子 Agent A 的对话或工具结果不会进入子 Agent B 的上下文。
- 主 Agent 可以通过任务结果获得子 Agent 输出，但不会直接复用子 Agent checkpoint。

## TODO-04：取消与超时完整传播

- [ ] 用户取消主任务时中止所有未完成子 Agent。
- [ ] 主任务超时时中止 Planner、Reviewer、Synthesizer 和工具调用。
- [ ] 父级 `AbortSignal` 传播到所有子运行。
- [ ] 已取消任务不能继续产生文本增量或写入工具调用。
- [ ] 取消和超时只生成一次最终状态事件。
- [ ] 增加委派过程中取消、审核过程中超时的测试。

验收标准：

- 取消后所有子运行都进入终止状态。
- 不出现主任务已取消但子 Agent 继续消耗模型调用的情况。

## TODO-05：全局运行预算

- [ ] 所有子 Agent 共享同一个根任务预算。
- [ ] 限制最大递归深度。
- [ ] 限制模型总轮次。
- [ ] 限制工具调用总数。
- [ ] 限制子任务创建数量。
- [ ] 限制根任务总执行时间。
- [ ] 预算耗尽时返回可识别的失败原因。
- [ ] 增加递归委派和工具调用超额测试。

验收标准：

- Agent 无法通过不断委派绕过根任务限制。
- 任一预算达到上限后，新的模型或工具调用不会启动。

## TODO-06：工具权限与路径隔离

- [ ] Agent 只能解析其定义中声明的工具。
- [ ] 子 Agent 无法继承未声明的主 Agent 工具。
- [ ] 写操作继续经过工具策略和用户审批。
- [ ] 所有文件操作限制在当前工作区内。
- [ ] Windows 短路径、符号链接和路径大小写不能绕过检查。
- [ ] 增加子 Agent 未授权工具和越界路径集成测试。

验收标准：

- 未声明工具在执行前被拒绝。
- 任何形式的工作区外写入都被拒绝且不会产生文件变更。

## TODO-07：子任务失败和编排规则

- [ ] 明确不可恢复失败时终止当前子任务。
- [ ] 明确依赖任务失败后，下游任务是跳过还是终止。
- [ ] Reviewer 驳回后只允许有限次数重试。
- [ ] 重试必须继续消耗同一个根任务预算。
- [ ] 多个子任务失败时保留每个任务的具体原因。
- [ ] Synthesizer 不得把失败任务描述为已成功完成。
- [ ] 增加依赖失败、审核驳回和重试耗尽测试。

验收标准：

- 每个计划任务最终都有明确的成功、失败、跳过或取消状态。
- 编排流程不存在无限重试和永远等待的任务。

## TODO-08：单模型多 Agent 端到端测试

- [ ] 覆盖“主 Agent → 委派 → 子 Agent → 返回结果”流程。
- [ ] 覆盖“Planner → Scheduler → Reviewer → Synthesizer”流程。
- [ ] 覆盖多个独立任务的调度。
- [ ] 覆盖依赖任务失败。
- [ ] 覆盖用户取消和根任务超时。
- [ ] 覆盖预算耗尽。
- [ ] 覆盖工具拒绝和工作区越界。
- [ ] 使用可控的 Fake ModelGateway，测试中不访问真实模型服务。

验收标准：

- 完整流程不依赖网络即可重复执行。
- 测试同时验证最终结果、Agent 事件顺序、任务状态和资源释放。

## TODO-09：最低限度运行日志

- [ ] 每次根任务记录唯一 run ID 和 thread ID。
- [ ] 每个子任务记录父 run ID、Agent 类型和执行深度。
- [ ] 记录任务开始、完成、失败、取消和超时事件。
- [ ] 记录工具名称、审批结果和失败原因。
- [ ] 记录子任务重试次数和 Reviewer 结论。
- [ ] 日志不得记录 API Key 或其他敏感配置。
- [ ] 验证运行日志可以还原一次多 Agent 调用链。

验收标准：

- 用户报告失败时，可以通过 run ID 找到具体失败的 Agent、任务和步骤。
- 敏感模型连接信息不会写入日志。

## 基础稳定版完成条件

以下条件全部满足后，可以将后端标记为“单模型多 Agent 基础稳定版”：

- [ ] TODO-01 至 TODO-09 全部通过验收。
- [ ] TypeScript 类型检查通过。
- [ ] Agent 范围 ESLint 通过。
- [ ] 全部 Agent 单元测试和集成测试通过。
- [ ] 测试过程中不访问真实模型网络。
- [ ] 项目切换、取消和异常路径不存在已知资源泄漏。
- [ ] 没有未限制的递归委派、无限重试或越权工具调用。

## 暂不包含

- 多模型 `ModelRuntimeRegistry`。
- 不同 Agent 使用不同模型。
- 模型故障自动 fallback。
- 动态 Agent 插件系统。
- 分布式任务调度。
- 应用重启后自动续跑未完成任务。
- 完整图形化运行追踪界面。
