# STORYWRITER 框架说明：先总结，再展开

> 依据：`docs/pdf/StoryWriter_中文精译版.md` 第 2 节与第 3.3 节。  
> 本文用一则短例把论文第 2 节的多智能体写作流程讲清楚。例子按论文方法重构，便于对照模块，不是论文原文的生成结果，也不是 StoryOS 的实现说明。

---

## 1. 先总结

STORYWRITER 描述的是一套**长故事生成流程**。所有角色都跑在 AutoGen 里，实验时各自调用的主干模型是 **GPT-4o-mini**。流程本身回答的是：一篇长故事怎样从一句前提，经过可检查的事件、可打乱的章节，再到受控的正文。

它要同时保住两件事：

- **语篇连贯**：情节接得上，人物和因果关系记得住，故事能写完。
- **叙事复杂**：章节不必按时间顺序平铺，读起来仍然能把事件链拼回去。

三阶段分工如下。

| 阶段 | 谁来做 | 交出什么 | 关键做法 |
| :--- | :--- | :--- | :--- |
| 大纲 | EventSeed、EventValidator | 一系列事件元组 | 每个事件带时间、地点、人物、目标、关系；不合格就退回重写 |
| 规划 | SubTasker、Weaver | 子事件，以及它们所在的章节 | 非线性叙事（NLN）：可以倒叙、预叙，因果边保持不动 |
| 写作 | Coordinator、FinalWriter | 各章正文，再合成全篇 | 重写输入与输出（ReIO）：先压缩历史，再按结构和风格改稿 |

后文只用一个故事把这三步走完。

**前提（压缩版）：** 写身经百战的老兵沈衡，和他并肩二十年的战友梁秋。某夜北坡密林遇伏，两人活了下来。黄昏时，在一处偏僻山脊上，沈衡发现梁秋把撤退路线交给了敌军。故事写到沈衡仍把受伤的梁秋拖出包围，但不再认他作战友。

**故事里实际发生的顺序**（后文叫「故事顺序」）：

1. 两人在军中互救二十年。
2. 伏击前夜，梁秋把西坡路线和铜哨口令交给敌军。
3. 入夜，北坡密林遇伏，两人幸存。
4. 次日黄昏，山脊上沈衡对上地图缺页和铜哨，揭穿背叛。
5. 沈衡把梁秋拖出包围，关系终止。

**读者读到的章节顺序**（后文叫「叙事顺序」）故意不按上面排：

| 章 | 这一章写哪些子事件 | 相对故事顺序的手法 |
| :--- | :--- | :--- |
| 第 1 章 | 伏击的枪响、沈衡把梁秋按进壕沟；章末闪过山脊上一只空弹夹 | 从中段切入；章末是预叙 |
| 第 2 章 | 二十年互救；梁秋交出铜哨，读者尚未知道交给谁 | 倒叙 |
| 第 3 章 | 山脊揭穿；补上梁秋换弹时故意慢半步；拖出包围 | 回到现在，并补上伏击里被藏起的一拍 |

读者最后仍能复原 1→2→3→4→5，因为「泄密导致西侧枪声」「铜哨对上口令」「救助还在、称呼取消」这几条关系没有被拆掉。这就是这套理论要演示的全部。

## 2. 用同一例子展开

### 2.1 大纲智能体：先写成事件元组

传统大纲常写成几句描述，例如「两人遇伏，后来发现背叛」。STORYWRITER 改成**事件元组**：一条事件是一个可检查的节点，边上写它和别的事件是什么关系。附录里的要素是时间、地点、人物、目标；引言里还强调事件之间要有因果等关系。

EventSeed 按前提逐条生成。EventValidator 盯着已有大纲，只做两件事：这一条自身是否成立，它和前面的事件是否接得上。通过就留下，不通过就给出反馈，让 EventSeed 改下一条或重写这一条。

下面按生成过程演示一轮退回。

**EventSeed 先交出 E1**

| 字段 | 内容 |
| :--- | :--- |
| 名称 | 北坡遇伏 |
| 时间 | 入夜后 |
| 地点 | 北坡密林 |
| 人物 | 沈衡、梁秋、敌军小队 |
| 目标 | 活过这一夜 |
| 关系 | 故事的当前动作；原因尚未展开 |

EventValidator：通过。反馈可以很短，论文图 2 里的对应说法是「很好，继续。」

**EventSeed 再交出一条，这一条不合格**

| 字段 | 内容 |
| :--- | :--- |
| 名称 | 梁秋死于交叉火力 |
| 时间 | 同一夜后半 |
| 地点 | 北坡密林 |
| 人物 | 沈衡、梁秋 |
| 目标 | 沈衡独自撤离 |
| 关系 | 紧接 E1，梁秋死亡 |

EventValidator：退回。前提要求山脊上揭穿背叛，还要求沈衡把梁秋带出包围。这一条让后续事件没有当事人。反馈要指出缺的是哪条约束，而不是另写一套大纲。

**EventSeed 按反馈改写成后面四条**

| 编号 | 名称 | 时间 | 地点 | 人物 | 目标 | 关系 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| E1 | 北坡遇伏 | 入夜后 | 北坡密林 | 沈衡、梁秋、敌军 | 活过这一夜 | 当前动作 |
| E2 | 交出铜哨 | 伏击前夜 | 营地外 | 梁秋、敌军接头人 | 把西坡路线交出去 | 发生在 E1 之前；是 E1 里西侧枪声的原因 |
| E3 | 山脊揭穿 | 次日黄昏 | 偏僻山脊 | 沈衡、梁秋 | 确认谁把路线交了出去 | 紧接 E1；证据来自 E2 的铜哨和缺页地图 |
| E4 | 拖出包围 | 揭穿之后 | 山脊向下的坡道 | 沈衡、梁秋 | 离开包围圈 | 紧接 E3；人被带走，战友关系结束 |
| E5 | 二十年互救 | 从军至今 | 多处战场 | 沈衡、梁秋 | 彼此活下来 | 发生在 E2 之前；解释沈衡为何仍会拖人 |

注意 E5、E2 在故事时间上更早，大纲阶段却可以后写出来。大纲要的是事件和关系齐全，还不是章节顺序。Validator 在 E3 上会再查一次：铜哨和缺页必须能指回 E2，否则「揭穿」没有证据。论文图 2 里对不合格事件的反馈是「不好，我建议……」，这里的建议就是补上这条证据边。

到这一步，大纲是五条元组加一组关系，可以画成一张很小的事件图：

```text
E5 二十年互救
  └─先于→ E2 交出铜哨
              └─导致→ E1 北坡遇伏
                          └─紧接→ E3 山脊揭穿
                                      └─紧接→ E4 拖出包围
```

### 2.2 规划智能体：拆开，再故意打乱章节

这一阶段要解决的是：事件如果永远按时间线一章接一章，长故事会平，也缺少交织。论文把做法叫做**非线性叙事（NLN）**，并把它放在三则已有理论上。

- 热奈特区分**故事顺序**和**叙事顺序**。上面的 1→5 是故事顺序；第 1 章从遇伏写起，是叙事顺序。倒叙（analepsis）是先写后面的事，再补前面的事。预叙（prolepsis）是在当前段落里先露出后文的一片碎片。
- 赫尔曼强调连贯来自事件之间的因果和逻辑，读者靠这些联系把链条重建出来。所以允许乱序的前提，是关系还在。
- 瑞安的叙事可能世界用来说明：顺序一变，读者路径就变。同一组事件可以走出不同的阅读体验。论文引用的是这层潜力；短例只走其中一条路径。

两个模块分开做。

**SubTasker** 把高层事件拆成还能单独写进某一章的子事件。拆开之后，原先的因果边要落到具体子事件上，不能只留在父事件上。

| 父事件 | 子事件 | 这一拍具体发生什么 | 必须保住的联系 |
| :--- | :--- | :--- | :--- |
| E1 北坡遇伏 | 1.1 | 雾里第一轮射击，方向来自西侧 | 西侧这个方向后来要能指回 E2 |
| E1 | 1.2 | 沈衡把梁秋按进壕沟 | 说明他此刻仍把梁秋当战友 |
| E1 | 1.3 | 梁秋换弹时故意慢了半步 | 这是 E2 的结果，写第 1 章时先藏住 |
| E2 交出铜哨 | 2.1 | 梁秋把西坡那一页从地图上撕下 | 第 3 章的缺页要能对上 |
| E2 | 2.2 | 他把铜哨和一句口令交给接头人 | 第 3 章用来揭穿 |
| E3 山脊揭穿 | 3.1 | 黄昏，沈衡发现地图少了西坡 | 对上 2.1 |
| E3 | 3.2 | 空弹夹和铜哨、敌军口令对上 | 对上 2.2，并解释 1.1 为何来自西侧 |
| E3 | 3.3 | 沈衡问他要不要自己走 | 把选择权交给 E4 |
| E4 拖出包围 | 4.1 | 沈衡拖着他下坡 | 动作仍是救助 |
| E4 | 4.2 | 沈衡改口，只叫他的名字 | 关系终止，与 1.2 对照 |
| E5 二十年互救 | 5.1 | 早年沈衡为梁秋挡过一次白刃 | 给 1.2 和 4.1 一个动机 |
| E5 | 5.2 | 梁秋曾把沈衡从河里拽上来 | 同上 |

**Weaver** 不改这些子事件的内容，只决定它们进哪一章。分配结果就是第 1 节那张章节表，展开如下。

**第 1 章**收 1.1、1.2，外加 3.1 的一片碎片。

- 正文从雾和西侧枪声写起，再写沈衡把人按进壕沟。
- 章末只给一只落在山脊上的空弹夹，不解释它为什么在那里。这是预叙：故事时间上它属于次日黄昏，叙事时间上它先被读者看见。
- 1.3（故意慢半步）先不进这一章。它一出现，背叛就提前说破了。

**第 2 章**收 5.1、5.2、2.1、2.2。

- 这是倒叙：从军中互救写到交出铜哨。
- 2.2 可以写到「交给一个戴兜帽的人」，先不写「这人是敌军接头人」。关系在大纲里已经记为「导致西侧枪声」，章节文本可以选择晚一点让读者看懂。

**第 3 章**收 3.1、3.2、1.3、3.3、4.1、4.2。

- 先把第 1 章那只空弹夹接上：它是沈衡在山脊核对口令时掉下的。
- 再补 1.3。读者这时才明白，壕沟里那半步慢，是因为梁秋知道西侧会开枪。
- 最后写拖行和改口。

Weaver 做完后，可以用一张对照看「乱序」到底乱在哪里。

```text
故事顺序：  5 二十年 → 2 泄密 → 1 遇伏 → 3 揭穿 → 4 拖出
叙事顺序：  第1章(1.1, 1.2, 预叙3.1的碎片)
            第2章(5.1, 5.2, 2.1, 2.2)
            第3章(3.1, 3.2, 1.3, 3.3, 4.1, 4.2)
```

1.3 留到第 3 章，是这则短例里最关键的一刀：事件没有被删，只是晚出场。读者在第 3 章把「西侧枪声 ← 交出路线 ← 铜哨」接上之后，第 1 章的伏击仍然成立。消融实验里去掉 NLN 时，子事件会退回严格时间顺序，复杂性分数明显下降。这和短例的直觉一致：若第 1 章就写完 1.3 和 2.2，揭穿不再是揭穿。

### 2.3 写作智能体：历史先压短，稿子再改一遍

写作阶段由 Coordinator 和 FinalWriter 配合。Coordinator 看全局结构，从大纲、子事件到正文都参与；FinalWriter 负责把当前这拍写成风格统一的正文。

论文指出一个具体限度：输入超过大约 **10,000 个字符** 后，模型容易丢开早期情节，写出偏题或不连贯的段落。长故事必然超过这个长度，所以写作智能体里加了 **ReIO**。

**输入侧：只把和当前子事件有关的历史送进去。**

假设正在写第 3 章的 3.2（铜哨对上口令）。此时前面已经有第 1 章和第 2 章的正文。Coordinator 不做「把前文各缩写一遍」这种均等摘要，而是按当前子事件挑选。

当前子事件需要这些事实：

- 西侧响过枪（1.1）。
- 沈衡曾把梁秋按进壕沟（1.2）。
- 地图少了西坡那一页（2.1）。
- 铜哨和口令已经交出去（2.2）。
- 章末那只空弹夹还没有解释（第 1 章预叙）。

可以压掉、且不影响 3.2 的内容：

- 5.1、5.2 里两次互救的战斗细节。写 4.1 时再把它们取回来。
- 第 1 章里雾气、树木、枪声节奏的句子。

压完的输入示意：

```text
当前要写：3.2 山脊上，铜哨与敌军口令对上。
必须维持：
- 枪来自西侧；地图缺的是西坡。
- 铜哨是梁秋在前夜交出的。
- 沈衡在壕沟里仍保护过他。
- 第 1 章结尾的空弹夹要在这一拍落地。
不要写：原谅、重新以战友相称、梁秋死亡。
```

摘要会缓存。后面写 3.3、4.1 时，若依赖的事实不变，就复用这份摘要，只追加新约束。第 3.3 节把这件事做成一个**摘要智能体**加**滑动窗口**：事件顺序往前走，窗口里的旧内容被系统性简化。对 15,000 token 以下的文本，他们比较了几种窗口，覆盖 **[2, k-1]** 的那一档平均最好。含义是：写到第 k 个事件时，把中间这一大段历史尽量简化；缩得更彻底的设置，叙事质量更好。短例里「互救的战斗细节先退出 3.2 的输入」，就是同一种选择。

**输出侧：稿子偏离结构或风格，就重写并替换。**

FinalWriter 可能交出这样一段：

> 沈衡握着铜哨，忽然笑了。二十年还在。他叫了声「秋哥」，说西坡的事到此为止，下山以后仍是兄弟。

Coordinator 对照 E3、E4：揭穿必须发生，救助可以留下，战友关系必须结束。这段把关系写回去了，和 4.2 冲突，也和输入里的「不要写」冲突。于是重写并替换原段，而不是另起一章并存两稿：

> 沈衡把铜哨放在两人中间。西坡那一页、这只哨、壕沟里慢的那半步，是同一件事。他抓住梁秋的腕子往下拖，开口时只剩名字：「梁秋。走。」

这一轮可以重复，直到结构和风格都对齐。消融实验对得上短例里的两种失败：去掉输入压缩，历史变长，成本和整体质量一起变差；去掉输出重写，正文更容易偏离大纲，相关性下降。

三章写完后，Coordinator 按 Weaver 的章节顺序合成全篇。合成时不再重新决定哪些子事件出场，那是规划阶段已经固定的结果。

## 3. 这则短例里，各模块各改了哪一刀

| 模块 | 在这个故事里的那一刀 | 若拿掉，短例会变成什么 |
| :--- | :--- | :--- |
| EventSeed | 写出遇伏、泄密、揭穿、拖行、互救五条元组 | 只剩「遇伏后发现背叛」这种句子，铜哨和西侧对不上 |
| EventValidator | 退回「梁秋死于伏击」 | 山脊揭穿没有当事人 |
| SubTasker | 把泄密拆成缺页和铜哨，把伏击拆出「慢半步」 | 章节只能整段搬运父事件，无法把一拍留到后文 |
| Weaver | 第 1 章藏起慢半步，用空弹夹做预叙 | 时间线平铺，揭穿提前发生 |
| Coordinator 输入 | 写铜哨对口令时，暂时拿掉两次互救的战斗细节 | 输入被旧战斗占满，口令这拍容易写散 |
| Coordinator 输出 | 删掉「秋哥」「仍是兄弟」 | 结尾和「关系终止」冲突 |
| FinalWriter | 把压缩后的约束写成山脊上的一段正文 | 结构还在，但没有可阅读的叙事句 |

论文用同一组维度给整套流程打分：相关性、连贯性、共情、意外性、创造性、复杂性。人工评估里 STORYWRITER 的平均分是 4.2，平均长度 8,081；直接把前提交给 GPT-4o-mini 的平均长度是 1,078。长度和质量同时上去，是他们声称这套分工成立的主要证据。

## 4. 读的时候建议停在这里

第 2 节讲的是生成流程。论文后半还有两件不同的事，不要和上面的六个角色混成一个模型：

- 第 3 节的对照方法是 DOC、Agents' Room，以及单独的 GPT-4o-mini。自动评分用的是 GPT-4o。
- 第 4 节用这套流程生成数据集 LONGSTORY，再监督微调出 STORYWRITER_LLAMA（Llama 3.1-8B）和 STORYWRITER_GLM（GLM-4-9B）。那是「用流程生产训练数据」，流程本身仍然是第 2 节这三阶段。

回到短例，整套理论可以收成三句话：

1. 大纲是事件和关系，Validator 负责把写死后文的事件退回去。
2. 章节可以倒叙、预叙，只要缺页、铜哨、西侧枪声这几条边还在。
3. 写某一拍时，历史按这一拍来裁；写出的句子若把「战友关系结束」写没了，就替换掉再写。
