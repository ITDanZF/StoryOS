## 摘要

大语言模型（Large Language Models，LLMs）通过实现类人的文本生成和自然语言理解，极大地推动了人工智能的发展。然而，它们对静态训练数据的依赖限制了其响应动态、实时查询的能力，从而导致输出过时或不准确。检索增强生成（Retrieval-Augmented Generation，RAG）作为一种解决方案应运而生，它通过整合实时数据检索来增强大语言模型，从而提供与上下文相关且最新的响应。尽管前景广阔，传统的 RAG 系统仍受限于静态工作流，缺乏多步推理和复杂任务管理所需的自适应性。智能体式检索增强生成（Agentic Retrieval-Augmented Generation，Agentic RAG）通过将自主人工智能智能体嵌入 RAG 流水线，超越了这些局限。这些智能体利用智能体设计模式——反思（reflection）、规划（planning）、工具使用（tool use）和多智能体协作（multi-agent collaboration）——来动态管理检索策略、迭代地精炼上下文理解，并通过从顺序步骤到自适应协作等清晰定义的操作结构来调整工作流。这种集成使 Agentic RAG 系统能够在多样化的应用中提供无与伦比的灵活性、可扩展性和上下文感知能力。本文对 Agentic RAG¹ 系统进行了分析性综述。它追溯了 RAG 范式的演变，基于智能体数量（agent cardinality）、控制结构（control structure）、自主性（autonomy）和知识表示（knowledge representation）提出了一个原则性的 Agentic RAG 架构分类法，并对现有框架之间的设计权衡进行了比较分析。该综述进一步考察了在医疗保健、金融、教育和企业文档处理等领域的实际应用，并为系统设计者和从业者提炼了实践性经验教训。最后，它指出了与评估、协调、记忆管理、效率和治理相关的关键开放研究挑战，并概述了未来研究的方向。

## 1 引言

大语言模型（Large Language Models，LLMs）[1, 2, 3]（如 GPT-5、PaLM 和 LLaMA）通过实现类人的文本生成和自然语言理解，已经改变了人工智能的面貌。这些模型推动了对话智能体 [4]、内容创作、实时翻译以及包括文本到图像（text-to-image）和文本到视频（text-to-video）合成在内的多模态生成任务 [5, 6] 的创新。然而，一个核心挑战依然存在：大语言模型如何能够可靠地对快速变化的外部知识进行推理，而不是仅仅依赖静态的预训练数据。

尽管取得了这些进展，大语言模型仍然受限于静态的预训练数据，常常产生过时的响应、幻觉（hallucination）内容 [7]，并且无法适应不断演变的现实世界信息。

检索增强生成（Retrieval-Augmented Generation，RAG）[8, 9] 通过在推理时将外部知识整合到生成过程中，解决了这些局限。通过将大语言模型的能力与基于向量数据库 [11]、API 或网络来源的检索机制 [10] 相结合，RAG 改善了事实基础（factual grounding）、相关性和时效性。然而，传统的 RAG 流水线通常是静态和线性的，限制了复杂的多步推理、深度上下文理解和迭代式响应精炼。这些局限促使人们寻求自主控制机制，以动态决定何时检索、如何改写查询，以及何时收集到充分的证据。

与此同时，智能体式人工智能（agentic AI）[12] 的进展引入了能够感知、推理和自主执行任务的智能智能体 [13]。这些智能体利用设计模式——反思、规划、工具使用和多智能体协作——来动态分解任务并调整策略。这些能力与 RAG 直接相关，因为检索和推理决策本身可以被视为智能体任务。这些模式进一步通过工作流模式（workflow patterns）[13, 14] 加以结构化，包括提示链（prompt chaining）、路由（routing）、并行化（parallelization）、编排者-工作者模型（orchestrator–worker）以及评估器-优化器循环（evaluator–optimizer loop），这些模式在系统层面管理多个提示、模型或智能体如何协同工作。

RAG 与智能体智能的融合催生了智能体式检索增强生成（Agentic Retrieval-Augmented Generation，Agentic RAG）[15]，它将自主智能体直接集成到 RAG 流水线中，以实现动态检索、迭代式上下文精炼和自适应工作流编排 [16]。这引入了一个显式的控制层，指导系统如何基于外部证据进行推理——协调检索、验证信息、调用工具并精炼响应——从而使 Agentic RAG 能够高效处理需要精确性和自适能力的复杂多领域任务，如图 1 所示。

尽管兴趣快速增长，Agentic RAG 领域仍然较为分散，架构各异、术语不一致，且比较性理解有限。现有工作聚焦于单个框架或特定应用的实现，目前尚无统一的分类法沿着原则性的设计维度来组织 Agentic RAG 系统。

本文提出一项分析性综述，旨在结构化这一新兴领域。它回顾了 RAG 范式的演变，包括朴素（naïve）RAG、模块化（modular）RAG 和基于图的（graph-based）RAG [17]，以及它们向智能体系统的转变。本文基于智能体数量、控制结构、自主性和知识表示提出了一个原则性的 Agentic RAG 架构分类法，随后进行了设计权衡的比较分析。该综述考察了在医疗保健 [18, 19]、金融和教育 [20] 等领域的应用，为系统设计者提炼了实践性经验，并指出了开放研究挑战以指导未来工作。

本文结构如下：第 2 节介绍 RAG 及其演变，重点阐述传统方法的局限。第 3 节阐述智能体智能的原理和智能体模式。第 4 节阐述智能体工作流模式。第 5 节给出 Agentic RAG 系统的分类法，包括单智能体、多智能体和基于图的框架。第 6 节对 Agentic RAG 框架进行比较分析。第 7 节考察 Agentic RAG 的应用，第 8 节讨论实现工具和框架。第 9 节对 Agentic RAG 框架进行比较分析。第 10 节讨论经验教训和实践指导。第 11 节聚焦基准和数据集，第 12 节讨论开放研究问题和未来挑战，第 13 节总结 Agentic RAG 系统的未来方向。

## 2 检索增强生成的基础

### 2.1 检索增强生成（RAG）概览

检索增强生成（Retrieval-Augmented Generation，RAG）代表了人工智能领域的一项重大进展，它将大语言模型（Large Language Models，LLMs）的生成能力与实时数据检索相结合。虽然大语言模型在自然语言处理方面已展现出卓越的能力，但它们在静态预训练数据上的依赖常常导致过时或不完整的响应。RAG 通过动态检索来自外部来源的相关信息，并将其纳入生成过程来解决这一局限，从而产生在上下文上准确且最新的输出。

### 2.2 RAG 的核心组件

RAG 系统的架构整合了三个主要组件（图 2）：

- **检索（Retrieval）**：负责查询外部数据源，如知识库、API 或向量数据库。高级检索器利用稠密向量搜索和基于 transformer 的模型来提高检索精度和语义相关性。（注：原文此处作 "Retrieveal"，为 "Retrieval" 之笔误。）
- **增强（Augmentation）**：处理检索到的数据，提取并总结最相关的信息，以与查询上下文对齐。
- **生成（Generation）**：将检索到的信息与大语言模型的预训练知识相结合，生成连贯、在上下文上恰当的响应。

### 2.3 RAG 范式的演变

检索增强生成（RAG）领域已发生了显著演变，以应对现实世界应用日益增长的复杂性——在这些应用中，上下文准确性、可扩展性和多步推理至关重要。最初基于关键词的简单检索，已经转变为能够整合多样化数据源和自主决策过程的复杂、模块化和自适应系统。这一演变凸显了 RAG 系统高效且有效地处理复杂查询的日益增长的需求。

本节考察 RAG 范式的演进，介绍关键的发展阶段——朴素 RAG（Naïve RAG）、高级 RAG（Advanced RAG）、模块化 RAG（Modular RAG）、图 RAG（Graph RAG）和智能体式 RAG（Agentic RAG），以及它们的定义性特征、优势和局限。通过理解这些范式的演变，读者可以领会检索与生成能力所取得的进展及其在各个领域的应用。

#### 2.3.1 朴素 RAG（Naïve RAG）

朴素 RAG [21] 代表了检索增强生成的基础实现。图 3 展示了朴素 RAG 的简单"检索-读取"工作流，其重点是基于关键词的检索和静态数据集。这些系统依赖简单的基于关键词的检索技术（如 TF-IDF 和 BM25）从静态数据集中获取文档。然后，检索到的文档被用来增强语言模型的生成能力。

朴素 RAG 的特点在于其简单性和易于实现，使其适用于上下文复杂性较低、基于事实的查询任务。然而，它存在若干局限：

- **缺乏上下文感知**：由于依赖词法匹配而非语义理解，检索到的文档往往无法捕捉查询的语义细微差别。
- **输出碎片化**：缺乏高级预处理或上下文整合，常常导致响应脱节或过于笼统。
- **可扩展性问题**：基于关键词的检索技术难以应对大型数据集，往往无法识别最相关的信息。

尽管存在这些局限，朴素 RAG 系统为检索与生成的结合提供了关键的原理验证，为更复杂的范式奠定了基础。

#### 2.3.2 高级 RAG（Advanced RAG）

高级 RAG [21] 系统在朴素 RAG 的局限之上进行构建，融入了语义理解和增强的检索技术。图 4 突出了高级 RAG 在检索中的语义增强及其迭代式、上下文感知的流水线。这些系统利用稠密检索模型（如稠密段落检索（Dense Passage Retrieval，DPR））和神经排序算法来提高检索精度。

高级 RAG 的关键特征包括：

- **稠密向量搜索**：查询和文档被表示在高维向量空间中，从而使用户查询与检索到的文档之间实现更好的语义对齐。
- **上下文重排序**：神经模型对检索到的文档进行重排序，以优先处理上下文最相关的信息。
- **迭代式检索**：高级 RAG 引入多跳检索机制，能够针对复杂查询在多个文档之间进行推理。

这些进展使高级 RAG 适用于要求高精度和细致理解的应用，例如研究综合和个性化推荐。然而，计算开销大和可扩展性有限等挑战依然存在，尤其是在处理大型数据集或多步查询时。

#### 2.3.3 模块化 RAG（Modular RAG）

模块化 RAG [21] 代表了 RAG 范式的最新演变，强调灵活性和可定制性。这些系统将检索和生成流水线分解为独立、可复用的组件，从而能够进行领域特定的优化和任务适应性调整。图 5 展示了模块化架构，呈现了混合检索策略、可组合流水线和外部工具集成。

模块化 RAG 的关键创新包括：

- **混合检索策略**：将稀疏检索方法（例如稀疏编码器 BM25）与稠密检索技术 [22]（例如 DPR——稠密段落检索）相结合，以在多样化的查询类型中最大化准确性。
- **工具集成**：纳入外部 API、数据库或计算工具来处理专门任务，例如实时数据分析或领域特定的计算。
- **可组合流水线**：模块化 RAG 使检索器、生成器和其他组件能够被独立替换、增强或重新配置，从而对特定用例具有高度适应性。

例如，一个为金融分析设计的模块化 RAG 系统可以通过 API 检索实时股票价格，使用稠密检索分析历史趋势，并通过定制化的语言模型生成可操作的投资见解。这种模块化和可定制性使模块化 RAG 成为复杂、多领域任务的理想选择，兼具可扩展性和精确性。

#### 2.3.4 图 RAG（Graph RAG）

图 RAG [17] 通过整合基于图的数据结构扩展了传统的检索增强生成系统，如图 6 所示。这些系统利用图数据中的关系和层次结构来增强多跳推理和上下文丰富化。通过纳入基于图的检索，图 RAG 能够产生更丰富、更准确的生成输出，尤其适用于需要关系理解的任务。

图 RAG 的特点在于其具备以下能力：

- **节点连通性**：捕捉并推理实体之间的关系。
- **层次化知识管理**：通过基于图的层次结构处理结构化和非结构化数据。
- **上下文丰富化**：通过利用基于图的路径来增加关系理解。

然而，图 RAG 也有一些局限：

- **可扩展性有限**：对图结构的依赖可能限制可扩展性，尤其是在数据来源广泛的情况下。
- **数据依赖性**：高质量的图数据对产生有意义的输出至关重要，这限制了其在非结构化或标注不佳的数据集上的适用性。
- **集成复杂性**：将图数据与非结构化检索系统集成，会增加设计和实现的复杂性。

图 RAG 非常适合医疗诊断、法律研究等需要对结构化关系进行推理的领域。

#### 2.3.5 智能体式 RAG（Agentic RAG）

Agentic RAG 通过引入能够进行动态决策和工作流优化的自主智能体，代表了一种范式转变。与静态系统不同，Agentic RAG 采用迭代式精炼和自适应检索策略来处理复杂、实时和多领域的查询。该范式在引入基于智能体的自主性的同时，充分利用了检索与生成过程的模块化特性。

Agentic RAG 的关键特征包括：

- **自主决策**：智能体根据查询复杂度独立评估并管理检索策略。
- **迭代式精炼**：纳入反馈循环以提高检索准确性和响应相关性。
- **工作流优化**：动态编排任务，实现实时应用中的高效性。

尽管取得了进展，Agentic RAG 仍面临一些挑战：

- **协调复杂性**：管理智能体之间的交互需要复杂的编排机制。
- **计算开销**：使用多个智能体增加了复杂工作流的资源需求。
- **可扩展性限制**：虽然可扩展，但系统的动态特性可能在高查询量下给计算资源带来压力。

Agentic RAG 在客户支持、金融分析和自适应学习平台等领域表现出色，这些领域对动态自适性和上下文精确性要求极高。

### 2.4 传统 RAG 系统的挑战与局限

传统的检索增强生成（RAG）系统通过整合实时数据检索，显著扩展了大语言模型（LLMs）的能力。然而，这些系统仍然面临阻碍其在复杂现实应用中发挥效用的关键挑战。最显著的局限集中在上下文整合、多步推理以及可扩展性与延迟问题上。

#### 2.4.1 上下文整合

即使 RAG 系统成功检索到相关信息，它们也常常难以将这些信息无缝地纳入生成的响应中。检索流水线的静态特性和有限的上下文感知能力会导致碎片化、不一致或过于笼统的输出。

**示例**：诸如"阿尔茨海默病研究有哪些最新进展，它们对早期治疗有何影响？"这样的查询，可能会检索到相关研究论文和医学指南。然而，传统 RAG 系统往往无法将这些发现综合成一个连贯的解释，将新疗法与具体的患者场景联系起来。类似地，对于"干旱地区小规模农业的最佳可持续实践有哪些？"这样的查询，传统系统可能会检索到关于一般农业方法的文档，却忽略了针对干旱环境量身定制的关键可持续性实践。

#### 2.4.2 多步推理

许多现实世界查询需要迭代式或多跳推理——跨多个步骤检索和综合信息。传统 RAG 系统往往无法基于中间洞见或用户反馈来精炼检索，从而导致不完整或脱节的响应。

**示例**：像"欧洲可再生能源政策有哪些经验可以应用于发展中国家，潜在的经济影响是什么？"这样的复杂查询，需要对多种类型的信息进行编排，包括政策数据、针对发展中地区的语境化以及经济分析。传统 RAG 系统通常无法将这些迥异的要素连接成一个连贯的响应。

#### 2.4.3 可扩展性与延迟问题

随着外部数据源规模的扩大，查询和排序大型数据集的计算密集度日益增加。这会导致显著的延迟，从而削弱系统在实时应用中提供及时响应的能力。

**示例**：在金融分析或实时客户支持等对时间敏感的场景中，查询多个数据库或处理大量文档集所导致的延迟可能妨碍系统的整体效用。例如，在高频交易中检索市场趋势的延迟可能导致错失机会。

### 2.5 Agentic RAG：一种范式转变

传统 RAG 系统由于其静态工作流和有限的自适能力，往往难以处理动态、多步推理和复杂的现实世界任务。这些局限促使了智能体智能的整合，从而催生了 Agentic RAG。通过纳入能够进行动态决策、迭代式推理和自适应检索策略的自主智能体，Agentic RAG 建立在早期范式的模块化之上，同时克服了它们固有的约束。这一演变使得更复杂、多领域的任务能够以更高的精确性和上下文理解得以处理，使 Agentic RAG 成为下一代人工智能应用的基石。特别是，Agentic RAG 系统通过优化工作流来降低延迟，并迭代式地精炼输出，从而解决了历来阻碍传统 RAG 可扩展性和有效性的挑战。

## 3 智能体智能的核心原理与背景

智能体智能（Agentic Intelligence）构成了智能体式检索增强生成（RAG）系统的基础，使它们能够超越传统 RAG 的静态和被动特性。通过整合能够进行动态决策、迭代式推理和协作式工作流的自主智能体，Agentic RAG 系统展现出更强的自适性和精确性。本节探讨支撑智能体智能的核心原理。

**AI 智能体的组件**。本质上，一个 AI 智能体包括（图 7）：

- **大语言模型（具有定义的角色与任务）**：充当智能体的主要推理引擎和对话接口。它解释用户查询、生成响应并保持连贯性。
- **记忆（短期与长期）**：跨交互捕捉上下文和相关数据。短期记忆（short-term memory）[23] 跟踪即时对话状态，而长期记忆（long-term memory）[23] 存储累积的知识和智能体经验。
- **规划（反思与自我批判）**：通过反思、查询路由或自我批判（self-critique）[24] 指导智能体的迭代式推理过程，确保复杂任务被有效分解 [25]。
- **工具（向量搜索、网络搜索、API 等）**：将智能体的能力扩展到文本生成之外，使其能够访问外部资源、实时数据或专门计算。

智能体模式（Agentic Patterns）[26, 27] 提供了结构化的方法论，用于指导智能体式检索增强生成（RAG）系统中智能体的行为。这些模式使智能体能够动态调整、规划和协作，确保系统能够以精确性和可扩展性处理复杂的现实世界任务。有四种关键模式支撑着智能体工作流：

### 3.1 反思（Reflection）

反思是智能体工作流中的一种基础设计模式，使智能体能够迭代式地评估和精炼其输出。通过纳入自我反馈机制，智能体可以识别并纠正错误、不一致之处以及有待改进的地方，从而提升在代码生成、文本生成和问答等任务上的性能（如图 8 所示）。在实际使用中，反思涉及提示智能体对其输出的正确性、风格和效率进行批判，然后将这些反馈纳入后续迭代。诸如单元测试或网络搜索等外部工具可以通过验证结果和指出差距来进一步增强这一过程。

在多智能体系统中，反思可以涉及不同的角色，例如一个智能体生成输出而另一个智能体对其进行批判，从而促进协作式改进。例如，在法律研究中，智能体可以通过重新评估检索到的判例法来迭代式地精炼响应，确保准确性和全面性。反思已在 Self-Refine [28]、Reflexion [29] 和 CRITIC [24] 等研究中展示了显著的性能提升。

### 3.2 规划（Planning）

规划 [25] 是智能体工作流中的一种关键设计模式，使智能体能够自主地将复杂任务分解为更小、可管理的子任务。这一能力对于动态和不确定场景中的多跳推理和迭代式问题求解至关重要，如图 9a 所示。

通过利用规划，智能体可以动态确定完成更大目标所需的步骤序列。这种自适性使智能体能够处理无法预先定义的任务，确保决策的灵活性。虽然功能强大，但与反思等确定性工作流相比，规划可能产生较不可预测的结果。规划特别适合需要动态调整、而预定义工作流不足以胜任的任务。随着技术的成熟，其推动跨领域创新应用的潜力将持续增长。

### 3.3 工具使用（Tool Use）

工具使用使智能体能够通过与外部工具、API 或计算资源交互来扩展其能力，如图 9b 所示。这一模式允许智能体收集信息、执行计算并处理超出其预训练知识范围的数据。通过将工具动态整合到工作流中，智能体能够适应复杂任务，并提供更准确、更符合上下文的输出。

现代智能体工作流将工具使用纳入各种应用，包括信息检索、计算推理以及与外部系统的交互。随着 GPT-4 的函数调用能力以及能够管理众多工具访问的系统等进展，这一模式的实现已经发生了显著演变。这些进展促成了复杂的工作流，使智能体能够自主地为给定任务选择并执行最相关的工具。

虽然工具使用显著增强了智能体工作流，但在工具选择优化方面仍存在挑战，尤其是在可用选项数量众多的情境下。受检索增强生成（RAG）启发的技术（如基于启发式的选择）已被提出来解决这一问题。

### 3.4 多智能体（Multi-Agent）

多智能体协作 [30] 是智能体工作流中的一种关键设计模式，能够实现任务专门化和并行处理。智能体之间进行通信并共享中间结果，确保整个工作流保持高效和连贯。通过将子任务分配给专门的智能体，这一模式提高了复杂工作流的可扩展性和自适性。多智能体系统允许开发者将复杂任务分解为更小、可管理的子任务，分配给不同的智能体。这种方法不仅提升了任务性能，还为管理复杂交互提供了一个稳健的框架。每个智能体都以其自身的记忆和工作流运行，其中可以包括工具使用、反思或规划，从而实现动态和协作式的问题求解（见图 10）。

虽然多智能体协作具有巨大潜力，但与反思和工具使用等更成熟的工作流相比，它是一种较不可预测的设计模式。尽管如此，AutoGen、Crew AI 和 LangGraph 等新兴框架正在为实现有效的多智能体解决方案提供新的途径。

这些设计模式构成了 Agentic RAG 系统成功的基础。通过将工作流结构化——从简单的顺序步骤到更具自适应性和协作性的过程——这些模式使系统能够动态调整其检索和生成策略，以应对现实世界环境中多样且不断变化的需求。利用这些模式，智能体能够处理迭代式、上下文感知的任务，其能力远超传统 RAG 系统。

## 4 智能体工作流模式：动态协作的自适应策略

智能体工作流模式 [13, 31] 对基于大语言模型的应用进行结构化，以优化性能、准确性和效率。根据任务复杂度和处理需求的不同，适用不同的方法。

### 4.1 提示链：通过顺序处理提高准确性

提示链（prompt chaining）[13, 31] 将一个复杂任务分解为多个步骤，其中每一步都建立在前一步的基础之上。这种结构化方法通过在推进之前简化每个子任务来提高准确性。然而，由于顺序处理，它可能增加延迟。

**何时使用**：当任务可以被分解为固定的子任务，且每个子任务都对最终输出有所贡献时，这种工作流最为有效。它在逐步推理能够提高准确性的场景中特别有用。

**示例应用**：

- 用一种语言生成营销内容，然后将其翻译成另一种语言，同时保留细微差别。
- 通过先生成大纲、验证其完整性、再展开全文来组织文档创作。

### 4.2 路由：将输入定向到专门的处理流程

路由（routing）[13, 31] 涉及对输入进行分类，并将其定向到适当的专门提示或处理流程。这种方法确保不同的查询或任务被分别处理，从而提高效率和响应质量。

**何时使用**：适用于不同类型的输入需要不同处理策略的场景，确保每个类别都获得优化的性能。

**示例应用**：

- 将客户服务查询分类为技术支持、退款请求或一般咨询等类别。
- 将简单查询分配给较小的模型以节省成本，而将复杂请求交给更先进的模型。

### 4.3 并行化：通过并发执行加快处理速度

并行化（parallelization）[13, 31] 将任务划分为可同时运行的独立过程，从而降低延迟并提高吞吐量。它可以分为分段（sectioning，独立的子任务）和投票（voting，为准确性产生多个输出）。

**何时使用**：当任务可以独立执行以提高速度，或者多个输出可以提高置信度时有用。

**示例应用**：

- **分段**：拆分内容审核等任务，其中一个模型筛查输入，而另一个模型生成响应。
- **投票**：使用多个模型交叉检查代码漏洞，或分析内容审核决策。

### 4.4 编排者-工作者：动态任务委派

这种工作流 [13, 31] 以一个中央编排者模型为特征，该模型动态地将任务分解为子任务，将其分配给专门的工作者模型，并汇总结果。与并行化不同，它能够适应不同的输入复杂度。

**何时使用**：最适合需要动态分解和实时调整、且子任务并非预先定义的任务。

**示例应用**：

- 根据所请求更改的性质，自动修改代码库中的多个文件。
- 通过从多个来源收集和综合相关信息来进行实时研究。

### 4.5 评估器-优化器：通过迭代精炼输出

评估器-优化器（evaluator-optimizer）[13, 31] 工作流通过生成初始输出并根据评估模型的反馈对其进行精炼，迭代式地改进内容。

**何时使用**：当迭代式精炼能显著提高响应质量时有效，尤其是在存在明确评估标准的情况下。

**示例应用**：

- 通过多轮评估和精炼循环改进文学翻译。
- 进行多轮研究查询，其中额外的迭代会精炼搜索结果。

## 5 Agentic RAG 系统的分类法

智能体式检索增强生成（RAG）系统可以基于其复杂度和设计原则，划分为不同的架构框架。这些框架包括单智能体架构、多智能体系统以及分层式智能体架构。每个框架都针对特定挑战而定制，并为多样化应用优化性能。本节对这些架构进行详细的分类，重点阐述它们的特征、优势和局限。

### 5.1 单智能体 Agentic RAG：路由器（Router）

单智能体 Agentic RAG [32] 充当一个集中式决策系统，其中单个智能体管理信息的检索、路由和整合（如图 16 所示）。这种架构通过将这些任务整合到一个统一智能体中而简化了系统，使其特别适用于工具或数据源数量有限的场景。

**工作流**

1. **查询提交与评估**：当用户提交查询时，流程开始。一个协调智能体（或主检索智能体）接收查询并分析它，以确定最合适的信息来源。
2. **知识来源选择**：根据查询类型，协调智能体从多种检索选项中进行选择：
   - **结构化数据库**：对于需要表格数据访问的查询，系统可以使用文本到 SQL（Text-to-SQL）引擎，与 PostgreSQL 或 MySQL 等数据库交互。
   - **语义搜索**：在处理非结构化信息时，它使用基于向量的检索来获取相关文档（例如 PDF、书籍、组织记录）。
   - **网络搜索**：对于实时或广泛的上下文信息，系统利用网络搜索工具访问最新的在线数据。
   - **推荐系统**：对于个性化或上下文相关的查询，系统利用推荐引擎提供量身定制的建议。
3. **数据整合与大语言模型综合**：一旦从选定来源检索到相关数据，就将其传递给大语言模型（LLM）。大语言模型综合所收集的信息，将来自多个来源的洞见整合成一个连贯且符合上下文的响应。
4. **输出生成**：最后，系统给出一个全面的、面向用户的答案来回应原始查询。该响应以可操作、简洁的格式呈现，并可选择性地包含所使用来源的参考文献或引用。

**关键特征与优势**

- **集中式简洁性**：单个智能体处理所有检索和路由任务，使架构易于设计、实现和维护。
- **效率与资源优化**：由于智能体更少、协调更简单，系统所需计算资源更少，且能更快地处理查询。
- **动态路由**：智能体实时评估每个查询，选择最合适的知识来源（例如结构化数据库、语义搜索、网络搜索）。
- **跨工具通用性**：支持各种数据源和外部 API，从而能够实现结构化和非结构化工作流。
- **适用于更简单的系统**：适合任务定义明确或集成需求有限的应用（例如文档检索、基于 SQL 的工作流）。

**用例：客户支持**

提示：你能告诉我我的订单的配送状态吗？

系统流程（单智能体工作流）：

1. **查询提交与评估**：
   - 用户提交查询，由协调智能体接收。

   - 从订单管理数据库检索跟踪详情。
   - 从承运商的 API 获取实时更新。
   - 可选地进行网络搜索，以识别影响配送的本地状况，例如天气或物流延误。
3. **数据整合与大语言模型综合**：
   - 相关数据被传递给大语言模型，由其将信息综合成一个连贯的响应。
4. **输出生成**：
   - 系统生成一个可操作且简洁的响应，提供实时跟踪更新和潜在的备选方案。

### 5.2 多智能体 Agentic RAG 系统

多智能体 RAG（Multi-Agent RAG）[32] 代表了单智能体架构的一种模块化和可扩展的演进，旨在通过利用多个专门智能体来处理复杂工作流和多样化的查询类型（如图 17 所示）。该系统不再依赖单个智能体来管理所有任务——推理、检索和响应生成——而是将职责分配给多个智能体，每个智能体都针对特定角色或数据源进行了优化。

**工作流**

1. **查询提交**：流程从用户查询开始，由协调智能体或主检索智能体接收。该智能体充当中央编排者，根据查询的需求将查询委派给专门的检索智能体。
2. **专门检索智能体**：查询被分发给多个检索智能体，每个智能体专注于特定类型的数据源或任务。例如：
   - **智能体 1**：处理结构化查询，例如与 PostgreSQL 或 MySQL 等基于 SQL 的数据库交互。
   - **智能体 2**：管理语义搜索，从 PDF、书籍或内部记录等来源检索非结构化数据。
   - **智能体 3**：专注于从网络搜索或 API 检索实时公开信息。
   - **智能体 4**：专门处理推荐系统，根据用户行为或画像提供上下文感知的建议。
3. **工具访问与数据检索**：每个智能体将查询路由到其领域内的适当工具或数据源，例如：
   - **向量搜索**：用于语义相关性。
   - **文本到 SQL（Text-to-SQL）**：用于结构化数据。
   - **网络搜索**：用于实时公开信息。
   - **API**：用于访问外部服务或专有系统。
   
   检索过程并行执行，从而能够高效处理多样化的查询类型。

4. **数据整合与大语言模型综合**：检索完成后，来自所有智能体的数据被传递给大语言模型（LLM）。大语言模型将检索到的信息综合成一个连贯且符合上下文的响应，无缝整合来自多个来源的洞见。
5. **输出生成**：系统生成一个全面的响应，以可操作且简洁的格式返回给用户。

**关键特征与优势**

- **模块化**：每个智能体独立运行，允许根据系统需求无缝添加或移除智能体。
- **可扩展性**：多个智能体的并行处理使系统能够高效处理高查询量。
- **任务专门化**：每个智能体都针对特定类型的查询或数据源进行优化，从而提高准确性和检索相关性。
- **效率**：通过将任务分配给专门智能体，系统最大限度地减少瓶颈，并提升复杂工作流的性能。
- **通用性**：适用于跨多个领域的应用，包括研究、分析、决策和客户支持。

**挑战**

- **协调复杂性**：管理智能体间通信和任务委派需要复杂的编排机制。
- **计算开销**：多个智能体的并行处理可能增加资源使用。
- **数据整合**：将来自多样化来源的输出综合成一个连贯的响应并非易事，需要先进的大语言模型能力。

**用例：多领域研究助手**

提示：在欧洲采用可再生能源会产生哪些经济和环境影响？

系统流程（多智能体工作流）：

- **智能体 1**：使用基于 SQL 的查询从经济数据库检索统计数据。
- **智能体 2**：使用语义搜索工具搜索相关学术论文。
- **智能体 3**：执行网络搜索，查找关于可再生能源的最新新闻和政策更新。
- **智能体 4**：咨询推荐系统，以推荐相关内容，例如报告或专家评论。

响应：

整合响应："根据欧盟政策报告，欧洲采用可再生能源已使过去十年温室气体排放减少了 20%。在经济方面，可再生能源投资已创造约 120 万个就业岗位，其中太阳能和风能领域增长显著。近期学术研究还强调了电网稳定性和储能成本方面的潜在权衡。"

### 5.3 分层式 Agentic RAG 系统

分层式 Agentic RAG（Hierarchical Agentic RAG）[15] 系统采用结构化、多层级的（multi-tiered）方法进行信息检索和处理，如图 18 所示，从而提升效率和战略决策能力。智能体按层级组织，较高层级的智能体监督和指导较低层级的智能体。这种结构能够实现多层级决策，确保查询由最合适的资源来处理。

**工作流**

1. **查询接收**：用户提交查询，由负责初步评估和委派的顶层智能体接收。
2. **战略决策**：顶层智能体评估查询的复杂度，并决定优先使用哪些下级智能体或数据源。根据查询的领域，某些数据库、API 或检索工具可能被认为更可靠或更相关。
3. **向下级智能体委派**：顶层智能体将任务分配给专门处理特定检索方法（例如 SQL 数据库、网络搜索或专有系统）的下级智能体。这些智能体独立执行分配给它们的任务。
4. **汇总与综合**：下级智能体的结果由较高层级的智能体收集和整合，由其将信息综合成一个连贯的响应。
5. **响应交付**：最终综合出的答案返回给用户，确保响应既全面又符合上下文。

**关键特征与优势**

- **战略优先排序**：顶层智能体可以根据查询复杂度、可靠性或上下文对数据源或任务进行优先排序。
- **可扩展性**：跨多个智能体层级分配任务，能够处理高度复杂或多面向的查询。
- **增强的决策能力**：较高层级的智能体施加战略监督，以提高响应的整体准确性和连贯性。

**挑战**

- **协调复杂性**：跨多个层级维持稳健的智能体间通信，可能增加编排开销。
- **资源分配**：在各层级之间高效分配任务以避免瓶颈，并非易事。

**用例：金融分析系统**

提示：鉴于当前可再生能源的市场趋势，最佳的投资选择是什么？

系统流程（分层式智能体工作流）：

1. **顶层智能体**：评估查询的复杂度，并优先使用可靠的金融数据库和经济指标，而非验证程度较低的数据源。
2. **中层智能体**：从专有 API 和结构化 SQL 数据库检索实时市场数据（例如股价、板块表现）。
3. **下级智能体**：执行网络搜索以查找最新政策公告，并咨询跟踪专家观点和新闻分析的推荐系统。
4. **汇总与综合**：顶层智能体汇总结果，将定量数据与政策洞见整合。

响应：

整合响应："根据当前市场数据，可再生能源股票在过去一个季度上涨了 15%，这得益于支持性政府政策和投资者兴趣的升温。分析师认为，风能和太阳能板块尤其可能保持增长势头，而绿氢等新兴技术则呈现中等风险但潜在高回报。"

### 5.4 智能体式纠错 RAG（Agentic Corrective RAG）

纠错 RAG（Corrective RAG）引入了自我纠正检索结果的机制，从而增强文档利用并提高响应生成质量，如图 19 所示。通过将智能智能体嵌入工作流，纠错 RAG [33] [34] 确保对上下文文档和响应进行迭代式精炼，最大限度地减少错误并最大化相关性。

**纠错 RAG 的核心思想**：纠错 RAG 的核心原理在于其能够动态评估检索到的文档、执行纠正操作并精炼查询，以提高生成响应的质量。纠错 RAG 按如下方式调整其方法：

- **文档相关性评估**：检索到的文档由相关性评估智能体（Relevance Evaluation Agent）评估相关性。低于相关性阈值的文档会触发纠正步骤。
- **查询精炼与增强**：查询由查询精炼智能体（Query Refinement Agent）精炼，该智能体利用语义理解来优化检索以获得更好的结果。
- **从外部来源进行动态检索**：当上下文不足时，外部知识检索智能体（External Knowledge Retrieval Agent）执行网络搜索或访问替代数据源，以补充检索到的文档。
- **响应综合**：所有经过验证和精炼的信息被传递给响应综合智能体（Response Synthesis Agent），以进行最终的响应生成。

**工作流**：纠错 RAG 系统建立在五个关键智能体之上：

1. **上下文检索智能体（Context Retrieval Agent）**：负责从向量数据库检索初始上下文文档。
2. **相关性评估智能体（Relevance Evaluation Agent）**：评估检索到的文档的相关性，并标记任何不相关或模糊的文档以进行纠正操作。
3. **查询精炼智能体（Query Refinement Agent）**：改写查询以改进检索，利用语义理解优化结果。
4. **外部知识检索智能体（External Knowledge Retrieval Agent）**：当上下文文档不足时，执行网络搜索或访问替代数据源。
5. **响应综合智能体（Response Synthesis Agent）**：将所有经过验证的信息综合成一个连贯且准确的响应。

**关键特征与优势**

- **迭代式纠正**：通过动态识别和纠正不相关或模糊的检索结果，确保高响应准确性。
- **动态自适性**：纳入实时网络搜索和查询精炼，以提高检索精度。
- **智能体式模块化**：每个智能体执行专门任务，确保高效和可扩展的运行。
- **事实性保证**：通过验证所有检索和生成的内容，纠错 RAG 最大限度地降低幻觉或错误信息的风险。

**用例：学术研究助手**

提示：生成式人工智能研究的最新发现是什么？

系统流程（纠错 RAG 工作流）：

1. **查询提交**：用户向系统提交查询。
2. **上下文检索**：
   - 上下文检索智能体从已发表的生成式人工智能论文数据库中检索初始文档。
   - 检索到的文档被传递给下一步进行评估。
3. **相关性评估**：
   - 相关性评估智能体评估文档与查询的一致性。
   - 文档被分类为相关、模糊或不相关类别。不相关的文档被标记以进行纠正操作。
4. **纠正操作（如需要）**：
   - 查询精炼智能体改写查询以提高针对性和相关性。
   - 外部知识检索智能体执行网络搜索，从外部来源获取更多论文和报告。
5. **响应综合**：
   - 响应综合智能体将经过验证的文档整合成一个连贯且全面的摘要。

响应：

整合响应："生成式人工智能的最新发现凸显了扩散模型、用于文本到视频任务的强化学习以及大规模模型训练优化技术方面的进展。更多详情请参阅 NeurIPS 2024 和 AAAI 2025 上发表的研究。"

### 5.5 自适应 Agentic RAG（Adaptive Agentic RAG）

自适应检索增强生成（Adaptive Retrieval-Augmented Generation，Adaptive RAG）[35] 通过根据传入查询的复杂度动态调整查询处理策略，增强了大语言模型（LLMs）的灵活性和效率。与静态检索工作流不同，自适应 RAG [36] 采用一个分类器来评估查询复杂度，并确定最合适的方法，其范围从单步检索到多步推理，甚至对简单直接的查询完全跳过检索，如图 20 所示。

**自适应 RAG 的核心思想**：自适应 RAG 的核心原理在于其能够根据查询的复杂度动态地定制检索策略。自适应 RAG 按如下方式调整其方法：

- **简单直接的查询**：对于无需额外检索的基于事实的问题（例如"水的沸点是多少？"），系统直接使用已有知识生成答案。
- **简单查询**：对于需要最少上下文的适度复杂任务（例如"我最近的电费账单状态如何？"），系统执行单步检索以获取相关详情。
- **复杂查询**：对于需要迭代式推理的多层查询（例如"X 市的人口在过去十年中发生了怎样的变化，促成因素有哪些？"），系统采用多步检索，逐步精炼中间结果以提供全面的答案。

**工作流**：自适应 RAG 系统建立在三个主要组件之上：

1. **分类器角色**：
   - 一个较小的语言模型分析查询以预测其复杂度。
   - 该分类器使用自动标注的数据集进行训练，这些数据集来自过去的模型结果和查询模式。
2. **动态策略选择**：
   - 对于简单直接的查询，系统避免不必要的检索，直接利用大语言模型进行响应生成。
   - 对于简单查询，它采用单步检索过程来获取相关上下文。
   - 对于复杂查询，它激活多步检索以确保迭代式精炼和增强的推理。
3. **大语言模型整合**：
   - 大语言模型将检索到的信息综合成一个连贯的响应。
   - 大语言模型与分类器之间的迭代式交互能够对复杂查询进行精炼。

**关键特征与优势**

- **动态自适性**：根据查询复杂度调整检索策略，优化计算效率和响应准确性。
- **资源效率**：对简单查询最大限度地减少不必要的开销，同时确保对复杂查询的彻底处理。
- **增强的准确性**：迭代式精炼确保复杂查询以高精度得到解决。
- **灵活性**：可以扩展以纳入额外的路径，例如领域特定的工具或外部 API。

**用例：客户支持助手**

提示：为什么我的包裹延误了，我有哪些备选方案？

系统流程（自适应 RAG 工作流）：

1. **查询分类**：
   - 分类器分析查询，确定其为复杂查询，需要多步推理。
2. **动态策略选择**：
   - 系统根据复杂度分类激活多步检索过程。
3. **多步检索**：
   - 从订单数据库检索跟踪详情。
   - 从承运商 API 获取实时状态更新。
   - 执行网络搜索，查找天气状况或本地中断等外部因素。
4. **响应综合**：
   - 大语言模型整合所有检索到的信息，综合出一个全面且可操作的响应。

响应：

整合响应："由于您所在地区的恶劣天气，您的包裹延误了。它目前位于本地分拣中心，将在 2 天内送达。或者，您可以选择在网点自提。"

### 5.6 基于图的 Agentic RAG

#### 5.6.1 Agent-G：用于图 RAG 的智能体框架

Agent-G [8] 引入了一种新颖的智能体架构，将图知识库与非结构化文档检索相整合。通过结合结构化和非结构化数据源，该框架以改进的推理和检索准确性增强了检索增强生成（RAG）系统。它采用模块化检索器库、动态智能体交互和反馈循环来确保高质量输出，如图 21 所示。

**Agent-G 的核心思想**：Agent-G 的核心原理在于其能够动态地将检索任务分配给专门智能体，同时利用图知识库和文本文档。Agent-G 按如下方式调整其检索策略：

- **图知识库**：结构化数据被用于抽取关系、层次结构和连接（例如医疗保健中的疾病到症状映射）。
- **非结构化文档**：传统文本检索系统提供上下文信息以补充图数据。
- **批判模块（Critic Module）**：评估检索信息的质量和相关性，确保与查询对齐。
- **反馈循环**：通过迭代式验证和重新查询来精炼检索与综合。

**工作流**：Agent-G 系统建立在四个主要组件之上：

1. **检索器库（Retriever Bank）**：
   - 一组模块化智能体专门负责检索基于图的或非结构化的数据。
   - 智能体根据查询的需求动态选择相关来源。
2. **批判模块（Critic Module）**：
   - 验证检索数据的相关性和质量。
   - 标记低置信度结果以进行重新检索或精炼。
3. **动态智能体交互**：
   - 面向特定任务的智能体协作以整合多样化的数据类型。
   - 确保图来源与文本来源之间的检索和综合保持连贯。
4. **大语言模型整合**：
   - 将经过验证的数据综合成一个连贯的响应。
   - 来自批判模块的迭代式反馈确保与查询意图对齐。

**关键特征与优势**

- **增强的推理**：将来自图的结构化关系与来自非结构化文档的上下文信息相结合。
- **动态自适性**：根据查询需求动态调整检索策略。
- **提高的准确性**：批判模块降低响应中出现不相关或低质量数据的风险。
- **可扩展的模块化**：支持为专门任务添加新智能体，从而增强可扩展性。

**用例：医疗诊断**

提示：2 型糖尿病的常见症状有哪些，它们与心脏病有何关联？

系统流程（Agent-G 工作流）：

1. **查询接收与分配**：系统接收查询，并确定需要同时使用图结构化和非结构化数据来全面回答问题。
2. **图检索器**：
   - 从医学知识图谱中抽取 2 型糖尿病与心脏病之间的关系。
   - 通过探索图层次结构和关系，识别肥胖和高血压等共同风险因素。
3. **文档检索器**：
   - 从医学文献中检索 2 型糖尿病症状的描述（例如口渴增多、尿频、疲劳）。
   - 添加上下文信息以补充基于图的洞见。
4. **批判模块**：
   - 评估检索到的图数据和文档数据的相关性和质量。
   - 标记低置信度结果以进行精炼或重新查询。
5. **响应综合**：大语言模型将来自图检索器和文档检索器的经过验证的数据整合成一个连贯的响应，确保与查询意图对齐。

响应：

整合响应："2 型糖尿病的症状包括口渴增多、尿频和疲劳。研究表明糖尿病与心脏病之间存在 50% 的相关性，主要通过肥胖和高血压等共同风险因素起作用。"

#### 5.6.2 GeAR：用于检索增强生成的图增强智能体

GeAR [37] 引入了一个智能体框架，通过纳入基于图的检索机制来增强传统的检索增强生成（RAG）系统。通过利用图扩展技术和基于智能体的架构，GeAR 应对多跳检索场景中的挑战，提升系统处理复杂查询的能力，如图 22 所示。

**GeAR 的核心思想**：GeAR 通过两项主要创新提升 RAG 性能：

- **图扩展（Graph Expansion）**：通过将检索过程扩展为包含图结构化数据，增强传统的基础检索器（例如 BM25），使系统能够捕捉实体之间的复杂关系和依赖。
- **智能体框架（Agent Framework）**：纳入一个基于智能体的架构，利用图扩展更有效地管理检索任务，从而在检索过程中实现动态和自主的决策。

**工作流**：GeAR 系统通过以下组件运行：

1. **图扩展模块（Graph Expansion Module）**：
   - 将基于图的数据整合到检索过程中，使系统在检索期间能够考虑实体之间的关系。
   - 通过将搜索空间扩展到相连实体，增强基础检索器处理多跳查询的能力。
2. **基于智能体的检索（Agent-Based Retrieval）**：
   - 采用智能体框架来管理检索过程，能够根据查询复杂度动态选择和组合检索策略。
   - 智能体可以自主决定利用图扩展的检索路径，以提高检索信息的相关性和准确性。
3. **大语言模型整合**：
   - 将经图扩展而丰富化的检索信息与大语言模型（LLM）的能力相结合，生成连贯且符合上下文的响应。
   - 这种整合确保生成过程同时受到非结构化文档和结构化图数据的启发。

**关键特征与优势**

- **增强的多跳检索**：GeAR 的图扩展使系统能够处理需要在多个相互关联的信息片段之间进行推理的复杂查询。
- **智能体式决策**：智能体框架能够动态和自主地选择检索策略，提高效率和相关性。
- **提高的准确性**：通过纳入结构化图数据，GeAR 增强了检索信息的精确性，从而产生更准确、更符合上下文的响应。
- **可扩展性**：智能体框架的模块化特性允许根据需要整合额外的检索策略和数据源。

**用例：多跳问答**

提示：哪位作者影响了 J.K. 罗琳的导师？

系统流程（GeAR 工作流）：

1. **顶层智能体**：评估查询的多跳性质，并确定需要结合图扩展和文档检索来回答问题。
2. **图扩展模块**：
   - 识别出 J.K. 罗琳的导师是查询中的一个关键实体。
   - 通过探索关于文学关系的图结构化数据，追溯该导师所受的文学影响。
3. **基于智能体的检索**：
   - 一个智能体自主选择图扩展的检索路径，以收集关于该导师所受影响的相关信息。
   - 通过查询文本数据源来整合额外上下文，以获取关于该导师及其所受影响的非结构化详情。
4. **响应综合**：利用大语言模型结合来自图检索和文档检索过程的洞见，生成一个准确反映查询中复杂关系的响应。

响应：

整合响应："J.K. 罗琳的导师 [导师姓名] 深受 [作者姓名] 的影响，后者以其 [著名作品或体裁] 而闻名。这种关联凸显了文学史上层层递进的关系，其中有影响力的思想常常历经多代作者传承。"

### 5.7 Agentic RAG 中的智能体文档工作流

智能体文档工作流（Agentic Document Workflows，ADW）[38] 通过实现端到端的知识工作自动化，扩展了传统的检索增强生成（RAG）范式。这些工作流编排复杂的以文档为中心的过程，将文档解析、检索、推理和结构化输出与智能智能体相整合（见图 23）。ADW 系统通过维护状态、协调多步工作流并对文档应用领域特定逻辑，解决了智能文档处理（Intelligent Document Processing，IDP）和 RAG 的局限。

**工作流**

1. **文档解析与信息结构化**：
   - 使用企业级工具（例如 LlamaParse）解析文档，以抽取发票编号、日期、供应商信息、行项目和付款条款等相关数据字段。
   - 对结构化数据进行组织，以便下游处理。
2. **跨过程的状态维护**：
   - 系统维护关于文档上下文的状态，确保多步工作流中的一致性和相关性。
   - 跟踪文档在各个处理阶段的进展。
3. **知识检索**：
   - 从外部知识库（例如 LlamaCloud）或向量索引中检索相关参考文献。
   - 检索实时的、领域特定的指南，以增强决策。
4. **智能体式编排**：
   - 智能智能体应用业务规则、执行多跳推理并生成可操作的建议。
   - 编排解析器、检索器和外部 API 等组件，实现无缝整合。
5. **可操作输出生成**：
   - 输出以结构化格式呈现，并针对特定用例进行定制。
   - 将建议和抽取的洞见综合成简洁且可操作的报告。

**用例：发票付款工作流**

提示：根据提交的发票和相关的供应商合同条款，生成一份付款建议报告。

系统流程（ADW 工作流）：

1. 解析发票以抽取关键详情，例如发票编号、日期、供应商信息、行项目和付款条款。
2. 检索相应的供应商合同以核实付款条款，并识别任何适用的折扣或合规要求。
3. 生成一份付款建议报告，包括原始应付款项、潜在的提前付款折扣、预算影响分析和战略性付款行动。

响应：整合响应："发票 INV-2025-045，金额 15,000.00 美元，已处理。若在 2025-04-10 前付款，可享受 2% 的提前付款折扣，应付款项降至 14,700.00 美元。由于小计超过 10,000.00 美元，已应用 5% 的批量订单折扣。建议批准提前付款，以节省 2% 并为即将到来的项目阶段确保及时的资金分配。"

**关键特征与优势**

- **状态维护**：跟踪文档上下文和工作流阶段，确保跨过程的一致性。
- **多步编排**：处理涉及多个组件和外部工具的复杂工作流。
- **领域特定智能**：应用定制的业务规则和指南，提供精确的建议。
- **可扩展性**：通过模块化和动态的智能体集成，支持大规模文档处理。
- **提升的生产力**：自动化重复性任务，同时在决策中增强人类专业知识。

## 7 Agentic RAG 的应用

智能体式检索增强生成（RAG）系统已在多个领域展现出变革性潜力。通过结合实时数据检索、生成能力和自主决策，这些系统应对了复杂、动态和多模态的挑战。本节探讨 Agentic RAG 的关键应用，深入阐述这些系统如何塑造客户支持、医疗保健、金融、教育、法律工作流和创意产业等行业。

### 7.1 客户支持与虚拟助手

Agentic RAG 系统通过实现实时、上下文感知的查询解析，正在革新客户支持。传统聊天机器人和虚拟助手通常依赖静态知识库，导致泛泛或过时的响应。相比之下，Agentic RAG 系统动态检索最相关的信息，适应用户的上下文，并生成个性化的响应。

**用例：Twitch 广告销售增强 [39]**

例如，Twitch 在 Amazon Bedrock 上利用带 RAG 的智能体工作流来简化广告销售。该系统动态检索广告商数据、历史广告活动表现和受众人口统计数据，以生成详细的广告提案，显著提升了运营效率。

**关键收益**：

- **提高的响应质量**：个性化和上下文感知的回复增强了用户参与度。
- **运营效率**：通过自动化复杂查询，减少对人类支持客服的工作负担。
- **实时自适性**：动态整合不断演变的数据，例如实时服务中断或定价更新。

### 7.2 医疗保健与个性化医疗

在医疗保健领域，将患者特定数据与最新医学研究相整合，对于明智的决策至关重要。Agentic RAG 系统通过检索实时临床指南、医学文献和患者病史来实现这一点，以协助临床医生进行诊断和治疗规划。

**用例：患者病例摘要 [40]**

Agentic RAG 系统已被应用于生成患者病例摘要。例如，通过整合电子健康记录（EHR）和最新的医学文献，该系统为临床医生生成全面的摘要，以便他们做出更快、更明智的决策。

**关键收益**：

- **个性化照护**：根据患者个体需求量身定制建议。
- **时间效率**：简化相关研究的检索，为医疗服务提供者节省宝贵时间。
- **准确性**：确保建议基于最新证据和患者特定参数。

### 7.3 法律与合同分析

Agentic RAG 系统正在重新定义法律工作流的开展方式，为快速文档分析和决策提供工具。

**用例：合同审查 [41]**

一个法律领域的 Agentic RAG 系统可以分析合同、抽取关键条款并识别潜在风险。通过将语义搜索能力与法律知识图谱相结合，它自动化了繁琐的合同审查过程，确保合规并降低风险。

**关键收益**：

- **风险识别**：自动标记偏离标准条款的条款。
- **效率**：减少合同审查过程所花费的时间。
- **可扩展性**：同时处理大量合同。

### 7.4 金融与风险分析

Agentic RAG 系统通过为投资决策、市场分析和风险管理提供实时洞见，正在变革金融行业。这些系统整合实时数据流、历史趋势和预测建模，生成可操作的输出。

**用例：汽车保险理赔处理 [42]**

在汽车保险中，Agentic RAG 可以自动化理赔处理。例如，通过检索保单详情并将其与事故数据相结合，它在确保符合监管要求的同时生成理赔建议。

**关键收益**：

- **实时分析**：基于实时市场数据提供洞见。
- **风险缓解**：利用预测分析和多步推理识别潜在风险。
- **增强的决策**：结合历史数据和实时数据，形成全面的策略。

### 7.5 教育与个性化学习

教育是 Agentic RAG 系统正在取得重大进展的另一个领域。这些系统通过生成针对学习者进度和偏好量身定制的解释、学习材料和反馈，实现自适应学习。

**用例：研究论文生成 [43]**

在高等教育中，Agentic RAG 已被用于通过综合来自多个来源的关键发现来辅助研究人员。例如，一位研究者查询"量子计算的最新进展是什么？"，会收到一份带有参考文献的简洁摘要，从而提升其工作的质量和效率。

**关键收益**：

- **定制化的学习路径**：根据学生个体需求及其表现水平调整内容。
- **有吸引力的互动**：提供交互式解释和个性化反馈。
- **可扩展性**：支持多样化教育环境的大规模部署。

### 7.6 多模态工作流中的图增强应用

图增强 Agentic RAG（GEAR）将图结构与检索机制相结合，使其在相互关联的数据源至关重要的多模态工作流中尤为有效。

**用例：市场调查生成**

GEAR 能够为营销活动综合文本、图像和视频。例如，查询"环保产品的新兴趋势是什么？"，会生成一份丰富的报告，其中包含客户偏好、竞品分析和多媒体内容。

**关键收益**：

- **多模态能力**：整合文本、图像和视频数据，产生全面的输出。
- **增强的创造力**：为营销和娱乐生成创新的想法和解决方案。
- **动态自适性**：适应不断演变的市场趋势和客户需求。

Agentic RAG 系统的应用涵盖广泛的行业，展示了它们的通用性和变革潜力。从个性化客户支持到自适应教育以及图增强的多模态工作流，这些系统应对了复杂、动态和知识密集型的挑战。通过整合检索、生成和智能体智能，Agentic RAG 系统正在为下一代人工智能应用铺平道路。

## 8 用于 Agentic RAG 的工具与框架

智能体式检索增强生成（RAG）系统代表了检索、生成和智能体智能相结合的重大演进。这些系统通过整合决策、查询改写和自适应工作流，扩展了传统 RAG 的能力。以下工具和框架为开发 Agentic RAG 系统提供了稳健的支持，满足了现实世界应用的复杂需求。

**关键工具与框架**：

- **LangChain 与 LangGraph**：LangChain [44] 提供了用于构建 RAG 流水线的模块化组件，无缝整合检索器、生成器和外部工具。LangGraph 通过引入支持循环、状态持久化和人在环（human-in-the-loop）交互的基于图的工作流加以补充，从而在智能体系统中实现复杂的编排和自我纠正机制。
- **LlamaIndex**：LlamaIndex [45] 的智能体文档工作流（ADW）实现了文档处理、检索和结构化推理的端到端自动化。它引入了一种元智能体（meta-agent）架构，其中子智能体管理较小的文档集，并通过一个顶层智能体进行协调，以完成合规分析和上下文理解等任务。
- **Hugging Face Transformers 与 Qdrant**：Hugging Face [46] 提供用于嵌入和生成任务的预训练模型，而 Qdrant [47] 通过自适应向量搜索能力增强检索工作流，允许智能体通过在稀疏和稠密向量方法之间动态切换来优化性能。
- **CrewAI 与 AutoGen**：这些框架强调多智能体架构。CrewAI [48] 支持分层和顺序过程、稳健的记忆系统以及工具集成。AG2 [49]（前身为 AutoGen [50, 51]）在多智能体协作方面表现出色，对代码生成、工具执行和决策具有先进支持。
- **OpenAI Swarm 框架**：一个面向符合人体工学的、轻量级多智能体编排而设计的教育框架 [52]，强调智能体自主性和结构化协作。
- **基于 Vertex AI 的 Agentic RAG**：由 Google 开发的 Vertex AI [53] 与智能体式检索增强生成（RAG）无缝整合，提供一个构建、部署和扩展机器学习模型的平台，同时利用先进的人工智能能力来实现稳健的、上下文感知的检索和决策工作流。
- **Semantic Kernel**：Semantic Kernel [54, 55] 是微软的一个开源 SDK，将大语言模型（LLMs）整合到应用中。它支持智能体模式，能够创建自主人工智能智能体，用于自然语言理解、任务自动化和决策。它已被用于 ServiceNow 的 P1 事件管理（P1 incident management）等场景，以促进实时协作、自动化任务执行并无缝检索上下文信息。
- **用于 Agentic RAG 的 Amazon Bedrock**：Amazon Bedrock [39] 为实现智能体式检索增强生成（RAG）工作流提供了稳健的平台。
- **IBM Watson 与 Agentic RAG**：IBM 的 watsonx.ai [56] 支持构建 Agentic RAG 系统，其例证是使用 Granite-3-8B-Instruct 模型，通过整合外部信息并增强响应准确性来回答复杂查询。
- **Neo4j 与向量数据库**：Neo4j 是一个著名的开源图数据库，擅长处理复杂关系和语义查询。除 Neo4j 外，Weaviate、Pinecone、Milvus 和 Qdrant 等向量数据库提供高效的相似性搜索和检索能力，构成了高性能智能体式检索增强生成（RAG）工作流的骨干。

## 10 经验教训与实践指导

基于对范式、分类法和现实世界用例的分析，本节为设计、评估和部署 Agentic RAG 系统提炼实践洞见。

### 10.1 Agentic RAG 并非始终是正确的默认选择

Agentic RAG 不应被视为传统 RAG 的普遍替代品。虽然它提供了卓越的自适性和多步推理，但它也引入了协调复杂性、延迟和计算成本。对于简单的事实检索或范围明确的查询，模块化 RAG 流水线以较低的开销提供足够的性能。从业者应根据任务复杂度，有选择性地采用智能体式设计。

### 10.2 架构选择强烈影响系统行为

不同的架构会导致根本不同的行为。单智能体系统偏向简洁性；多智能体系统能够实现并行化，但需要编排；分层式架构以复杂性为代价引入监督。架构决策隐式地编码了关于控制、信任和错误容忍度的假设——纠错式工作流提高准确性但增加延迟，而自适应架构则以正确性保证换取响应速度。

### 10.3 检索质量仍是主要瓶颈

智能体推理无法弥补持续糟糕的检索。失败往往源于检索覆盖不足、索引构建不当，或结构化与非结构化知识的整合不充分。在引入智能体复杂性之前，投资稳健的检索流水线和高质量的索引仍然至关重要。

### 10.4 智能体自主性需要明确的约束

不受约束的自主性可能带来过度调用工具、冗余的推理循环或目标错位的风险。有效的系统通过在有限的规划视野（planning horizons）、预定义的工具访问策略和明确的停止条件之间取得平衡来约束自主性。受约束的自主性会产生更可靠的结果，尤其是在生产环境中。

### 10.5 评估必须关注过程，而不仅仅是结果

现有基准聚焦于输出质量，对中间决策的可见性有限。有意义的评估需要过程级指标，以捕捉推理效率、工具使用模式以及对变化上下文的适应能力。没有这样的评估，改进就可能是零散的，而非系统性的。

### 10.6 领域知识显著放大智能体收益

Agentic RAG 在具有结构化知识和明确约束的领域中取得最强劲的收益。医疗保健、金融和法律分析尤其受益于将检索与基于规则的推理和图结构化知识相结合。开放域任务的收益较为有限，这凸显了领域建模作为 Agentic RAG 设计的补充性组成部分。

### 10.7 迈向 Agentic RAG 的负责任部署

Agentic RAG 在透明性、问责制和信任方面带来了挑战。多智能体协作使错误归因复杂化，而自主工具使用则引发了安全关切。负责任的部署需要治理机制、人类监督和明确的运营边界。可解释性、可追溯性和可审计性必须成为一流的设计目标，尤其是在高风险应用中。

  专为 Agentic RAG 量身定制，评估跨知识库的动态信息综合。

- **HotpotQA**：一个多跳问答基准，需要在相互关联的上下文上进行检索和推理，适用于评估复杂的 RAG 工作流 [63]。
- **RAGBench**：一个大规模、可解释的基准，涵盖跨领域的 10 万个示例，使用 TRACe 框架进行可操作的 RAG 评估 [64]。
- **BERGEN（检索增强生成基准）**：一个通过标准化实验系统地基准测试 RAG 系统的库 [65]。
- **FlashRAG 工具包**：实现多种 RAG 方法和基准数据集，以支持高效和标准化的评估 [66]。
- **GNN-RAG**：在节点级和边级预测任务上评估基于图的 RAG 系统，聚焦于知识图谱问答中的检索质量和推理性能 [67]。

## 12 Agentic RAG 的开放研究问题与未来挑战

尽管 Agentic RAG 取得了快速进展，该领域仍处于成熟早期。虽然现有系统展示了相较传统 RAG 流水线的明显优势，它们也暴露出各种尚未解决的研究挑战，必须加以解决才能在现实世界环境中实现稳健、可扩展和可信赖的部署。本节概述关键的开放研究问题，并阐述 Agentic RAG 系统的长期研究愿景。

### 12.1 智能体协调、控制与涌现行为

随着系统扩展到多智能体和分层式框架，涌现行为变得难以预测。当前的编排依赖启发式规则和提示工程，收敛保证有限。未来的研究必须解决部分可观测性和目标冲突下的协调问题，正式建模智能体间的依赖关系，防止级联失败，并确保可验证的协作结果。

### 12.2 超越输出质量的评估方法论

输出级指标（答案正确性、检索准确性）对 Agentic RAG 而言是不充分的，因为中间决策会塑造性能。需要标准化基准来评估推理轨迹、规划深度、自适性、噪声检索下的鲁棒性以及成本效率。评估答案如何产生的过程感知型（process-aware）评估，对于系统性进展至关重要。

### 12.3 记忆管理与长期适应

长期记忆设计仍是一个开放挑战。持久记忆存在知识漂移和偏见强化的风险，而频繁更新则可能放大幻觉。关键问题包括在持久性与自适性之间取得平衡、选择性保留，以及协调外部知识与已存储的智能体经验。

### 12.4 计算成本、效率与可持续性

多智能体协作和迭代式检索增加了延迟和资源消耗。未来的研究必须探索成本感知的规划、自适应推理和轻量级协调——根据任务复杂度动态调整活跃智能体、有选择性地调用工具并优化检索深度。

### 12.5 自主 RAG 系统中的安全、信任与治理

自主智能体可能引入包括未授权操作和有偏决策在内的失效模式。在多智能体场景中，追踪责任尤为困难。开放方向包括透明的决策追踪、人在环监督，以及确保高风险应用中智能体目标与人类意图保持一致的治理框架。

### 12.6 跨领域与跨任务的泛化

大多数现有 Agentic RAG 系统在领域特定场景或精心策划的基准上进行评估。这些系统在具有不同数据特征、监管约束或推理要求的领域之间的泛化能力如何，仍不清楚。设计无需大量任务特定调优即可调整其检索和推理策略的智能体，是一个开放问题。未来工作应聚焦于开发领域无关的智能体抽象、可迁移的规划策略，以及能够泛化到狭窄应用情境之外的自适应检索策略。实现稳健的跨领域泛化，对于充分发挥 Agentic RAG 作为通用推理框架的潜力至关重要。

---

## 13 结论

Agentic RAG 代表了从静态 RAG 流水线向自主、自适应推理框架的重大演进。本综述考察了 RAG 基础、智能体智能的整合以及定义现代 Agentic RAG 系统的架构模式。通过基于智能体数量、控制结构、自主性和知识表示的原则性分类法来组织各种方法，本工作为这一碎片化的领域提供了一个结构化的视角。分析表明，没有单一架构是普遍最优的；有效性取决于使复杂性与任务需求相匹配。Agentic RAG 在医疗保健、金融、教育和企业处理等复杂、知识密集型任务中具有明显优势，但这些优势需要高质量的检索基础、有纪律的自主性和精心的编排。

在多智能体协调、过程感知评估、记忆管理、计算效率和治理方面，仍有大量开放挑战。本综述整合了现有工作，引入了一个统一框架，并阐明了设计权衡和研究方向，以推动 Agentic RAG 领域的发展。

### 表 1：RAG 范式的比较分析

| 范式 | 关键特征 | 优势 |
|------|---------|------|
| 朴素 RAG（Naïve RAG） | 基于关键词的检索（例如 TF-IDF、BM25） | 简单且易于实现；适用于基于事实的查询 |
| 高级 RAG（Advanced RAG） | 稠密检索模型（例如 DPR）；神经排序与重排序；多跳检索 | 高精度检索；改进的上下文相关性 |
| 模块化 RAG（Modular RAG） | 混合检索（稀疏与稠密）；工具与 API 集成；可组合的、领域特定的流水线 | 高灵活性与可定制性；适用于多样化应用；可扩展 |
| 图 RAG（Graph RAG） | 基于图结构的集成；多跳推理；通过节点的上下文丰富化 | 关系推理能力；缓解幻觉；适用于结构化数据任务 |
| 智能体式 RAG（Agentic RAG） | 自主智能体；动态决策；迭代式精炼与工作流优化 | 适应实时变化；可扩展以处理多领域任务；高准确性 |

### 表 2：比较分析：传统 RAG vs Agentic RAG vs 智能体文档工作流（ADW）

| 特征 | 传统 RAG | Agentic RAG | 智能体文档工作流（ADW） |
|------|---------|-------------|------------------------|
| 侧重点（Focus） | 孤立的检索和生成任务 | 多智能体协作与推理 | 以文档为中心的端到端工作流 |
| 上下文维护 | 有限 | 通过记忆模块实现 | 跨多步工作流维护状态 |
| 动态自适性 | 极低 | 高 | 针对文档工作流定制 |
| 工作流编排 | 无 | 编排多智能体任务 | 整合多步文档处理 |
| 外部工具/API 的使用 | 基础集成（例如检索工具） | 通过 API 和知识库等工具扩展 | 深度整合业务规则和领域特定工具 |
| 可扩展性 | 限于小型数据集或查询 | 可扩展以支持多智能体系统 | 可扩展以支持多领域企业工作流 |
| 复杂推理 | 基础（例如简单问答） | 借助智能体进行多步推理 | 跨文档的结构化推理 |
| 主要应用 | 问答系统、知识检索 | 多领域知识与推理 | 合同审查、发票处理、理赔分析 |
| 优势 | 简洁、快速搭建 | 高准确性、协作式推理 | 端到端自动化、领域特定智能 |
| 挑战 | 上下文理解差 | 协调复杂性 | 资源开销、领域标准化 |

### 表 3：基于分类法的 Agentic RAG 架构比较

| 维度 | 单智能体 RAG | 多智能体 RAG | 分层式/纠错式 RAG | 基于图/以文档为中心的 RAG |
|------|-------------|-------------|------------------|--------------------------|
| 智能体数量（Agent Cardinality） | 单个 | 多个 | 多个（分层） | 多个 |
| 控制结构（Control Structure） | 集中式 | 扁平式 | 分层式/基于评估器 | 自适应/结构化 |
| 知识表示（Knowledge Representation） | 非结构化 | 非结构化或混合 | 非结构化或混合 | 基于图或以文档为中心 |
| 知识依赖（Knowledge Dependency） | 低 | 中等 | 中等 | 高，对图质量敏感 |
| 推理模式（Reasoning Mode） | 隐式、大语言模型驱动 | 分布于智能体之间 | 带监督控制的战略性 | 关系式或符号式 + 大语言模型 |
| 推理深度（Reasoning Depth） | 低到中等 | 中等到高 | 高 | 高，多跳推理 |
| 检索自适性（Retrieval Adaptivity） | 有限 | 高 | 高 | 高 |
| 可扩展性（Scalability） | 中等 | 高 | 中等 | 中等 |
| 延迟（Latency） | 低 | 中等 | 高 | 中等到高 |
| 工程复杂性（Engineering Complexity） | 低 | 中等 | 高 | 高 |
| 最佳适用场景（Best-Fit Scenarios） | 简单问答与路由 | 多领域综合 | 高风险、可靠性关键任务 | 知识密集、关系型领域 |
