## 摘要

从开放式主题生成长篇线性小说，对大语言模型而言仍是一项重大挑战——当采用基于前提（premise）或线性大纲的方法时，模型常常无法保证全局结构与叙事多样性。我们提出 BiT-MCTS，一个由主题驱动的框架，它将受弗雷塔格金字塔（Freytag's Pyramid）启发的"高潮优先、双向扩展"策略付诸实施。给定一个主题，我们的方法提取核心戏剧冲突并生成一个显式的高潮，随后采用双向蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）向后（上升动作、开场）和向前（下降动作、结局）扩展情节，从而产出一个结构化的大纲。最后一个生成阶段将精炼后的大纲落实为完整的叙事。我们构建了一个中文主题语料库用于评估，并在三个当代 LLM 骨干模型上进行了广泛的实验。结果表明，相对于强基线，BiT-MCTS 提升了叙事连贯性、情节结构与主题深度，同时根据自动指标与人工评判，实现了篇幅显著更长、更加连贯的故事。

## 1 引言

大语言模型（LLM）在文本生成方面取得了长足进步，尤其是在故事生成领域，展现出其在人工智能领域的潜力（Liu and Singh, 2002; Ammanabrolu and Riedl, 2018; Yang et al., 2023; Kumar, 2024）。然而，小说生成任务仍然是一项艰巨的挑战。与一般的故事生成不同，小说不仅要求情节连贯、引人入胜，还要求遵循更高的文学标准，包括运用精妙的文学手法以及发展核心主题。

小说生成面临若干关键挑战：

**（1）复杂的叙事结构：** LLM 本质上难以设计出人类文学作品所特有的精妙叙事框架与情感互动（Tian et al., 2024）。当前的方法往往依赖于顺序式大纲生成（Yao et al., 2019; Tian et al., 2024），这可能导致过于公式化的叙事。

**（2）文学理论支撑：** 现有方法往往缺乏对既有文学理论的依托。虽然 LLM 能够生成长篇文本，但它们常常无法在扩展叙事中始终维持复杂的叙事结构。

**（3）基于主题的探索：** 大多数现有方法受限于对特定前提的关注，对基于主题的小说生成探索不足。有效的基于主题的生成需要在一个广阔而未定义的叙事空间中导航，然而当前技术缺乏系统性的搜索机制来确保叙事多样性。

为解决这些挑战，我们提出 BiT-MCTS，一个将弗雷塔格金字塔叙事理论（Freytag, 2003）与由 LLM 引导的双向蒙特卡洛树搜索（MCTS）相结合的框架。与先前基于 MCTS 的系统（如 Narrative Studio——其采用单次、基于前提的 MCTS 通道直接生成相对较短的故事）不同，BiT-MCTS 首先从宽泛的主题中派生出核心戏剧冲突，然后利用 LLM 直接生成核心高潮情节。随后，我们引入双向蒙特卡洛树搜索（MCTS）（Abramson, 2014），以核心高潮情节为根节点，生成连贯的叙事大纲。该过程向前搜索合理的"下降动作"与结局——其中下降动作包含高潮之后发生的事件，引入新的冲突并逐步推进情节，而结局则为叙事提供收尾。此外，该过程（向后）搜索合理的"上升动作"与开场——上升动作由通往高潮的事件构成，逐步营造张力并发展冲突，而开场则指背景信息与必要的情境。最后，我们将结构化大纲扩展为完整的叙事。

我们使用三个骨干 LLM（GPT-5-mini、Gemini-2.5-Flash、DeepSeek-V3），在 40 个中文主题（取自官方征文/小说竞赛）的留出集上评估 BiT-MCTS。基线包括 StoryWriter（Xia et al., 2025）、一个经过改编的 Narrative Studio（Ghaffari and Hokamp, 2025）以及直接 LLM 生成。我们采用 Wang et al. (2025) 的十维小说基准的改编版本，并使用比较式评估协议——自动化 LLM 评判器（与生成骨干模型不同）加上人类专家评估——并进行大量消融实验，以量化每个组件的贡献。

我们将主要贡献总结如下：

1. 我们将弗雷塔格金字塔叙事理论应用于自动化小说生成，提出一个"高潮优先、双向 MCTS 搜索"框架。
2. 我们构建了一个中文小说主题数据集，并设计了相应的基准，用以评估情节结构与文学质量，为未来长篇叙事生成研究提供了宝贵的资源。
3. 通过大量实验与消融研究，我们证明了我们的框架相对于当代强基线的有效性，并验证了每个组件的必要性¹。

¹ 所有代码与数据都将公开，以促进可复现性与进一步发展。

## 2 方法

### 2.1 概览

我们的框架 BiT-MCTS 针对的是从抽象、开放式主题生成长篇线性小说的问题。在这里，主题指的是驱动一部文学作品的中心艺术思想（例如"爱"）。其目标是自动产出一个完整、结构化的叙事，在深入探索主题的同时，优化叙事复杂度、连贯的情节结构、合理的角色发展、情感共鸣与文本多样性。

为实现这一目标，BiT-MCTS 以弗雷塔格金字塔（Freytag, 2003）为基础——这是一个经典的叙事模型，将小说划分为五个戏剧阶段：开场（引入角色与场景）、上升动作（冲突升级）、高潮（张力峰值）、下降动作（后果）与结局（最终收束）。这一结构模板确保了全局连贯性与情感节奏——使其特别适合计算式叙事生成。重要的是，我们对"高潮"一词的使用，指的是最突出地体现给定主题的事件，而非断言一个单一的、排他性的峰值；后续生成过程允许出现额外的局部高潮、反转与起伏式张力。

图 2 总结了 BiT-MCTS 的流水线。给定一个用户指定的主题（例如"爱"），系统首先抽取一个简洁的核心冲突与一个具体的叙事高潮。这种高潮优先的策略固定了一个高风险的转折点，为后续规划提供了牢固的锚点。从该锚点出发，双向 MCTS 模块沿两个方向展开情节：下降动作树向前扩展以探索后果，而上升动作树向后扩展以生成合理的先导事件与通向高潮的升级冲突。两棵树都使用一个基于 LLM 的、在创造力与连贯性之间权衡的奖励，来生成多样且兼容的候选片段。片段被组装成一个临时大纲；我们合成对齐的开篇与结尾，应用全局精炼以修复逻辑缺口与节奏问题，并通过带专用提示词的分段生成，将精炼后的大纲落实为完整叙事（提示词见附录）。

### 2.2 冲突与高潮生成

给定一个高层次主题 𝜃，我们使用一个 LLM 生成中心戏剧冲突的简洁规范，该冲突刻画了叙事中主要对抗力量的特性。这一冲突随后被用作第二次模型调用的条件化上下文，以产出小说高潮的场景级描述：一个单一的高潮事件 𝑒*——即中心冲突达到最大强度并得到解决或转化的那个事件。所得的高潮场景被视为后续 MCTS 的锚点（根）节点，用于结构化情节构建。

### 2.3 双向 MCTS

我们通过执行两个以单一高潮事件 𝑒* 为锚点的 MCTS 阶段来构建五幕大纲：一个向前阶段（下降动作），扩展高潮之后的事件；以及一个向后阶段（上升动作），生成通向高潮的先导事件。

**节点表示。** 令 V 表示树节点集合。每个节点 𝑣∈V 编码一个部分大纲和一组记账量：

- **部分大纲 𝑆(𝑣)**：与 𝑣 关联的有序事件序列。
- **树结构** 𝑝(𝑣) 与 𝐶(𝑣) 分别表示 𝑣 的父节点与子节点。
- **深度 𝑑(𝑣)**：节点 𝑣 的深度（根的 𝑑=0）。
- **访问次数 𝑁(𝑣)**：节点 𝑣 被访问的次数。
- **累积回报 𝑊(𝑣)**：回传到 𝑣 的模拟回报之和。
- **前缀情节奖励 𝜌(𝑣)**：从根到 𝑣 的情节前缀的评估器得分。
- **终止标志 𝜏(𝑣) ∈ {0,1}**：指示 𝑣 是否对应于一个已完成的大纲。
- **完全展开标志 𝜒(𝑣) ∈ {0,1}**：指示 𝑣 的所有可允许子节点是否均已生成。
- **缓存扩展 Π(𝑣)**：为 𝑣 缓存的候选扩展。

我们使用 ⊕ 和 ⊖ 表示事件序列上的连接操作符：𝑆⊕𝑒（追加）、𝑒⊖𝑆（前插）。评估器（奖励函数）记为 𝑅(·)，它将部分大纲 𝑆 映射为标量质量得分。基于 LLM 的情节写作分布记为 𝐺(·|𝑆, dir)，其中 dir ∈ {forward, backward}。

**评估器（奖励函数）。** 评估器是一个基于 LLM 的奖励函数，记为 𝑅(·)，它将部分大纲 𝑆（具体为从根到节点 𝑣 的完整路径）映射为标量质量得分；在我们的记号中，存储于节点 𝑣 的情节奖励为 𝜌(𝑣) = 𝑅(𝑆(𝑣))。对于每个新创建的节点，我们用一个专门的评估提示词（附录 B）提示 LLM，沿显式枚举的维度对从根到该节点的整个情节评分：角色发展、场景描写、一致性、相关性、因果/时序关系、主题探索、可读性、创造力、主要缺陷识别与整体质量。这些维度强调逻辑连贯性、结构健全性与创作价值，而非表面化的语言指标；可读性用于对抗情节大纲趋于晦涩的倾向。LLM 将各维度得分求和，重新缩放到 [0,10] 以保持稳定，并返回最终得分。

**高层流程。** 1) 用 𝑆(𝑣_climax) = [𝑒*] 初始化一个根节点 𝑣_climax，并运行向前 MCTS（dir = forward）以获得高潮后片段 𝑆→。2) 用 𝑆(𝑣_post) = 𝑆→ 初始化一个新根 𝑣_post，并运行向后 MCTS（dir = backward）以生成高潮前片段，从而得到完整大纲 𝑆←。先生成结果（下降动作）再生成原因（上升动作），约束了先导事件的生成，减少了不连贯的铺垫。

下面我们以四个步骤描述单个 MCTS 阶段（适用于两个方向）。

**选择（Selection）。** 从根出发，遍历到一个叶节点，方式是重复选择最大化一个 UCT 式采样的子节点 𝑢∈𝐶(𝑣)：

UCB(𝑢) = 𝑊(𝑢)/𝑁(𝑢) + 𝑐·√(2·ln 𝑁(𝑝(𝑢))/𝑁(𝑢))，  （式 1）

其中 𝑐>0 是控制探索项权重的探索常数。

**展开（Expansion）。** 若叶节点 𝑣_leaf 非终止且未完全展开，则获取（并在首次展开时缓存）一个排序后的候选列表：

Π(𝑣_leaf) = {𝑒₁, …, 𝑒_𝐾} ← 𝐺(·|𝑆(𝑣_leaf), dir)，  （式 2）

其中 𝐾 为候选预算。具体而言，实现仅在节点首次展开时调用一次提议器（proposer），并将返回的列表存储在 Π(𝑣_leaf) 中；一个指向 Π(𝑣_leaf) 的索引指针追踪哪些候选已被使用。对该父节点的每一步展开，通过取 Π(𝑣_leaf) 中下一个未使用的候选 𝑒（即按缓存顺序）来实例化恰好一个新子节点。对于一个可允许的候选 𝑒，创建一个子节点 𝑢，其

𝑆(𝑢) = { 𝑆(𝑣_leaf) ⊕ 𝑒，若 dir = forward；𝑒 ⊖ 𝑆(𝑣_leaf)，若 dir = backward }，  （式 3）

并存储其即时情节奖励：

𝜌(𝑢) = 𝑅(𝑆(𝑢))。  （式 4）

与实现一致，新创建的子节点在回传更新之前不赋予访问/计数累加器（𝑁(𝑢)=0，𝑊(𝑢)=0）。若缓存列表耗尽或无可允许候选剩余，则设 𝜒(𝑣_leaf)=1。

**模拟（Simulation）。** 由于 LLM 无法可靠地预测全局终止，且固定 rollout 深度缺乏灵活性，我们执行一种带早停规则的、受引导的、局部聚焦的模拟。从节点 𝑣（具有部分大纲 𝑆(𝑣) 与缓存的情节奖励 𝜌(𝑣)）出发，模拟器执行至多 𝑠_max 次单步扩展尝试（受剩余深度预算约束），从情节写作分布 𝐺(·|𝑆_cur, dir) 中采样候选事件。每个采样的扩展仅在其不降低评估器得分 𝑅(·) 时才被接受。为降低陷入局部最优的风险，若某个采样扩展提前停止，它返回最佳被接受的奖励，而不将 𝑣 标记为终止；仅当搜索深度达到预设最大深度时，才将父节点标记为终止（𝜏(𝑣)←1）。经验上，表 4 显示，相对于替代模拟策略，这种早停策略在所有评估维度上都改进了生成，同时降低了计算成本。伪代码如下。

**回传（Backpropagation）。** 令 reward_sim 表示在新创建子节点处发起的模拟所返回的标量。回传沿遍历路径 𝑃=(𝑣₀, 𝑣₁, …, 𝑣_𝑘)（从根 𝑣₀ 到被模拟节点 𝑣_𝑘，含两端）更新访问次数与累积奖励。对每个节点 𝑣∈𝑃 执行：

𝑁(𝑣) ← 𝑁(𝑣)+1，𝑊(𝑣) ← 𝑊(𝑣)+reward_sim。  （式 5）

**算法 1：带早停的受引导模拟（Guided Simulation with Early Termination）**

```
 1: procedure SIMULATE(𝑣, 𝑑max)
 2:     if 𝜏(𝑣) = 1 或 𝑑(𝑣) ≥ 𝑑max then
 3:         𝜏(𝑣) ← 1
 4:         return 𝜌(𝑣)
 5:     end if
 6:     reward_cur ← 𝜌(𝑣)
 7:     𝑆_cur ← 𝑆(𝑣)
 8:     for 𝑖 ← 1 to min(𝑠max, 𝑑max − 𝑑(𝑣)) do
 9:         𝑒 ∼ 𝐺(·|𝑆_cur, dir)
10:         if dir = forward then
11:             𝑆_new ← 𝑆_cur ⊕ 𝑒
12:         else
13:             𝑆_new ← 𝑒 ⊖ 𝑆_cur
14:         end if
15:         if 𝑑(𝑆_new) > 𝑑max then
16:             break
17:         end if
18:         reward_new ← 𝑅(𝑆_new)
19:         if reward_new ≥ reward_cur then
20:             𝑆_cur ← 𝑆_new
21:             reward_cur ← reward_new
22:         else
23:             break
24:         end if
25:     end for
26:     return reward_cur
27: end procedure
```

### 2.4 大纲精炼

在双向 MCTS 产出一个粗略大纲之后，我们应用一个两步精炼。首先，模型生成定制的开篇与结尾场景，为核心冲突充当首尾呼应（bookend）。其次，一个 LLM 自批评者（self-critic）审阅完整大纲的连贯性——通过重排、插入或删除来修复逻辑缺口、节奏问题或矛盾——从而产出一个用于最终文本生成的打磨后的大纲。

### 2.5 分段小说生成

最后一步将精炼后的叙事大纲作为其直接输入。为管理上下文长度并维持风格控制，整部小说被分为三个连续片段生成：开头、主体与结尾。每个片段由一次独立的 LLM 调用产出，其中模型以整个大纲为条件，并被给予片段特定的指令（例如，"开头段落应精心构思以抓住读者的兴趣。"）。每个片段生成的文本随后被拼接起来，构成完整的小说。

## 3 实验

### 3.1 实验设置

**数据集。** 现有的公开数据集主要面向图像（He et al., 2022），缺乏适合长篇叙事生成的文学主题的专门集合。因此，我们构建了一个面向长篇小说的专用中文主题数据集，包含 40 个主题²。主题被挑选以覆盖不同难度与创造力的谱系：（i）常见主题——单个关键词或简短熟悉的短语（例如"梦想 / dream"）；（ii）竞赛主题——收集自省级与国家级征文/小说竞赛的提示（例如"二十四节气 / twenty-four solar terms"、"来自 2035 年的信 / a letter from 2035"），这些主题引入了更大的词汇与概念多样性。每个主题被用作生成的单一测试提示。

² 虽然 BiT-MCTS 框架也可用于生成其他语言的小说，但为了更可靠的人工评估，我们使用中文数据进行了测试。

**骨干 LLM。** 实验在三个骨干 LLM 上进行，以测试对模型选择的鲁棒性：GPT-5-mini、Gemini-2.5-Flash 与 DeepSeek-V3。每个基线与我们的方法都使用相同的骨干模型进行评估。

**基线。** 我们将我们的方法与自动故事生成中的两种最先进方法以及朴素 LLM 基线进行对比：

（1）**StoryWriter**（Xia et al., 2025）：一个多智能体长篇生成框架，它生成大纲、规划叙事结构并生成上下文感知的文本。

（2）**Narrative Studio**（Ghaffari and Hokamp, 2025）：最初是一个基于 MCTS 的分支叙事系统；为了自动化比较，我们改编其 MCTS 核心，以从前提出发生成单一的线性故事。与我们的 BiT-MCTS 不同，这个改编系统生成并拼接故事片段，而不使用显式的中间大纲或叙事理论引导。

（3）**朴素基线**：使用相同的提示词从每个骨干 LLM 直接生成，用于隔离生成框架的效果。

**评估指标与协议。** 我们采用 Wang et al. (2025) 的十维小说基准（叙事复杂度、创造力、情感共鸣、情节结构、角色发展、场景、语法正确性、流畅性、多样性、整体质量）。为提高可靠性，我们使用比较式评估协议（Haider et al., 2025; Toshniwal et al., 2025），即评判器为每个主题查看多个系统输出，并在每个维度上选择最佳者；主要指标是胜率（被选为最佳的百分比）。

**基于 LLM 的比较评估。** 主要的自动评判器是 Qwen3-Max，它与生成骨干模型不同，从而减轻同模型家族的自偏好偏差（Liusie et al., 2024）。对于 40 个测试主题中的每一个，每种方法生成一篇小说；每个主题下生成的四篇小说在四个独立轮次中以完全随机的呈现顺序进行评估，以减轻位置效应。我们报告按主题聚合的各维度胜率。此外，我们在所有主题上将我们的方法与每个竞争者进行两两比较，每个主题的每次两两评估以随机顺序重复四次（每种顺序两次评估）。

**人工评估。** 为补充对创造力与主题表达等主观维度的自动评判，我们对以 DeepSeek-V3 为骨干的输出进行了聚焦的人工评估。由于人工评估成本高昂，我们随机选择了 20 个主题，并基于三种方法（我们的方法与两个竞争者）生成了 60 篇小说。八位专家标注者（六位文学研究生与两位资深高中语文教师）进行匿名排序；每篇小说集在十个基准维度（Wang et al., 2025）外加主题表达维度上进行排序。各维度胜率由排序推导得出。

**超参数配置。** 对于 MCTS 组件，我们简单地将 UCB 探索常数 C = 0.5，以平衡探索与利用。每棵树搜索 50 次迭代，最大搜索深度 𝑑_max = 8，最大模拟深度 𝑠_max = 3，每个节点最多 𝑘_max = 4 个子节点展开；这些约束旨在抑制叙事失控蔓延，同时保留足够的情节多样性。采样温度按生成阶段变化（各模板取值见附录 A）。为确保受控比较，Narrative Studio 使用相同的迭代次数（50）与最大模拟深度（3）。

### 3.2 实验结果

#### 3.2.1 主要结果

如表 1 所示，BiT-MCTS 获得了远高于基线的平均胜率（在 DeepSeek-V3、GPT-5-Mini 与 Gemini-2.5-Flash 上分别为 47.2%、50.5% 与 58.5%，而最佳基线平均值分别为 27.2%、31.5% 与 16.8%）。增益集中在衡量结构与文学质量的维度，而非表面化的流畅性：在大多数骨干设置下，BiT-MCTS 在叙事复杂度、情节结构、角色发展与情感共鸣方面处于领先地位。语法正确性与流畅性对 BiT-MCTS 而言保持持平或占优（例如，DeepSeek-V3 下的 GR/FL 为 60.0%/62.5%），表明叙事精妙度的提升并非以牺牲表面质量为代价。基于主题的探索体现在多样性与整体质量上：GPT-5-Mini 下 DI = 77.5%，Gemini-2.5-Flash 下 DI = 92.5%，OQ 分别为 47.5% 与 77.5%，意味着对不同的叙事实例化进行了系统性覆盖，而非简单重复。

两两正面对比（附录表 6）佐证了这些结果：BiT-MCTS 以压倒性优势击败朴素基线，并在大多数维度上对 StoryWriter 与 Narrative Studio 保持较大领先。

损失率诊断（附录表 5）显示，BiT-MCTS 在各骨干与各维度上始终获得最低的失败率，为质量建立了一个可靠的下界：该方法不仅更频繁地获胜，还能避免产出明显糟糕的输出。这种一致性降低了观察到的增益可归因于偶然离群值的可能性，并支持了跨骨干 LLM 与评估维度的鲁棒性主张。

#### 3.2.2 长度分析

长度分析提供了进一步的视角。BiT-MCTS 产出了篇幅显著更长的叙事（表 2）。为排除长度是唯一驱动因素的可能，我们进行了两项研究：（1）将故事限制在 3,000–5,000 词并进行两两比较（附录表 7），BiT-MCTS 在大多数维度上仍然胜出；（2）比较平均长度为 4,669.2 与 8,059.6 的输出（附录图 3），显示更长的叙事仅在少数表面指标上产生轻微下降，而在情节结构与角色发展上获得了实质性增益。综合来看，这些发现表明 MCTS 探索使得情节线索与弧线得到更充分的发展，而非仅仅增加冗余。

#### 3.2.3 消融研究

表 4 中的消融结果量化了每个核心组件的贡献。基线搜索策略（束搜索与 Best-of-N 采样）显示出中等的损失率。用直接生成替换 MCTS（-MCTS(direct)）产生 93.5% 的平均损失，禁用迭代精炼（-Refinement）产生 94.0%，而交换或移除双向调度（-Order Swapped 与 -Bidirectional）则产生极端失败（平均损失分别为 97.25% 与 100%）。用固定 rollout 深度与 LLM 预测的组合替换早停，显著降低了性能（58.0% 损失）。这些诊断表明，双向规划、MCTS 搜索与精炼各自都是实现鲁棒、符合理论的长篇生成所必需的，以达成连贯的弧线、对叙事空间的系统性探索，以及改进的生成后打磨。

#### 3.2.4 人工评估

专家人工评估（表 3）与自动评判收敛一致。BiT-MCTS 获得了最高的人工平均胜率（43.82%），并在关键设计维度上领先：情感共鸣（ER 45.84%）、情节结构（PS 46.67%）、角色发展（CD 50.84%）与主题（TH 51.67%）。总体而言，人类读者认为 BiT-MCTS 的叙事更具情感感染力、结构更好，并且更有效地落实抽象的主题提示。这些评判也间接佐证了大纲组件：BiT-MCTS 以大纲驱动、高潮优先的规划，似乎产出了更连贯、更具情感共鸣且更贴合主题的故事。

## 4 相关工作

自动故事生成研究已超越静态的"先规划后写作"流水线，转向整合叙事理论、记忆机制与有原则的搜索的架构。早期的层级式大纲改进了主题连贯性，但全局结构与多样性表现有限（例如 Plan-and-Write（Yao et al., 2019）），这促使一些工作将规划与写作分布到多个智能体，或用记忆增强规划（例如 Agents' Room（Huot et al., 2025）及相关的多智能体/记忆方法）。互补性的努力致力于解决角色深度与局部逻辑一致性——以角色为中心的想象力（Character-Centric Imagination）与修复系统是这一趋势的代表（Park et al., 2025; Zhang and Long, 2024）——而多模态系统则探索文本—视觉对齐与风格控制（Yang et al., 2024）。对于长篇叙事，动态大纲、层级表示与时序知识图谱（例如 StoryWriter、DOME 与基于知识图谱的方法（Xia et al., 2025; Wang et al., 2024; Shi et al., 2025a））有助于管理主题漂移与交织的情节，尽管其中许多仍依赖启发式规划。

蒙特卡洛树搜索及其混合体为分支探索提供了一种更有原则的机制，Narrative Studio 及近期系统整合学习到的价值/策略模型，将 MCTS 扩展用于创造性生成（Ghaffari and Hokamp, 2025; Materzok, 2025; Shi et al., 2025b）。最后，一系列自动指标与人工标注协议被提出用于评估叙事质量（Wang et al., 2025; He et al., 2022; Hou et al., 2025; Liu et al., 2023; İsmail Tarım and Onan, 2025）。综合来看，这些进展改进了可控性与复杂度，但凸显了对长程生成进行系统性、符合理论的搜索的需求。相比之下，BiT-MCTS 采用显式的双向规划，从而优先保证长程连贯性与目标实现，而非仅仅依赖前向的、由学习到的价值驱动的 rollout。

## 5 结论

我们提出了 BiT-MCTS，一个以主题为根基的小说生成框架，它优先生成一个显式高潮，并应用双向 MCTS 来组装连贯的上升动作与下降动作。在中文主题数据集上进行的自动评估与人工评估均证明了 BiT-MCTS 的有效性。

在未来的工作中，我们将在其他语言中应用并评估我们的方法，并通过与人类读者交互、从人类反馈中学习，进一步改进小说的创造力与质量。

## 局限性

尽管观察到了益处，仍有若干局限值得注意：

**（1）搜索效率与成本：** 对长程情节的 MCTS 在计算上代价高昂。API 延迟、token 成本与搜索深度限制约束了探索。渐进式加宽（progressive widening）、价值估计或学习到的先验并未被使用，留下了尚未开发的效率增益潜力。

**（2）评估约束：** 自动评分依赖单一外部模型（Qwen3-Max），这可能仍会引入评估器模型偏差。人工评估使用了较小的评审小组，且仅聚焦于两个（补充）维度；更广泛的专家评估、评分者间一致性（inter-rater agreement）报告以及特定体裁的评分细则，对更强的效度而言是必要的。

**（3）长度—质量权衡：** 尽管我们的方法生成了篇幅显著更长的叙事，但在非常长的序列上维持细粒度一致性仍然具有挑战性。我们并未开展受控研究来厘清长度如何影响自动评分与人工评分。

## 伦理声明

我们承认 LLM 可能产出有害、冒犯性或其他不当内容。为降低这些风险，所有拟用于人工评估的模型生成文本在标注前都经过了人工审查；在审查池中，我们未识别出任何包含明显有害内容的样本。我们进一步对任何可能公开分享的材料应用标准的去标识化与内容过滤程序。

所有人工标注均由从大学群体中招募的志愿参与者完成。参与者在参与前收到了书面说明并给予知情同意；说明描述了研究目的、可能遇到敏感语言的可能性、参与的志愿性质，以及随时退出而不受任何惩罚的权利。标注者因其付出的时间获得了公平合理的报酬。

为研究分析目的，我们未收集任何个人身份信息，且在数据处理过程中删除或匿名化了任何附带的标识符。

我们仅将 AI 助手 GPT-5-Mini 用于手稿文本的非实质性语言润色；未使用任何自动化系统来生成评估标签、替代人类判断或影响标注者的决定。本文报告的所有分析与判断均反映人类标注与作者的解读。

最后，我们遵守了所在机构的伦理准则与适用的法律要求。我们审查了本研究中使用的所有制品的许可，未发现其使用与本研究存在冲突。

### A.3 情节评估提示词（温度 = 0.0）

> 你是一位严格的专业小说情节评估师（奖励函数）：你是一位严格的小说情节批评专家。分析以下叙事，并针对以下每个类别进行评分，每个类别按 1 到 10 分打分（1=非常差，10=优秀）。如情况需要，请使用**完整分域**。例如：
>
> - （2）→ 极度矛盾或不连贯
> - （5）→ 尚可但有缺陷或略显乏味
> - （9）→ 优秀，仅有轻微或无缺陷
> - （10）→ 近乎完美
>
> *** 待评分类别 ***
>
> 1. 整体质量：情节的吸引力、结构性与流畅程度如何。
> 2. 主要缺陷识别：小说是否存在不一致、重复或不自然的模式。若小说没有明显错误，则给更高分。
> 3. 角色：角色的行为与对话是否一致且可信？
> 4. 场景：背景设定应与情节和角色深度融合，有效营造氛围、影响角色决策并推动情节发展。扣分项：场景与情节脱节、违背常识的细节、生硬的世界观说明或信息过载。
> 5. 一致性：小说是否维持内部逻辑与连续性（无矛盾）？
> 6. 相关性：事件之间是否有逻辑关联？
> 7. 因果与时序关系：因果关系与时间顺序是否处理得当？
> 8. 主题：情节是否围绕给定主题展开？主要矛盾与主要角色都应同主题密切相关。整个情节必须围绕主题。
> 9. 可读性：情节应清晰易懂，不含令人困惑或含糊的元素。
> 10. 创造力：情节是否呈现原创想法、独特的情节反转或创新的角色发展，使其区别于常见套路？
>
> 若发现任何矛盾、不清晰或糟糕的过渡，请严格扣分。读者应能凭借此情节轻松想象整部小说。扣分项：情节过于复杂、信息过多。
>
> JSON 输出示例：
> { "metric_name": 一个整数得分 }

### 图 1：小说大纲生成方法对比

> 顺序式大纲生成会导致过于公式化的叙事，而双向 MCTS 能够生成多样且富有创意的大纲。

### 图 2：四阶段小说生成流水线概览

> 四阶段小说生成流水线按如下推进：（1）冲突与高潮生成确立核心冲突与核心高潮。（2）双向 MCTS 探索从高潮向前、向后搜索，以得到连贯且富有创意的大纲。（3）大纲精炼对双向 MCTS 生成的粗略大纲进行精炼与切分。（4）分段小说生成将精炼后的大纲扩展为最终、流畅的叙事小说。该流水线将抽象主题转化为完整、结构化的长篇小说。注意：示例英文文本译自中文文本，以便理解。

### 图 3：BiT-MCTS 生成不同长度故事的两两比较胜率

> BiT-MCTS 在生成不同长度故事时、十个维度上的两两比较胜率（DeepSeek-V3，短平均长度 4669 词 vs. 长平均长度 8059 词）。
